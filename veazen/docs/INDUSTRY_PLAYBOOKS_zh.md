# Veazen 行业流程手册（Industry Playbooks）
## 码角色模型 · 通用流程骨架 · 六大行业方案 · 预设模板产品化规格

**编制日期**：2026年7月14日
**双重用途**：① 销售/客服的顾问式话术底稿（降低客户教育成本）；② 产品的"行业预设模板"功能规格（交付 Claude Code 实现，降低客户配置时间成本）
**核心命题**：客户不会因为"码不够便宜"而流失，会因为"不知道码该怎么用"而流失。谁把行业流程预置好，谁就把 onboarding 从数周压缩到数十分钟。

## 一、先统一语言：码角色模型（Code Role Model）

客户口中的"溯源码""防伪码""机身码"往往指同一张标签上的不同东西。平台必须先有一套统一模型，才能跨行业复用。**五种角色，各司其职**：

| 角色 | 俗称 | 唯一性粒度 | 是否入 QR | 谁扫 | 作用 |
|---|---|---|---|---|---|
| **R1 品类码** | 商品条码、SKU 码、机型码 | 每个 SKU 一个 | 是（GS1 AI `01`=GTIN） | 零售 POS、平台 | 标识"这是什么产品"，零售流通与合规基础 |
| **R2 批次码** | 批号、生产批、Lot | 每批一个 | 是（AI `10`=Lot、`11`=生产日、`17`=有效期） | 内部、监管 | 召回单元、有效期管理、法规记录（多数法规只要求到这一层） |
| **R3 单品码** | 一物一码、序列号、机身码 | 每件一个 | 是（AI `21`=Serial） | 消费者/技师 | 防伪验证、单品溯源、订单绑定、窜货追踪 |
| **R4 核销码** | 防伪码、刮开码、暗码 | 每件一个（隐藏） | 否（刮层下） | 消费者 | 一次性核销，破解"明码可整体复制"的死穴 |
| **R5 物流码** | 箱码、托盘码、SSCC | 每箱/每托一个 | 是（AI `00`=SSCC） | 仓储、分销 | 层级聚合（箱↔件绑定），出入库整箱扫描，窜货溯源到经销商 |

**关键概念——层级聚合（Aggregation）**：R5↔R3 的父子绑定关系。装箱时扫箱码 + 扫箱内各单品码，建立"这100件在这一箱"。价值：出库只需扫箱码即可激活100件；发生窜货时，从消费者手中的单品码可反查"它出厂时装在哪一箱、发给了哪个经销商"——**这是窜货追责的关键证据链，也是汽配/美妆分销体系的刚需**。

**"机身码"的特别说明**：客户说"机身码"时通常指 R3，但载体是**直接零件标识（DPM，激光/针刻在产品本体）**而非标签，常见于汽配、电子、工业件。平台侧数据模型完全相同，差异只在物理载体与最小尺寸约束。

**取舍原则（给销售的话术）**：
- 只要 R1+R2 → 你在做**合规记录**，不是防伪（多数法规的底线要求）
- 加 R3 → 你有了**溯源与窜货能力**
- 加 R4 → 你才真正有**防伪能力**（没有 R4 的纯明码方案，造假者复制一张真码印十万份即可）
- 加 R5 → 你有了**分销层追责能力**（多级分销才需要）

## 二、通用七步流程骨架（所有行业的最大公约数）

```
① 建档 → ② 生成 → ③ 上物 → ④ 激活 → ⑤ 流通 → ⑥ 验证 → ⑦ 回流
```

| 步骤 | 动作 | 责任方 | Veazen 触点 | 常见卡点 |
|---|---|---|---|---|
| ① 建档 | 建产品、定码方案、配溯源页 | 品牌方 | 控制台/插件 | **卡点1：客户不知道选哪些码角色 → 行业预设直接给答案** |
| ② 生成 | 申请批次、云端签名生成、导出 | 品牌方 | 批次导出 CSV/PDF | **卡点2：导出文件给谁？格式对不对？→ 印刷厂对接包** |
| ③ 上物 | 印刷/贴标/喷码/激光刻 | 印刷厂 / 代工厂 / 品牌自贴 | 标签模板、伙伴门户 | **卡点3：最大卡点。谁贴、贴哪、多大 → 行业贴码位图** |
| ④ 激活 | 出厂扫描使码生效 | 代工厂 / 3PL / 品牌 | 激活 API、发货标签 | **卡点4：小客户没有产线扫描 → Lite 生成即激活** |
| ⑤ 流通 | 分销、物流、零售、DTC | 渠道 | 箱码扫描（可选） | 多级分销的数据断层 |
| ⑥ 验证 | 消费者/技师扫码 | 终端 | 验证页 | 扫码率低 → 靠"扫码有价值"（COA/故事/保修）拉动 |
| ⑦ 回流 | 数据、告警、复购、存证 | 品牌方 | 看板、告警、证据报告 | 客户不看数据 → 主动告警邮件 |

**三种上物模式（决定 onboarding 分叉，对应计划书 §7.5）**：
- **模式 A｜代工厂贴码**（标准模式）：品牌把序列化标签卷寄给 OEM，OEM 灌装时贴，出厂扫描激活。适合已有稳定代工关系、批量 ≥5,000。
- **模式 B｜品牌自贴**（Lite 模式）：品牌收到成品，发货时打印标签贴上，生成即激活。适合月销 <2,000、无产线。**这是绝大多数首年客户的真实形态。**
- **模式 C｜3PL/仓库贴码**：拣货打包时贴。介于 A/B 之间，需要 3PL 配合（多数 3PL 收贴标服务费 $0.15-0.35/件）。

### 3.1 膳食补剂 / 营养保健品（首发滩头，机会评分 8.6）

**行业现实**
- 典型客户：2-10 人的 DTC 品牌，自己不生产，用代工厂（Contract Manufacturer）
- 供应链：品牌定配方 → 代工厂生产（cGMP，21 CFR 111 要求批记录）→ **第三方实验室出具 COA（Certificate of Analysis，逐批检测报告）** → 贴标灌装 → 发 3PL / Amazon FBA → DTC + Amazon 双渠道
- 三大痛点：① **Amazon 混仓（co-mingling）**——你的正品和别人的假货被混在同一库位，退货/差评砸的是你的招牌；② 消费者对成分真实性天然怀疑（补剂行业的原罪）；③ 批次有效期与召回管理是法规底线

**码方案**：R1(GTIN) + R2(批号+有效期，**强制**) + R3(单品码) + R4(核销码，建议) ｜ R5 一般不需要
**贴码位**：瓶身标签印 QR（主）；**核销码印在铝箔封口内侧或瓶盖内**（开封才可见——天然的防篡改语义）；外箱贴批次标
**上物模式**：首年 90% 走模式 B（自贴）；月销超 5,000 转模式 A

**流程**
```
建档（产品+成分+COA上传）→ 生成批次（绑定批号/有效期/COA）
→ 打印标签（Avery 标签纸或标签卷）→ 贴瓶/发货即激活
→ DTC 发货绑定订单 / FBA 发仓 → 消费者扫码
→ 看到 COA + 批次 + 有效期 + 正品确认 → 订阅复购
```

**验证页模块（预设顺序）**：① 正品状态 ② **第三方 COA 检测报告**（重量级，补剂消费者最想看的东西）③ 批次/生产日/有效期 ④ Supplement Facts 成分表 ⑤ 如何识别假货 ⑥ 复购/订阅 CTA ⑦ 品牌故事
**风控预设**：`duplicate_scratch`（critical）｜`geo_velocity`｜**`channel_mismatch`（本行业特有）**：码被扫但从未通过任何已知渠道售出 → 疑似混仓假货或渠道泄漏
**销售话术**："你的 COA 现在躺在网站的 PDF 链接里没人看。把它放进扫码页，每个消费者拿到瓶子的第一件事就是扫码验真+看检测报告——防伪是顺带的，**信任是卖点**。"
**上手时间**：模式 B 下 ≤30 分钟（含 COA 上传）

### 3.2 精品食品饮料（机会评分 8.2）

**⚠️ 重要修正**：本行业必须**拆成三个子play**，因为 FSMA 204 只覆盖 FDA 的食品溯源清单（FTL）——**清单是特定高风险品类：绿叶菜、瓜类、辣椒、番茄、黄瓜、香草、芽苗、热带树果、鲜切果蔬、带壳蛋、坚果酱、软质/半软质奶酪（硬奶酪不在内）、鳍鱼与烟熏鳍鱼、甲壳类、软体类、即食沙拉**。橄榄油、蜂蜜、咖啡、枫糖**不在清单上**——对它们讲 FSMA 是错误话术，会当场暴露不专业。

| 子play | 客户 | 驱动力 | 码方案重心 |
|---|---|---|---|
| **A. FTL 合规**（生鲜/水产/软奶酪/坚果酱） | 加工商、包装商、进口商 | FSMA 204，2028-07-20 大限，24 小时内向 FDA 提供记录、记录保存 2 年 | **R2 为核心**：溯源批次码（TLC）+ CTE/KDE 事件链 |
| **B. 欧盟酒类电子标签** | 葡萄酒/烈酒出口商 | 欧盟已强制 QR 提供成分与营养信息 | R1+R2+R3，验证页即法定电子标签 |
| **C. 产地故事/防掺假**（橄榄油/蜂蜜/咖啡/枫糖） | 精品品牌 | 无强制。溢价保护、掺假防御、地理标志 | R3+R4 为核心，重溯源叙事 |

**子play A 的技术要点**：FSMA 204 的核心是**溯源批次码（TLC）** + 在关键追溯事件（CTE：收获、冷却、初次包装、首个陆基接收者、装运、接收、转化）记录关键数据元素（KDE）。Veazen 的 `trace_events` 模型天然对应 CTE/KDE，只需预置事件类型与字段映射，并提供"24 小时内导出 FDA 可读记录"的一键导出——**这一个功能就是本子play的全部卖点**。

**子play C 的码方案**：R1+R2(批号+最佳食用期) + R3(瓶颈/背标 QR) + R4(**封盖内核销码——防"回收真瓶灌假酒"，这是烈酒行业最致命的攻击**)
**验证页模块（子play C 预设）**：① 正品状态 ② 产地地图 + 采收/榨取日期 ③ **理化检测**（橄榄油：酸度/多酚；蜂蜜：水分/花粉源）④ 生产者故事/影像 ⑤ 风味与用法 ⑥ 复购
**风控预设**：`geo_velocity`｜`out_of_market`（进口商区域管控）｜`refill_suspect`（同一码多次扫描 + 跨国 → 疑似回收瓶灌装）
**销售话术（C）**："你的橄榄油比超市货贵三倍，消费者凭什么信？扫码看到榨取日期、酸度检测和你家橄榄园的照片——**扫码页就是你的溢价证明书**。"

### 3.3 美妆个护（机会评分 7.8）

**行业现实**
- 供应链：品牌 → OEM/ODM 灌装 → 批号喷码（欧盟 1223/2009 强制标注批号）→ 分销/免税/社媒电商
- 两大痛点：① **窜货是本行业第一痛点**——区域定价差导致的跨区倒货，比假货更常见、更伤利润；② 社媒电商（TikTok Shop/Instagram）假货泛滥
- **物理约束致命**：15ml 精华瓶身没有 QR 的空间 → **必须用短域名**（这是 Veazen 短跳转域规划的真实业务动因），或把 R3 放外盒、R4 放盒盖内

**码方案**：R1 + R2(批号 + PAO 开封后保质期) + R3(外盒 QR/瓶底小码) + R4(盒内封口) + **R5(箱码，做分销窜货必需)**
**上物模式**：模式 A 为主（OEM 灌装线贴标）
**流程**：建档 → 生成（批次绑批号/PAO）→ OEM 贴标灌装 → **装箱时箱码↔单品码聚合**（关键）→ 出库激活 + 记录发往哪个经销商 → 分销 → 消费者扫码 → 验真 + 成分 + 用法
**验证页模块**：① 正品状态 ② 批号/PAO/生产日 ③ INCI 全成分与过敏原 ④ 教程视频 ⑤ 正品渠道提示 ⑥ 复购/补充装
**风控预设**：**`out_of_market`（本行业最高权重）**｜`duplicate_scratch`｜`scan_burst`（同批码在非授权区集中出现 → 整箱窜货，可经聚合关系直接定位到经销商）
**销售话术**："你知道哪个经销商在往邻国倒货吗？装箱扫一次箱码，消费者在哪扫、那箱发给了谁，系统自动对上——**告警邮件直接告诉你是谁**。"

### 3.4 纺织服饰 / 户外配饰（机会评分 7.7，欧盟 DPP 第二波）

**行业现实**
- 供应链长且跨国：纤维 → 纱线/织造 → 染整 → 成衣厂（土耳其/葡萄牙/孟加拉/中国）→ 品牌 → 零售 → **二手转售**
- **本行业的难点不是码，是上游数据**：DPP 要求材质成分、产地、可回收性、维修信息——这些数据散落在 Tier 2/3 供应商手里。**卖软件的都在解决"码"，谁解决"数据收集"谁赢**
- 时间表：纺织授权法案预计 2027 通过 + 约 18 个月过渡 → 2028-29 强制。欧盟买手**现在**已在招标中索要 DPP 路线图

**码方案**：R1 + R3（**载体是水洗标**——缝在衣服里，寿命 = 衣服寿命，这是 DPP 的天然载体）｜吊牌 QR（零售期）｜高端线可选 NFC 织入
**特殊需求：供应商数据门户**——品牌邀请成衣厂/面料厂提交材质、产地、认证（GOTS/OEKO-TEX）数据，汇入产品档案。**这与计划书 Phase 5 的"印刷厂伙伴门户"是同一套 partner 角色机制，可复用。**
**流程**：建档（产品+材质结构）→ **邀请供应商填报数据** → 生成 → 水洗标印码（标签厂）→ 成衣厂缝入 → 品牌 QC 激活 → 零售 → 消费者扫码 → DPP 数据 + 保养 + 维修 + 转售
**验证页模块**：① 正品/所有权状态 ② **DPP 数据集**（成分/产地/认证/可回收性）③ 保养与维修指引 ④ 转售/以旧换新入口 ⑤ 品牌故事
**风控预设**：`duplicate_scratch` 弱化（服装无刮码）｜**`resale_transfer`**：二手转售时的所有权转移记录（扫码显示"原购于2026-03，已转手1次" → 这本身就是二手平台最想要的功能）
**销售话术**："2028 年你的欧盟买手会要 DPP。现在做，水洗标改一次版；到时候做，全线包材重做还要赶工期。"

### 3.5 汽配 / 工业耗材（机会评分 7.0，客单价最高、留存最好）

**行业现实**
- **扫码的不是消费者，是技师**——B2B 场景，UX 完全不同（专业扫码枪、批量扫描、离线容忍）
- 多级分销（厂 → 一级 → 二级 → 门店 → 技师）= **窜货地狱**
- 保修是天然钩子：技师安装时扫码激活保修 → 品牌获得"谁装在哪辆车上"的数据 → 索赔时验证真伪
- 载体特殊：金属件用**激光刻蚀 DataMatrix（DPM）直接标在本体**（即客户说的"机身码"），包装盒贴标签，外箱贴箱码

**码方案**：R1(零件号) + R2(生产批) + **R3(DPM 或标签，本体标识)** + R5(箱码，**必需**) ｜ R4 一般不用（金属件无处刮）
**替代 R4 的防伪手段**：DPM 本身难以低成本复制 + 激活状态机（未激活的码验证即告警）+ 保修绑定（假件无法注册保修）
**流程**：制造 → 激光刻码/贴标 → 装箱聚合 → 出库激活 + 记录发往经销商 → 多级分销 → **技师安装时扫码 → 激活保修 + 记录车辆/门店** → 索赔时校验
**验证页模块**（技师视角，非消费者）：① 正品 + 授权经销商校验 ② 适配车型数据 ③ **保修激活表单** ④ 安装指引/扭矩参数 ⑤ 技师积分奖励
**风控预设**：**`out_of_market`（territory enforcement，本行业头号价值）**｜`duplicate`｜`warranty_claim_mismatch`（索赔的码从未被激活 → 假件索赔）
**销售话术**："刹车片装错了是人命。技师扫一下就知道是不是你家的正品，顺手激活保修——你第一次知道你的货最终装在了哪里。"
**注意**：本行业销售周期 3-9 个月，非自助模式能拿下，属于**企业档**目标，不作首年主攻。

### 3.6 宠物食品 / 婴童用品（机会评分 6.9，竞争最空白）

**行业现实**：受众是"为无法自辩者做决定的人"（父母/宠主）——**信任敏感度全行业最高**；召回是生死线（一次召回可灭掉一个品牌）；DTC 订阅制普及
**码方案**：R1 + R2(批次+有效期，**核心**) + R3 + R4(可选)
**杀手级功能**：**批次召回一键广播**——品牌在控制台标记某批次为 `recalled`（复用现有 `flag_reason=recalled`），该批次所有码的验证页**立即**变为召回警示 + 退换指引。传统召回靠新闻稿和邮件，触达率极低；扫码召回是**唯一能在消费者拿起产品那一刻拦住他的通道**。
**验证页模块**：① 正品/**召回状态**（置顶）② 批次/有效期 ③ 原料产地溯源 ④ 检测报告 ⑤ 喂养/使用指引 ⑥ 订阅复购
**风控预设**：`duplicate_scratch`｜`expiry_alert`（临期/过期码被扫 → 提示消费者 + 告知品牌渠道积压）
**销售话术**："下次召回时，你唯一能在消费者开袋前拦住他的办法，就是他手里那个码。"

## 四、产品化：行业预设模板（交付 Claude Code 的功能规格）

### 4.1 功能定义
onboarding 第二步（模式分叉之后）增加一个问题：**"你的产品属于哪个行业？"** → 选择后自动应用该行业的预设包 → 客户开箱即用 90% 配置，只需补自己的品牌信息。**这是把本手册的知识固化成代码，是降低教育成本的唯一可规模化方式。**

### 4.2 数据结构：`industry_presets`（内置种子数据，非租户可写）

### 4.3 六个预设的差异摘要（实现对照表）
| preset key | code_roles | 必填批次字段 | 验证页首模块 | 特有风控 | 默认模式 |
|---|---|---|---|---|---|
| `supplements` | gtin,batch,serial,scratch | lot, expiry | COA | channel_mismatch | lite |
| `food_ftl` | gtin,batch(TLC) | lot, harvest_date | 溯源链 | — | standard |
| `food_specialty` | gtin,batch,serial,scratch | lot, best_before | 产地故事 | refill_suspect | lite |
| `beauty` | 全部 + case | lot, pao | 正品+批号 | out_of_market(高) | standard |
| `textile` | gtin,serial | — | DPP 数据集 | resale_transfer | standard |
| `autoparts` | gtin,batch,serial,case | lot | 授权校验+保修 | out_of_market, warranty_mismatch | standard |
| `pet_baby` | gtin,batch,serial | lot, expiry | **召回状态** | expiry_alert | lite |

### 4.4 ⚠️ 本手册暴露的两个数据模型缺口（必须回填 PROJECT_PLAN）
1. **`batches` 表缺少行业刚需字段**：`lot_code`、`mfg_date`、`expiry_date`（补剂/食品/美妆/宠物**全部**依赖，且是法规要求）。→ 建议 Phase 1 即补，成本极低，事后加代价大。
2. **缺少层级聚合（R5 物流码）**：美妆窜货、汽配分销的核心能力。→ 建议新增 `cases` 表（id, tenant_id, sscc, batch_id, ship_to_ref）+ `code_case_links` 关联表，排入 **Phase 5**，但**数据模型接口在 Phase 1 预留**。

### 4.5 实施排期建议
- **Phase 2**（随 onboarding 分叉一起）：`supplements` + `food_specialty` + `pet_baby` 三个预设（均为 Lite 模式、无需聚合，覆盖首发滩头）
- **Phase 4**：`beauty` + `food_ftl`（FDA 记录一键导出）
- **Phase 5**：`textile`（需供应商门户）+ `autoparts`（需聚合与保修模块）

## 五、销售侧应用（同一份知识的第二种变现）

1. **行业一页纸（PDF ×6）**：每个行业一张"流程图 + 贴码位图 + 验证页样例 + 三大痛点"，冷邮件附件与展会材料。制作成本≈0（内容即本手册），转化提升显著——**它证明你懂他的生意，而不只是卖工具**。
2. **官网行业落地页**：`/supplements`、`/specialty-food`、`/beauty`… 每页含该行业流程图 + 术语 + 案例。SEO 打的是"supplement anti-counterfeit"这类高意图长尾词，而非"防伪"大词（大词打不过巨头）。
3. **诊断式话术（销售脚本）**：不问"你要不要防伪"，而问四个问题——① 你的货是谁贴标的（→ 定模式 A/B/C）② 你有几级分销（→ 定要不要 R5）③ 你的批号/有效期现在怎么管（→ 切入 R2 与召回）④ 你最怕假货还是最怕窜货（→ 定风控重心）。**四个问题问完，方案自动生成，客户觉得你是顾问不是销售。**
4. **内容资产**：《补剂品牌防伪落地手册》《FSMA 204 中小食品企业清单》——法规恐慌期（2027起）的搜索流量入口。

## 六、给决策者的三条结论

1. **行业预设是本项目性价比最高的功能**：技术复杂度极低（一堆种子 JSON + onboarding 一个下拉框），但直接决定 onboarding 转化率和"10分钟出第一个码"北极星指标能否达成。优先级应高于任何炫技功能。
2. **先做三个预设，不要做六个**：补剂/精品食品/宠物婴童——三者共性极高（Lite 模式、无聚合、批次+有效期），一套代码覆盖，且正是首发滩头。美妆/纺织/汽配等有付费企业客户提出时再做。
3. **立刻回填两个数据模型缺口**：批次的 lot/expiry 字段（Phase 1 补）与聚合表接口预留。这是本次行业深挖最有价值的技术产出——它们不是功能，是地基。
