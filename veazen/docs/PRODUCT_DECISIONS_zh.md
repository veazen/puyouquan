## PD-001：企业自定义/自带码段（2026-07-13）

**问题**：企业客户能否按自己的规则生成码段，或上传已有编码体系的码？

**现状**：数据库 SerialProfile 模型已预留三种模式——`platform`（平台默认，
现行）、`custom_format`（自定义前缀/长度/字符集/显示分组）、`byo`（企业自带
码）。CRUD API 已上线（含 random_bits ≥ 64 熵值下限校验，§9.11）；但批次
生成环节尚未消费码段方案，BYO 缺导入通道。验证页已支持 GS1 扫码解析，
可对接 GTIN+序列号的国际编码体系。

**评估**：
- `custom_format` 接完剩余管线：小工作量（2～4 天）。
- `byo` 导入：中等工作量（1～2 周），需解决四个问题：
  1. 全局撞号 → BYO 强制品牌专属前缀；
  2. 连号可枚举 → 依赖二维码 URL 内的 Ed25519 签名兜底 + 手动输码限流；
  3. 责任边界 → 服务协议明确"自带码唯一性由客户保证"；
  4. 刮码不接受外部上传（安全核心，仅序列号可 BYO）。

**决策**：暂不动工，作为企业版销售弹药。谈判时 `custom_format` 可承诺当期
交付，`byo` 按合同排期。

## PD-002：退货重发与防伪码状态处理（2026-07-13）

**问题**：中小企业常见非质量退货，重新包装即可再售。若防伪码已被验证过
（尤其刻印在商品本体、无法更换时），如何让二次销售不受"已验证"警示影响？

**场景拆解**（按码的物理位置 × 验证深度）：

| 场景 | 退回时状态 | 推荐处理 |
|---|---|---|
| 码在包装/贴标上，未刮码 | 仅有扫码记录，页面仍绿 | 可直接重发；建议登记退货事件以抑制风控误报 |
| 码在包装/贴标上，已刮码 | 黄色"已验证" | **换标**：旧码作废（retired），绑新码并关联旧码保留溯源链 |
| 码刻印在商品本体，未刮码 | 页面仍绿 | 登记退货事件后直接重发 |
| 码刻印在商品本体，已验证 | 黄色"已验证" | **官方翻新状态**（见下） |
| Lite 码（首扫锁定）被扫 | 黄色 | Lite 码在标签上，换标即可 |

**"官方翻新"方案（核心设计）**：
- 商家收到退货 → 在插件/控制台扫码登记 RMA（退货质检）→ 码进入
  `refurbished` 状态；
- 消费者再扫时，页面从吓人的黄色警示变为**品牌背书文案**：
  "此商品经品牌方退货质检后重新销售，验证历史 N 次，品牌方确认为正品"
  ——透明（不隐瞒历史）且不伤转化；
- 关键安全约束：**状态转换只能由持凭据的商家发起**（JWT/API key），
  消费者端无任何入口；绝不提供"一键重置回全新"（会摧毁整个信任模型，
  且刮码涂层物理上不可恢复）；
- 风控联动：RMA 登记后，第二位买家的异地扫码不再触发 geo_velocity 误报。

**现有地基**：trace_events 表与接口（可记录 returned/reshipped 事件）、
flag/unflag 接口、状态机 409 保护、订单绑定——均为 Phase 1 已交付。

**缺口**（估 1 周）：`retired`/`refurbished` 两个新状态、RMA 登记接口、
插件/控制台入口、验证页翻新文案、风控规则感知、换标时新旧码关联字段。
远期加分项：监听 WooCommerce 退款事件自动建议 RMA。

**决策**：列入企业功能待办，与 PD-001 同批排期；对外话术即日可用——
"退货场景我们有完整的 RMA 设计，换标与官方翻新两条路径"。

## PD-003：仓管退货核验与"释放再售"流程（2026-07-13）

**问题**：最简小企业形态——一串码（可自定义/可上传）直印商品无贴纸无刮层，
遭恶意无理由退货且码已被验证。仓管员如何确认验证状态？如何作为全新商品
重新发货？

**关键洞察**：该形态对应 Lite 首扫锁定，锁是纯数字的——**数字锁可由商家
安全解除，物理刮层才不可逆**（与 PD-002 红线不冲突）。

**方案**：
1. **退货核验工具**（插件/控制台内部页，手机可用）：商家身份扫码查询
   验证状态/次数/末次扫码时间地点/绑定订单；内部查询不改状态、不触发
   风控、不污染统计。查询接口 GET /codes/:serial Phase 1 已有。
2. **释放为可再售**：已验证的码经审计化操作回到"已激活待首扫"；
   安全论证——释放仅作用于商家自己的码（商家本可无限生成新码，无跨租户
   风险）、全程审计日志、平台监测同码多次释放自动标记异常。
3. **策略开关**：商家可选"释放后显示全新"（默认，适合未拆封无理由退货）
   或"官方翻新标识"（PD-002）；内部溯源记录永远完整。
4. 流程 30 秒：收退货 → 扫码 → 未验证直接上架 / 已验证点释放再上架。

**缺口**（与 PD-002 合并开发约 1 周）：释放接口+状态转换、核验页
（插件+控制台）、策略开关、风控联动（RMA 后抑制 geo_velocity 误报）。

**决策**：PD-001+PD-002+PD-003 组成"中小企业实操套件"，统一排期；
销售话术即日可用。

## PD-004：企业版管理后台蓝图（2026-07-13，老板提出）

**愿景**：强大的企业管理后台——独立管理页面（自定义域名+落地页）、
产品库（批量导入）、分销管理（分销出库记录）、仓库账号（独立核验退货，
手机扫码/手输）、防伪码生成系统（自定义+上传存量）；后续 App 化随时查验溯源。

**评估**：全部可执行，半数地基已存在（custom_hostnames 表、品牌化设置、
退货核验台、M1 已批准）。三点优化：
1. **分销管理是战略王牌**——出库绑定经销商与辖区后，窜货检测从统计怀疑
   升级为逐件铁证，建议提高优先级；
2. **App 先 PWA 不上架**——添加到主屏幕+摄像头扫码+离线，1 周达到九成
   原生体验且更新即时；原生壳上架（含中国区软著）待用户规模触发；
3. **权限体系先行**——角色（owner/admin/warehouse）+邀请+页面权限是
   仓库账号/分销/工坊的公共地基，必须最先浇筑。

**路线图**（总 6~8 周，分批按需求触发）：
- E1 权限体系+仓库账号+浏览器摄像头扫码（~1.5 周，建议近期）
- E2 M1 码段工坊（已批准二、三批，~2.5 周，首个意向客户触发）
- E3 分销管理+窜货检测升级（~2 周，可与 E2 换序）
- E4 产品库 CSV 批量导入（~3 天，搭车交付）
- E5 自定义域名+品牌落地页（~1.5 周，首个白标客户触发；
  注意每域名证书托管约 $0.1/月 的边际成本计入定价）
- E6 PWA 化（~1 周，E1 后随时）

**决策**：待老板对 E1 开工时机与 E2/E3 先后顺序批示。
