# 全球化与中国区规划（2026-07-13 定稿）

> 结论先行：官网先做中英双语；登录/支付采用"一个账户多把钥匙、
> 一套系统多个渠道"的可插拔架构；所有需要中国企业主体的事项打包
> 延后，等中国区有真实付费需求再决策。

## 1. 官网多语言（立即执行）

- 路径结构：英文在根路径，中文在 `/zh/`（Astro 原生 i18n，SEO 友好，
  head 中输出 hreflang 互链）。
- 语言提示：按浏览器语言（navigator.language）弹**可关闭**的提示条
  建议切换，绝不按 IP 强制跳转；用户选择记入 localStorage。
- 首批语言：EN（默认）+ 简体中文；features/pricing/首页全量翻译，
  privacy/terms 法务文本暂保留英文（翻译件无法律效力，待法务审核）。
- 后续扩语种时向消费者验证页已有的 i18n×5 看齐。

## 2. 登录：一个账户，多把钥匙

- 现有：邮箱+密码（中国用户亦可用）。
- 近期：Google OAuth（国际用户主流）。
- 中期：手机号+短信（对中国用户友好，无需中国主体，选国际短信服务商）。
- 远期：微信扫码登录——**需要中国企业主体**（微信开放平台企业认证），
  归入第 4 节决策包。
- 架构要求：身份表与登录方式表分离（identity ↔ providers 1:N），
  新增登录方式不动存量数据。

## 3. 支付：Stripe 一套覆盖国际+中国买家

- 第一步（有付费意向客户时）：接 Stripe（VEAZEN LLC 主体），
  同时开通 **Alipay / WeChat Pay 付款方式**——中国客户扫码付款，
  资金走 Stripe 结算，无需中国实体。
- 第二步（中国业务起量后）：微信支付/支付宝**直连**（费率与体验更优），
  需要中国主体+对公账户，归入第 4 节决策包。
- 架构要求：计费层抽象 PaymentProvider，渠道可插拔。

## 4. 中国实体决策包（统一延后，触发条件：中国区真实付费需求）

以下事项全部依赖中国企业主体（WFOE 或本地合作方），届时一并决策：

1. 微信开放平台（微信登录）
2. 微信支付/支付宝直连
3. 国内服务器/CDN + ICP 备案（大陆访问提速）
4. PIPL 数据合规评估（中国消费者扫码数据出境规则；与 GDPR 法务
   审核同批委托律师）
