# 中小企业实操套件 · 整改方案（v1.1 已批准）

> 依据：产品决策档案 PD-001 / PD-002 / PD-003（docs/PRODUCT_DECISIONS_zh.md）
> 起草：2026-07-13 ｜ 状态：**已批准**（2026-07-13 老板批示 D1~D4 通过，D2 追加企业码段工坊）
> 目标：把"自定义码段、退货重发、仓管核验释放"三件事整合为一次连贯改造，
> 成为面向中小企业的核心卖点组合。

## 一、范围总览（三个模块）

| 模块 | 内容 | 来源 | 独立工期 |
|---|---|---|---|
| **M1 码段自主权** | 自定义格式生成 + 企业自带码上传 | PD-001 | 格式 2~4 天；上传 1~2 周 |
| **M2 退货重发（RMA）** | 换标 / 官方翻新两条路径 | PD-002 | 约 1 周 |
| **M3 仓管核验与释放** | 扫码查状态 + 一键释放再售 | PD-003 | 与 M2 合并，+2~3 天 |

M2 与 M3 高度重合，**必须合并开发**；M1 可独立排期。

## 二、详细设计

### M1 码段自主权

**M1a 自定义格式（custom_format 接线）**
- 批次申请时可选码段方案（现有 SerialProfile 数据模型与 CRUD 接口直接复用）；
- 生成 Worker 按方案出码：前缀 + 随机段（熵值 ≥64 位硬约束，已有校验）+
  字符集（32 进制 / 大写字母数字 / 纯数字）+ 显示分组；
- 控制台新增"码段方案"管理页；插件批次表单加方案下拉。

**M1c 企业码段工坊（老板批示新增，2026-07-13）**
- 控制台新增「码段工坊」页面，**仅限企业管理员角色**（owner/admin）使用；
- 两个入口二合一：
  1. **按规则自助生成**：管理员自定义前缀/长度/字符集/分组（熵值 ≥64 位
     硬约束），平台按规则生成整批码——即 M1a 能力的自助化界面；
  2. **上传自带码**：M1b 的 CSV 导入入口放进同一页面；
- 所有生成/上传操作进审计日志（谁、何时、多少枚、什么规则）；
- 工作量：在 M1a/M1b 之上追加 2~3 天（界面与权限）。

**M1b 企业自带码（BYO 上传）**
- 新增导入接口：CSV 上传 → 逐行校验（长度/字符集/全局唯一）→
  失败行报告 → 入库为 inactive 码；
- 强制品牌专属前缀（防跨租户撞号）；
- 刮码不接受上传（安全核心，平台生成）；
- 手动输码验证路径加限流（防连号枚举）；二维码链接仍带 Ed25519 签名兜底；
- 服务协议增加条款：自带码唯一性由客户保证。

### M2 退货重发（RMA）

- 码状态机扩展两个状态：`retired`（已回收，换标后旧码）、
  `refurbished`（官方翻新）；
- RMA 登记接口（商家凭据 + 审计日志）；
- 换标：新旧码关联字段（replaced_by），溯源链完整；
- 验证页新增两种文案（含 i18n 五语）：
  - retired：「此码已由品牌方回收」
  - refurbished：「此商品经品牌方退货质检后重新销售，验证历史 N 次，
    品牌方确认为正品」
- 风控联动：RMA 登记后抑制该码的 geo_velocity（异地飞行）误报；
- **新增规则 `lite_duplicate_scan`**（2026-07-13 实测反馈）：Lite 码已锁定
  后，**不同设备指纹**再次扫码 → warning 级告警（进控制台，默认不发邮件，
  设置页可开邮件）。同设备重复查看不告警（买家回看属正常行为）。
- **告警邮件分级**（2026-07-13 第一批实现决策）：仅 `critical` 级告警发送
  邮件；warning/info 只进控制台与 webhook——防告警疲劳。"设置页可开邮件"
  的租户级开关留待控制台 UI 批次实现。

### M3 仓管核验与释放

- **退货核验页**（插件后台 + 控制台各一，手机浏览器适配）：
  扫码/输码 → 显示验证状态、次数、末次扫码时间地点、绑定订单；
  内部查询不改状态、不触发风控、不计入扫码统计；
- **释放接口**：verified/锁定 → 回到 active（待首扫）；
  仅限商家凭据；写审计日志；同码释放次数计数，超阈值自动告警；
- **租户策略开关**（设置页）：释放后显示「全新」（默认）或「官方翻新」；
- 远期（不在本期）：监听 WooCommerce 退款事件自动弹出核验建议。

## 三、数据库与接口变更清单（概要）

**数据库**
1. `codes.status` 枚举 + `retired`、`refurbished`
2. `codes.replaced_by`（换标关联，可空）
3. `codes.release_count`（释放计数）
4. 租户 settings 新键：`rma_display_policy`（fresh / refurbished）
5. 复用 `trace_events` 记录 returned / released / relabeled 事件

**新增接口**
1. `POST /codes/:serial/rma`（登记退货）
2. `POST /codes/:serial/release`（释放再售）
3. `POST /codes/:serial/relabel`（换标绑定新码）
4. `POST /batches/import`（BYO 上传，M1b）
5. 批次创建请求体 + `serial_profile_id`（M1a）

## 四、排期建议（两批交付）

| 批次 | 内容 | 工期 | 触发条件（建议） |
|---|---|---|---|
| **第一批** | M2 + M3（退货全流程） | 约 1.5 周 | 演示商店跑通后即可开工——它是所有中小客户的共性刚需 |
| **第二批** | M1a 自定义格式 + M1c 工坊（生成半区） | 约 1 周 | 首个提出需求的意向客户 |
| **第三批** | M1b BYO 上传 + M1c 工坊（上传半区） | 1~2 周 | 首个付费的企业客户合同 |

每批交付都走既有验收纪律：单测 + e2e + CI 全绿才算完成。

## 五、验收标准（摘要）

- M2/M3：e2e 覆盖「扫码核验 → 释放 → 再首扫变绿」「换标 → 旧码显示回收
  → 新码可验证」「翻新码显示背书文案」「释放超阈值触发告警」四条链路；
- M1a：自定义前缀/纯数字/分组显示的批次生成、导出、扫码验证全通；
  熵值 <64 位被拒；
- M1b：上传含重复/非法行的 CSV 得到精确的失败报告；合法码全流程可验证；
  无前缀上传被拒。

## 六、安全红线（重申，不可协商）

1. 绝不提供"重置为从未验证"——释放只回到「已激活待首扫」且留痕；
2. 刮码明文永不接受上传、永不二次导出；
3. 所有状态转换仅限商家凭据发起，全部进只增审计日志。
