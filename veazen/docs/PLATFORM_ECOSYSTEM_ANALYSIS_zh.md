# 平台生态深度分析：WooCommerce / Shopify / 中国大陆电商
## 需求真相 · 行业适配 · 技术落地架构

**编制日期**：2026年7月14日
**服务对象**：Veazen（VEAZEN LLC）— 既可独立运作、又可作为电商平台插件/App 的防伪溯源基础设施
**核心问题**：三个生态的商家分别是谁、真需求在哪、技术上如何用一套云端同时吃下、中国到底能不能碰

---

## 一、执行摘要（六个结论）

1. **Shopify 在架构上比 WooCommerce 更适合本产品**：Shopify App 的代码跑在开发者自己的服务器上，与 Veazen"插件是壳、云端是脑"的第一性原则天然同构；而 WooCommerce 插件跑在商家服务器上，我们一直在"对抗"这个默认形态。
2. **Shopify 商家的付费意愿和品类分布都更优**：DTC 品牌密集（补剂/美妆/服饰/食品——正是我们行业排名前四），且已习惯为 App 付费；**Shopify 首 100 万美元 App 收入 0% 抽成**（2025年1月起），渠道成本不构成障碍。
3. **但 WooCommerce 仍应首发**：免费获客入口、SEO 资产、无审核门槛（Shopify 审核 2-8 周且首次提交失败率高）。结论是**不改顺序，但把 Shopify 从"Phase 5 模糊想法"提前为明确的第二渠道，并且现在就做接入层抽象**。
4. **中国大陆消费者验证场景：技术与法律双重不可行**，且比之前判断的更硬——**经营性 ICP 许可证要求外资 ≤50%**，100% 美资的 VEAZEN LLC 在法律上无法在大陆卖订阅制 SaaS；**`.app` 这类 TLD 在 ICP 备案中"routinely rejected"**，veazen.app 从域名层就走不通。
5. **但中国有一个被严重低估的黄金客群：中国跨境卖家**。他们的消费者在欧美扫码——ICP、PIPL、防火墙问题**全部自动消失**，而他们急需的恰恰是欧盟 DPP 合规和 Amazon 假货防御。**西方 SaaS 不说中文，中国 SaaS 不懂 DPP**——这个空档几乎无人填补，而 Veazen 同时具备中文能力和美国主体。
6. **一个必须现在就定的架构哲学**：**App 卸载 ≠ 服务终止**。码印在实物上，消费者手里的码不能因为商家停止付费而变砖——这既是消费者利益，也是"没人敢用欠费即砖化的系统"的商业现实，更是每个已印出的码都在为你持续导流的营销资产。

## 二、三大生态的商家画像与需求结构

### 2.1 横向对比

| 维度 | WooCommerce | Shopify | 中国大陆电商 |
|---|---|---|---|
| 商家规模 | 全球最大装机量（市占第一），美国约占 24-28% | 全球市占约 8%，**美国市占约 29%**（美国是主战场） | 淘系/京东/拼多多/抖音 + 有赞/微盟私域 |
| 商家画像 | 技术型/DIY、长尾多样、欧洲小企业密集、内容驱动（博客+商店） | **DTC 品牌**、时尚/美妆/健康密集、更年轻、更商业化 | 平台店铺为主；私域靠微信小程序 |
| 付费习惯 | 省钱倾向强，插件"能免费就免费" | **已习惯付费装 App**（多数店铺常年订阅数个付费 App） | SaaS 付费意愿低，价格战激烈 |
| 代码位置 | **商家服务器**（PHP，我们必须约束它别存密钥） | **开发者服务器**（与我们架构天然同构） | 平台/微信生态内 |
| 计费 | 我们自己收（Stripe） | **强制走 Shopify Billing API** | 微信/支付宝 |
| 上架门槛 | WP.org 审核（队列以周计，但标准宽松） | 审核 2-4 周 + BfS 再 2-4 周，**首次提交常见失败点：隐私 webhook 缺失、计费流程不清、截图用样图** | 需 ICP + 本地实体 |
| 对我们的价值 | **免费流量入口 + SEO 资产** | **付费转化率 + 品类吻合度** | 见第四节 |

### 2.2 需求真相：谁真需要，谁只是听起来需要

**WooCommerce 生态**
- 真需求：欧洲精品食品/酒庄（EU 电子标签已强制）、补剂/保健品、手工护肤、宠物食品——这些恰恰是 WooCommerce 上密度最高的品类
- 伪需求：dropshipping 铺货店（货不是自己的，没有品牌可保护）、纯数字商品店、服务类店铺——**这部分占 WooCommerce 装机量的相当比例，会拉低免费版转化率，属于必须容忍的噪音**
- 特点：**Lite 模式（发货即贴码）是刚需**——六成是单人/微型团队，没有工厂

**Shopify 生态**
- 真需求：补剂（Shopify 上密度极高）、美妆个护、精品咖啡/食品、服装配饰、宠物——**与我们的行业机会排名几乎完全重合**
- 更强的驱动力：Shopify 商家更依赖 **Amazon 双渠道**（DTC + FBA），而 Amazon 混仓假货是他们最痛的伤口；同时 Shopify 商家品牌意识强，"扫码看 COA/产地故事"这种营销叙事更容易卖动
- 伪需求：同样有大量 dropshipping 店铺
- 特点：**可以直接卖标准档**（$49-99），不必像 WooCommerce 那样靠免费版慢慢养

**中国大陆电商**
- 真需求存在且巨大（假货痛点全球最深），**但被三堵墙挡住**：政府主导体系（药品/农产品追溯码由国家平台承载）、本土服务商价格战（一物一码在中国是红海，几十家厂商，客单价被打到地板）、外资准入与数据合规（见第四节）
- 判断：**这不是"要不要进"的问题，是"能不能进"的问题——答案是不能，除非合资**

## 三、技术落地架构：一核多接入

### 3.1 架构原则（不可动摇）

```
                    ┌──────────────────────────┐
                    │   Veazen Core (云端)      │
                    │  码生成/签名/验证/风控/存证 │
                    │  ★ 唯一真相源，永远在线    │
                    └────────────┬─────────────┘
                                 │  统一 Channel Adapter 接口
        ┌──────────────┬─────────┼─────────┬──────────────┐
        │              │         │         │              │
   WooCommerce     Shopify   店匠/Shopline  Headless   工厂端 PWA
   (PHP 插件)      (App)     (中国跨境SaaS)  (API/Widget)  (中文,离线优先)
```

**接口抽象（现在就要做，成本几乎为零；等 Shopify 时再做要重构核心）**：
```ts
interface ChannelAdapter {
  syncProducts(): Promise<Product[]>          // 商品同步
  onOrderFulfilled(order): Promise<void>      // 发货事件 → 绑定码
  bindOrderCode(orderRef, serial): Promise<void>
  getVerifyEntryConfig(): WidgetConfig        // 前台验证组件配置
  billingSource: 'stripe' | 'shopify' | 'manual'
}
```
目录建议：`packages/adapters/{shared,woocommerce,shopify}/`。核心 API 只认 `ChannelAdapter`，不认任何平台细节。

### 3.2 WooCommerce 接入层（已规划，此处只补一条）
现状规划完整（§7 全部功能）。**唯一需要新增的认知**：WooCommerce 插件是我们唯一"代码跑在别人服务器上"的接入层，因此它是攻击面最大的一环——密钥加密存储、nonce、capability 检查这些已写进 §9，必须严格执行。

### 3.3 Shopify App 技术方案（新增，本报告核心产出）

**架构优势**：Shopify App 的后端就是你自己的服务器——**Veazen Core 直接就是 Shopify App 的后端，不需要"壳"**。这意味着 Shopify 接入的工作量可能比 WooCommerce 更小。

**技术要点清单**：

| 环节 | 方案 | 备注 |
|---|---|---|
| 认证 | OAuth 2.0 + **App Bridge session token**（非 API Key） | 2026 年新嵌入式 App 必须用 token 认证，消除第三方 cookie 问题 |
| 后台 UI | **嵌入式 App**（iframe + App Bridge）+ **Polaris 设计系统** | BfS 强制要求；不得嵌入外部网页（不能把 app.veazen.app 直接 iframe 进去）；**这意味着控制台要为 Shopify 单独做一套 Polaris 皮肤——是真实工作量** |
| 订单页动作 | **Admin action / 上下文菜单扩展** | ★ 这是"打印防伪发货标签"按钮的完美载体——技师/商家在订单详情页两次点击完成贴码，比 WooCommerce 的实现更原生 |
| 店铺前台 | **Theme App Extension（App Block）** | 禁止 ScriptTag 注入、禁止改主题文件；卸载时 block 自动移除。验证组件以 App Block 形式提供 |
| 数据关联 | **Metafields**（serial ↔ order/product 关联）+ 我方 DB 为主 | 遵循"数据所有权划分"：Shopify 存关联引用，码本体永远只在我们云端 |
| 事件 | Webhooks: `orders/create`、`orders/fulfilled`、`app/uninstalled` | 快速 ACK + 队列处理（与我们 BullMQ 架构一致） |
| **强制隐私 webhook** | `customers/data_request`、`customers/redact`、`shop/redact` | ★ **三个必须真实可用**，这是首次提交最常见的失败原因 |
| 计费 | **强制 Shopify Billing API**（GraphQL `appSubscriptionCreate` / `appUsageRecordCreate` / `appSubscriptionCancel`） | **不能用 Stripe**。租户模型需支持 `billing_source` 多源 |
| 收入分成 | **首 100 万美元 100% 归你**（2025-01-01 起），超出部分 85%；另 2.9% 处理费；Partner 注册一次性 $19 | 与自收 Stripe（2.9%+$0.3）基本持平——**渠道成本不是障碍，这是个好消息** |
| 审核 | 标准 2-4 周；Built for Shopify 额外 2-4 周 | 建议**首版不追 BfS**，先上架跑起来；BfS 作为第二年目标（它带来的是应用商店排名权重） |

**Shopify 特有的三个设计决策**：
1. **控制台双皮肤**：Shopify 内嵌版必须 Polaris，独立版（app.veazen.app）用我们自己的设计令牌（§2.5）。共用同一套 API 和业务逻辑，只是 UI 层分叉。
2. **计费多源**：一个租户可能同时装 WooCommerce 插件和 Shopify App。`tenants` 表需增加 `billing_source` 与 `external_billing_ref`，避免双重计费。**同一品牌在两个平台的码必须在同一个租户下**（否则风控数据被割裂——这恰恰是我们的护城河所在）。
3. **卸载不销毁**（见 3.5）。

### 3.4 中国大陆：技术现实（本节结论是"不做"，但理由必须精确）

**多数人搞错的第一件事**：ICP 备案不是"访问中国"的必要条件，而是"在中国境内托管"的必要条件。境外托管的站点**不需要 ICP，也不会被默认封锁**——但会穿越拥堵的国际网关，慢、不稳定，且**中国 CDN 节点不会为未备案域名提供服务**。

**对 Veazen 而言，四堵墙依次抬高**：

| 墙 | 具体约束 | 对我们的后果 |
|---|---|---|
| ① 域名 TLD | ICP 备案对 `.io`、`.app` 等 TLD **"routinely rejected"**，只有 .com/.cn/.com.cn/.net 摩擦最低 | **veazen.app 从域名层就无法备案**——要做中国得另买 .com/.cn |
| ② 实体 | 外国公司**不能直接申请 ICP**，需 WFOE/JV/持牌伙伴；WFOE 注册 3-6 个月 | 时间与资金成本 |
| ③ **经营性许可证** | **卖订阅制 SaaS = 商业行为，需经营性 ICP 许可证；而该证一般要求外资 ≤50%**（100% 中资或外资不超 50% 的合资） | ★ **VEAZEN LLC（100% 美资）在法律上无法在大陆卖订阅 SaaS**——这是硬性否决 |
| ④ 数据主权 | 2026 年监管强化：收集境内用户数据、未经批准存境外 → **网站下架，多数情况无缓冲期无申诉** | 消费者扫码数据（IP/地理）必须留在境内，等于要建独立的境内栈 |

**加上生态现实**：中国消费者的扫码习惯是**微信扫一扫**，落地页在微信内置浏览器打开；小程序若后端在境内同样需备案。政府主导的药品/农产品追溯体系已占据强制场景，剩余市场被本土一物一码厂商价格战覆盖。

**结论**：大陆消费者验证场景 = **技术+法律+商业三重不可行**。除非未来出现"付费企业客户愿意承担合资/境内部署成本"的特例，否则不投入。

### 3.5 独立运作（Headless）——被低估的第四条腿

不是所有客户都用电商平台：线下品牌、Amazon-only 卖家、B2B 制造商、用 Magento/BigCommerce/自研站的企业。规划中已有的三件套即可覆盖：**公开验证 JSON API（无鉴权）+ ≤15KB Verify Widget（一行 script 嵌任意网站）+ 完整租户 API**。

**外加工厂端 PWA（中国场景 C，见第四节）的技术要求**：中文界面、**离线优先设计**（IndexedDB 缓存 + 批量上传，工厂网络穿墙慢是常态）、支持 CSV 兜底导入、可考虑香港/新加坡节点降低延迟（不属于大陆，无需 ICP，但物理更近）。

### 3.6 ★ 架构哲学新增：App 卸载 ≠ 服务终止

普通 Shopify/WP 插件卸载即结束。**我们不行——码已经印在流通中的实物上了。**

**必须实现的优雅降级**：
```
商家停止付费 / 卸载插件 / 关店
  → 已生成的码：永久保持可验证（显示基础正品状态 + 品牌名）
  → 新增能力：停止（不能生成新批次、不能导出、看不到分析与告警）
  → 数据：保留（不删除，租户可随时恢复付费重新激活）
```
**三个理由**：① 消费者利益——手里的码不该因为商家欠费变砖；② 商业现实——**没有品牌敢把防伪押在一个"欠费即砖化"的系统上**，这是签单时必被问到的问题；③ 营销资产——每个已印出的码都在持续为你导流，卸载后的验证页可以体面地保留一行 "Verified by Veazen"。

这条应写入 PROJECT_PLAN §1 作为架构决策第 11 条。

## 四、中国市场的正确打法：三个场景，只做两个

| 场景 | 描述 | 判断 | 理由 |
|---|---|---|---|
| **A. 中国品牌 → 中国消费者** | 大陆内销防伪溯源 | ❌ **不做** | ICP 经营性许可证外资 ≤50%；数据须境内；.app 无法备案；政府体系+本土价格战 |
| **B. 中国跨境卖家 → 欧美消费者** | 独立站/Amazon 出海品牌 | ✅ **重点机会** | **消费者在欧美扫码 → ICP/PIPL/防火墙问题全部消失**；卖家用后台（跨境访问略慢但可用，他们本就在用 Shopify 后台） |
| **C. 中国工厂 → 服务欧美客户** | 代工厂贴码激活 | ✅ **做（刚需）** | 已在规划中；是服务欧美客户的必需，不是市场进入 |

### 场景 B 深挖：为什么这是个金矿

**市场体量**：中国跨境电商进出口规模 2025 年约 2.63 万亿元（海关总署）；独立站在中国跨境 B2C 中的占比逐年上升（不同来源口径 25%-50%，需谨慎引用）；Shopify 全球商家数百万量级，中国卖家占比据不同来源估计在 5%-15% 之间（**该数据来源质量参差，仅作方向参考，勿写进正式材料**）。此外还有店匠（Shoplazza）、Shopline、有赞 AllValue 等**专门服务中国跨境卖家的 SaaS**，商家高度聚集。

**他们的四个真痛点，每一个我们都正好接得住**：
1. **欧盟 DPP 合规**——出海纺织/电子/电池品类将被强制，而中国卖家对 DPP 的认知普遍滞后，且找不到会说中文又懂 DPP 的服务商
2. **Amazon 混仓假货**——中国卖家是 Amazon 上占比最高的群体之一，混仓伤害最直接
3. **品牌升级**——从铺货转精品是行业共识趋势，"可验证的正品身份"是品牌化的基础设施
4. **"中国货=低质"的偏见**——扫码看到原料溯源、检测报告、工厂实拍，是最有力的反驳。**这是防伪之外的第二个购买理由，而且更有情绪价值**

**Veazen 的独特适配**：中文文档/客服（信磐）+ **美国主体（西方消费者看到 verify.品牌.com 背后是美国公司，信任度高于中国服务商）** + DPP 能力。西方 SaaS 不说中文，中国 SaaS 不懂 DPP，**这个交叉点几乎空着**。

**渠道路径**：接入优先级应为 WooCommerce → Shopify → **店匠/Shopline**（中国跨境卖家聚集地），而**不是**有赞/微盟（国内私域，属于场景 A）。获客渠道也不同：知乎、公众号、跨境电商社群、雨果网/亿邦动力等行业媒体，而非 Google SEO。

**⚠️ 一个必须核查的合规问题**：向中国企业销售 SaaS 是跨境服务贸易（他们付美元/信用卡给美国公司），本身可行；但收款通道（Stripe 是否顺畅支持中国大陆企业客户订阅）、发票需求（中国企业要发票入账，美国公司只能开 Invoice，部分客户会因此卡住报销）需要实测。建议在有前 3 个中国跨境客户后再优化这条链路。

## 五、平台 × 行业 适配矩阵（速查）

| 行业 | WooCommerce | Shopify | 中国跨境卖家 | 建议方案 |
|---|---|---|---|---|
| 膳食补剂 | ★★★ 密度高 | ★★★ **最优** | ★★ 有但少 | Lite 模式 + COA 模块 + 混仓风控 |
| 精品食品/酒 | ★★★ **欧洲酒庄密集** | ★★ | ★ | 欧盟电子标签 / 产地故事双 play |
| 美妆个护 | ★★ | ★★★ **最优** | ★★★ 出海大品类 | 标准模式 + 窜货风控 + 短域名（小包装） |
| 纺织服饰 | ★★ | ★★★ | ★★★ **DPP 刚需** | 水洗标 + DPP 数据集 + 供应商门户 |
| 宠物/婴童 | ★★ | ★★★ | ★★ | Lite + 召回广播 |
| 汽配/工业 | ★★ B2B 站多 | ★ | ★★ 出海配件 | 企业档：聚合 + 保修 + 区域管控 |
| 3C/小家电 | ★ | ★★ | ★★★ **出海主力** | 机身码(DPM/标签) + 保修注册 + DPP(2028) |

## 七、三条决策建议

1. **不改首发顺序，但现在就做接口抽象。** WooCommerce 仍是首发（免费流量 + SEO + 无审核），但 Shopify 是"更肥的第二块地"——付费意愿高、品类吻合、架构同构、0% 抽成。用一天时间做 `ChannelAdapter` 抽象，能省未来一个月的重构。
2. **把"中国跨境卖家"写进目标客群，但用完全不同的获客动作。** 这是唯一能让你的中文能力变成资产（而非无用技能）的场景，且竞争空档真实存在。等 Shopify App 上线后启动，因为他们大量在 Shopify/店匠上。
3. **"卸载不砖化"要在第一版就实现，并且写进营销文案。** 这是签单时必被问到的问题，也是巨头做不到的姿态（他们的合同锁定逻辑相反）。一句"你的码永远有效，即使你哪天不用我们了"——**这是信任生意里最有说服力的一句话**。
