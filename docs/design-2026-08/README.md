## 0. 怎么用这份文件

建议的产出顺序：

1. 先看 **§1 硬约束** —— 有几条是不能碰的，方案里踩到就白做。

**特别提醒**：本项目已有 **99 个浏览器回归套件**（`muse-tab/tests/`），其中大量是**几何断言**
（元素坐标、净距、占比）。界面改动会撞到它们——这是设计，不是障碍：
改版方案需要明确说明**哪些断言是要被有意推翻的口径变更**，哪些是不能动的。

## 2. 设计令牌现状

全部定义在 `index.html` 的 `:root`（约 L30–L50）。

### 2.1 颜色

```
--bg        #f3f0e8   画布（暖米）
--toolbar   #f7f4ec   栏
--panel     #fefdf9   卡片
--paper     #fbfaf5   谱纸（打印强制 #fff）
--text      #20211d   正文
--muted     #6b6357   次要
--faint     #a49c8d   三级
--border    #e4ddcd   --border-soft #ece6d8
--accent    #c33a29   朱砂（主色）
--accent-2  #d24a37   --accent-soft rgba(195,58,41,.10)   --accent-ink #b02f20
--ink       #141414   谱面墨色
--danger    #b45309   琥珀（刻意与朱砂错开色相，避免告警与选中混淆）
--ok        #157a43
--glass     rgba(251,250,245,.82)
--hover     rgba(80,65,40,.06)
--shadow    none      ← 全局无阴影令牌，但代码里散布着写死的 box-shadow
--radius    10px      ← 定义了，但组件各写各的（见 §6.2）
--grad      linear-gradient(96deg, accent → #d24a37 → #e2705d)
```

三级表面层次（`--bg` < `--toolbar` < `--panel`）是有意设计的，方向正确。

### 2.2 字体

```
--font-ui   'PingFang SC','Hiragino Sans GB','Microsoft YaHei','HarmonyOS Sans SC',
            'Noto Sans SC','Source Han Sans SC','WenQuanYi Micro Hei','Segoe UI',system-ui
--font-num  'DejaVu Serif','Noto Serif SC','Source Han Serif SC', serif
基准        body { font: 14px/1.5 var(--font-ui) }
```

**中文字体前置**是刻意的（避免「拉丁优先 + 中文回退」的混排参差与伪粗合成）。

**实测：全站用到 26 种不同的 `font-size`**
（8 / 8.5 / 9 / 9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 15 / 16.5 / 17 …）
—— **没有字阶体系**，是逐处微调累积出来的。

### 2.3 深色模式

只有 `--grad-*` 三个变量在 `prefers-color-scheme: dark` 与 `[data-theme="dark"]` 下换值，
**主色板没有深色定义**。页面有 `#b-theme` 主题钮与 `#b-invert` 反色钮，实际靠别处实现。
→ 深色模式的完整性需要在方案里明确交代。

## 3. 版面结构（实测）

### 3.1 桌面（视口 1440×900，`body.shell`）

```
┌──────────────────────────────────────────────────────────┐
│ #top            高 125px  ← 主栏 45 + #editbar 79        │
│   主栏：品牌 智能 新建 打开 保存 导出 排版 预览 打印 预设 谱库 … 个人中心 │
│   #editbar：编辑组 / 品位 0–9 + 10–24 / 时值 9 钮        │
│   #editbar2：节奏组 7 钮 + 更多 + 节奏型库 + 撤销重做 + 缩放 │
├──────────┬───────────────────────────┬───────────────────┤
│#left-dock│  #score-wrap  809px       │ #right-dock 292px │
│  339px   │    #paper 765 / 谱面 735  │  创作 / 信息 两页签 │
│ 图标轨48 │                           │  当前编辑位置（5 行表）│
│ +面板291 │                           │  编辑模式·时值提示  │
│          │                           │  创作辅助          │
├──────────┴───────────────────────────┴───────────────────┤
│ #mixer-dock     高 49px                                   │
└──────────────────────────────────────────────────────────┘
```

**关键数字**：谱面 SVG 实测 **735px = 视口宽的 51%**。
左右两栏合计 631px，比谱面本身还宽 —— 见 §6.1。

### 3.2 移动（视口 390×844，iPhone UA）

底部**三层固定条自下而上堆叠**，高度写死在 CSS 变量里：

```
--mob-b1: 148px   播放坞（三排卡片）
--mob-b2: 204px   = b1 + 图层轨 52 + 分隔
--mob-b3: 255px   = b2 + 时值条 49 + 分隔
```

实测：底部固定 chrome 自 **y=591 起** → 占屏高 **30%**；顶栏另占 52px。
可视谱面窗口 ≈ 390 × 529。

移动端的取舍（`@media(max-width:820px)` 约 L1717–L1800）：
- 顶栏只留 品牌方块 / ☰ / 智能 / 撤销重做 / 个人中心，其余收进 ☰
- **`#editbar > *:not(#ebu-eb-dur){display:none}` —— 编辑栏只剩时值组**
- `#right-dock` 原样升成底部半屏抽屉（`body.rsheet`），最大 76vh
- 浮条 `#quickbar` 贴底固定

## 6. 实测问题清单

> 按「结构 → 一致性 → 密度 → 移动端」分组。每条都附实测证据。
> 这是**观察**，不是改法；改法请在方案里给。

### 6.1 结构：谱面被工具挤到一半

- 桌面 1440 视口下，谱面 SVG **735px = 51%**；左栏 339 + 右栏 292 = **631px**。
- 纵向：顶部 125px（两层栏）+ 底部 49px。
- 后果：A4 版心在 1440 屏上都放不下一整行的舒适宽度；1280 笔记本上更紧。
- 右栏「当前编辑位置」用 **5 行表格**显示 声部/小节/列/时值/音符 —— 这些是状态信息，
  却占了一张卡的高度。

### 6.2 一致性

- **选中态至少 4 种视觉**：顶栏红字 / 编辑栏红框 / 左栏红底白字 / 右栏「智能编辑」**黑底白字**。
  同一个「当前生效」概念，四种表达。
- **圆角散落**：实测 **20 种**取值（2/3/4/5/6/7/8/8.5/9/10/11/12/13/14/15/16/18/20/980/999px）；
  而令牌 `--radius:10px` **全站只被引用 1 次** —— 等于定义了却没在用。
- **阴影**：令牌是 `--shadow:none`，但代码里有 **20 处写死的 `box-shadow`**。
- **浮层三套**：`.vh-pop` / `.popmenu` / `.nw-ddmenu` 各有各的定位、关闭、层级逻辑。
- **分段控件三套写法**，v60.70 才给其中一处加了主/次区分。

### 6.3 密度与信息层级

**编辑器首屏（1440×900，吉他弹唱谱）可见按钮实测 118 个**，分布：

| 区域 | 可见按钮数 |
|---|---|
| `#editbar` 编辑栏（编辑组 + 品位 0–24 + 时值） | **41** |
| `#left-flyout` 左栏面板（其中双行「符号+中文」图标钮 **31**） | **38** |
| `#top .main-bar` 顶栏主行 | 13 |
| `#right-dock` 右栏 | 13 |
| 其余（播放坞等） | 13 |

- 左栏 31 个双行图标钮铺成 4 列，**全部同权重**，除分组标题外没有任何层级区分。
- 顶栏 13 个文字钮（新建/打开/保存/导出/排版/预览/打印/预设/谱库…）同样全部同权重。
- 副标题被截断过（v60.70 刚修）：说明**文案与容器宽度没有共同的约束来源**。

### 6.4 移动端（最严重）

1. **录 TAB 的核心动作在手机上没有触摸入口。**
   `#editbar > *:not(#ebu-eb-dur){display:none}` 把品位 0–9 整组隐藏（实测这 10 个按钮
   在 390 屏上 `width = 0`）；点音符弹出的 `#quickbar` 只给 时值 / 3 个技法 / 连音线，
   **不含品位**。目前唯一的触摸路径是 v60.62 新增的指板面板，而它藏在
   「智能抽屉 → 创作辅助 → 指板/键盘」三层之下。
2. **底部 30% 屏高被三层固定条占据**（148 + 52 + 49 + 分隔），且高度是**写死的 px 常量**
   （`--mob-b1/b2/b3`），任何一条改高都要手工同步三个数。
3. **音轨名被截成 1 个字 + 省略号**（截图 10 的「吉 ..」「旋 ..」）。
4. 播放坞是深色玻璃、其余是暖米纸 —— 移动端因坞占比大，割裂感被放大。

### 6.5 断点无体系

编辑器里 **7 个断点**：`520 / 560 / 640 / 720 / 820 / 1180 / 1200`；
官网 `site/pyq.css` 另有 **3 个且完全不同**：`580 / 820 / 960` —— 两套产物只有 820 对得上。
写法还混用 `@media (max-width:…)` 与 `@media(max-width:…)`（有无空格）。

## 7. 需要产品拍板的问题（方案里请给出取舍）

1. **谱面优先还是工具常驻？** 左右栏是否改为可收起/悬浮？收起后默认状态是什么？
2. **移动端定位**：手机是「只读看谱 + 轻编辑」还是「完整创作」？
   —— 这一条决定 §6.4-1 是补一套触摸录入，还是明确降级为看谱端。
3. **深色模式**要不要做完整（目前只有渐变色有深色值）？
4. **官网与编辑器**是否统一为一套设计语言？现在是两套 CSS、两种气质。
5. 五层 chrome 是否合并？（顶栏 + 编辑栏 + 节奏栏 + 左栏 + 右栏）
