# YuE2 深度解读与谱友圈结合分析

> 调研对象：<https://github.com/multimodal-art-projection/YuE>（主分支 commit `0edaf2f`，2026-09-14）
> 调研日期：2026-09-15 · 方法：全仓精读（76 个文件）+ 三视角提案 + 许可/技术/产品三把刀对抗核验

---

## 0. 一句话结论

YuE2 不是 2025 年那个 YuE。它现在的核心叙事是**「白盒符号规划」**——歌词+风格先生成一份**可读可改的 ABC 乐谱**，再据此渲染整首歌；配套发布了**音频→乐谱的 SheetSage2**。这恰好是谱友圈北极星那句话里箭头的**左端**（「AI 生成音频 / AI 转谱 →」），而谱友圈占的是**右端**（「→ 人类可弹可唱可教的干净谱面」）。

所以真正该拿的**不是它的生成能力，是它的格式与工程范式**：一套有界 ABC 方言、一个事件级的「旋律没被改动」校验器、一套溯源与完整性记录习惯。这三样纯前端可实现、零权重依赖、零 GPU、零许可风险。

反过来，凡是要把谱友圈变成「音乐生成器的上游」或「站内出歌服务」的方向，在三把刀下**都被推翻了**——理由不只是 24GB 显存和 CC BY-NC，更是方向与北极星相反。

## 1. YuE2 功能框架

### 1.1 四个模型，各管一段

| 模型 | 角色 | 许可 |
|---|---|---|
| **YuE2-3B** | 风格+歌词 →（可选 ABC 规划）→ 语义 token → 声学潜变量 | CC BY-NC 4.0 |
| **YuE2-Vae** | 潜变量 → 48kHz 立体声（日常试听解码器） | CC BY-NC 4.0 |
| **YuE2-Vae-legacy** | 复现论文基准用的解码器 | CC BY-NC 4.0 |
| **SheetSage2** | **音频 → 旋律/和弦/节拍/调/结构 → ABC + MIDI** | 仓库内无许可原文，仅技能文档一句「model cards identify … CC BY-NC 4.0」 |
| **MERT-v2-FullSong / 30s** | 音乐理解编码器（SheetSage2 的父模型；也可独立做检索/分析） | 同上 |

> ⚠️ 一手核对：`MODEL_LICENSE` 的 Scope 段（第 3–8 行）**只列了 YuE2-3B / YuE2-Vae / YuE2-Vae-legacy 三个 checkpoint**。SheetSage2 与 MERT2 的许可文本不在本仓库，需查各自 HF model card 才能定论。

### 1.2 一条主链路，三种入口

```
风格 + 歌词  ──┐
               ├─→ YuE2 plan() ─→ score.abc（可读可改）─┐
音频 ─ SheetSage2 ─→ score.abc ──────────────────────┤
                                                      ├─→ generate_semantic()
人工/agent 改过的 ABC ─────────────────────────────────┘        ↓
                                                         synthesize() → latents
                                                                ↓
                                                          decode() → 48kHz 立体声
```

三条工作流共用**同一个生成 checkpoint**，差别只在 ABC 从哪来：模型自己规划 / 转谱来的 / 人改过的。没有单独的"agent 模型"。

**`cot` 三档**（`src/yue2/protocol.py:14-18`）：

| 档位 | 含义 | 典型用途 |
|---|---|---|
| `cot="full"` | 规划**旋律+和弦**的 ABC | 新建歌曲（默认）、改和声 |
| `cot="melody"` | 只规划**旋律**，和弦留空由伴奏自由发挥 | **翻唱**（官方推荐） |
| `cot="off"` | 不做符号规划，直接出音频 | 无可编辑谱面 |

### 1.3 分阶段 API（可只要谱、不要音频）

`YuE2Pipeline` 暴露四段（`src/yue2/pipeline.py`）：

```python
plan()               # → SymbolicPlan（含 score.abc + 精确 token id）
generate_semantic()  # → 语义 token
synthesize()         # → 声学潜变量 latent.npy
decode()             # → 音频
```

**`plan()` 只跑 AR 阶段、不加载 VAE**（`pipeline.py:255-269`；CLI `--stage plan` 见 `cli.py:125-129`）。这意味着「只出谱不出音频」在技术上是一条独立路径——device 可回落 CPU/MPS。不过这只是代码路径存在，**3B 模型在 CPU 上的实际速度仓库里没有任何数据，需实测**。

`save_artifacts()` 会留下完整证据链：`audio.flac`、`score.abc`、`plan.json`、语义 token、`latent.npy`、有效配置、耗时、模型身份、完整性记录。`SymbolicPlan.load()` 会校验 sha256——**被改过的 score.abc 拒绝载入**，必须作为新输入提交。这个"不可篡改的计划 + 改了就是新版本"的设计，是本次调研里最值得抄的工程习惯之一。

### 1.4 ABC 原生方言（最有价值的部分）

YuE2 的 ABC 是个**刻意缩小的有界方言**，不是完整 ABC 标准：

```abc
X:1
T:
M:4/4
L:1/16
Q:1/4=88
V: Vocal clef=treble name="Vocal Melody" snm="Vocal"
V: Ins clef=treble name="Ins Melody" snm="Inst."
K:C
% verse
V: Vocal
"C"E2G2A2G2E2D2C4|"G"D2E2G2E2D2C2D4|
V: Ins
Z4|
```

- **双声部**：`Vocal`（人声旋律，和弦标记挂在这一行）+ `Ins`（器乐旋律/solo，**不是钢琴和声谱表**）。两条都是单旋律线。
- **和弦词表只有 15 种**：`major / m / dim / aug / 7 / maj7 / m7 / dim7 / m7b5 / sus4 / sus2 / 6 / m6 / 7sus4 / m(maj7)`，支持斜杠低音。`C13`、`Cmaj9`、`A7alt` **都不是合法记号**。
- **时值乘数是有限集**：`{1,2,3,4,6,8,12,16,24,32,48}`。10 个单位必须写成 `C8-C2`。
- **变音记号按字母跨八度传播**：`^F` 之后本小节的 `F` 和 `f` 都是升的——这一条与很多通用 ABC 实现不同。
- **段落用注释标**：`% verse`、`% chorus`、`% bridge`、`% interlude`。
- **明确拒绝**：三连音、装饰音、和弦堆叠、反复记号、跳房子、圆滑线、破碎节奏、装饰、`w:` 歌词行。

配套的 `skills/yue2-music/scripts/abc_tools.py` 是**纯 Python 标准库实现**（Apache 2.0），三个子命令：

| 命令 | 作用 |
|---|---|
| `inspect` | 解析成精确的四分音符分数、MIDI 音高、合并连音线后的时值、逐声部小节格、和弦起点 |
| `strip-chords` | 去和弦并**校验所有发声音符/起点/时值/拍号/速度未变** |
| `compare` | **事件级**比对两份谱：`C32 ≡ C16-C16`，但 `C32 ≠ C16C16`（后者多一次起音）、`C16z16 ≠ z16C16` |

`compare` 这个「合并连音线后的发声事件」口径，是本次调研里**最直接可用**的一件东西。

### 1.5 SheetSage2 转谱（音频 → 谱）

`model.transcribe(audio, output_dir, ...)` 一次调用给出：

| 产物 | 文件 |
|---|---|
| ABC 乐谱 | `score.abc` |
| 合并 MIDI / 旋律 MIDI / 和弦 MIDI | `transcription.mid`、`melody*.mid`、`chords.mid` |
| 节拍/重拍/调/和弦/结构标注 | `beat.lab`、`downbeat.lab`、`key.lab`、`chord.lab`、`structure.lab` |
| 定时事件 | `events.json` |

- 输入任何 FFmpeg 可解码的音频，自动混单声道重采样 24kHz；最短 1025 采样点。
- 默认 300 秒窗口 / 200 秒重叠 / 100 秒前瞻——**整首歌级别**，不是 30 秒片段。
- `melody_only=True` 导出无和弦 ABC（翻唱用）。
- 六个任务可选：`timestamp / downbeat_meter / structure / key / chord_full / melody_full`。
- 另有 `render.py` 可把 ABC 渲染成 **PDF/SVG/PNG** 和钢琴预览音频（依赖 abcjs MIT + Playwright + Chromium + FluidR3 CC BY 3.0）。

### 1.6 硬约束（决定了什么能做什么不能做）

| 约束 | 数值 | 出处 |
|---|---|---|
| 显存 | **24 GB BF16 NVIDIA**，一次一个请求 | `README.md:60`、`docs/generation.md:3` |
| 运行时 | Linux + Python 3.12；torch 2.10.0 / transformers 4.57.6 固定版本 | `pyproject.toml:13-22` |
| SheetSage2 | **另一套环境**：Python 3.10/3.11、torch 2.8.0、FFmpeg 6.1 | `docs/covers.md:12-20` |
| 上下文 | 24576 token；ABC 阶段上限 4096 token | `protocol.py:12,46` |
| 权重许可 | **CC BY-NC 4.0**（非商用） | `MODEL_LICENSE:3-5` |
| 代码/技能/文档 | Apache 2.0 | `README.md:214` |

谱友圈的现状是：**Node + SQLite 单机、无 GPU、前端无构建单文件**。两边的距离不是工程难度问题，是数量级问题。

### 1.7 基准成绩（读法）

WildSongBench 192 prompt，2026-09-12：

| 系统 | SongBench Avg ↑ | PER ↓ |
|---|---:|---:|
| YuE2 (best-of-8) | **6.9632** | 9.79% |
| Mureka 9 | 6.9377 | 11.69% |
| Suno v5 | 6.8721 | 8.10% |
| YuE2 | 6.7316 | 8.44% |
| Suno v6 | 6.5562 | 7.58% |
| YuE 1（旧版） | 4.9165 | 36.38% |

仓库自己写了克制的读法（`docs/benchmarks.md:39`）：「小差距是描述性的，不构成统计显著性」；Suno v6 的 SongEval 与 PER 都更好。**PER = 音素错误率**，对中文歌词咬字尤其要紧，YuE2 的 8.44% 明显高于 Suno v4.5 的 5.80%。

翻唱评测更有意思：**给全谱 CLEWS mAP 0.647，不给谱只有 0.006**——符号条件是翻唱能否保住"还是这首歌"的决定性因素。这条数据本身就是对"白盒符号规划"的最强论证。

## 2. 与谱友圈的关系：箭头方向

CLAUDE.md 的北极星原话是：

> 占据「**AI 生成音频 / AI 转谱 → 人类可弹可唱可教的干净谱面**」这一端。

把 YuE2 叠上去：

```
         YuE2 的地盘                          谱友圈的地盘
  ┌──────────────────────────┐      ┌────────────────────────────┐
  │ 歌词+风格 → ABC → 音频     │      │ 干净谱面：三记谱法同源互切    │
  │ 音频 ──SheetSage2──→ ABC  │ ───→ │ 出版级刻版 · 织体生成         │
  └──────────────────────────┘      │ 八场景入口 · 课程与练习        │
                                     └────────────────────────────┘
                          ↑
                    交汇点就是 ABC
```

**交汇点只有一个：ABC 这个格式。** 谱友圈已经打通 MusicXML 进出 + MIDI 进出（PROJECT.md 互操作表），唯独没有 ABC。

## 3. 结合方案（经三刀核验后重排）

### 3.1 可以直接做（不碰模型、不碰权重、不需拍板）

#### ① 符号不变量比对 `songCompare`　工作量：小
把 `abc_tools.py compare` 的**事件级比对口径**搬进编辑器：把 `(mi,ci)` 列展开成 `[起点, MIDI, 时长]` 事件序列、合并连音线，再比对。

用途：
- 转调 / 配伴奏 / 换织体后，给用户一句**「旋律未变」的实证**，而不是让他自己听；
- 课程 UGC 审核、付费谱版本比对；
- 给「织体生成 + 智能配谱」（P1）补一道**数值化回归闸**——现在这块只有截图和人眼。

这条三把刀都没砍动，且不依赖 ABC 导入是否立项。**建议优先做，它本身就对 P1 有用。**

#### ② 节奏题库生成器　工作量：小
YuE2 把合法时值枚举成有限集 `{1,2,3,4,6,8,12,16,24,32,48}`、每小节必须恰好凑满拍号、10 单位必须拆成 `C8-C2` 连音链——这套约束正好是**少儿课与师范生节奏训练的"合法时值表"教具**。

按拍号（2/4、3/4、4/4、6/8）批量出题：「这小节共几拍」「补齐时值」「把附点拆成连音链」，自动判分。与课程 P2 待做的 `tap`（节奏敲击）题型共用一套校验。

#### ③ AI 来源溯源标注 `song.src`　工作量：小
YuE2 对每个产物都留 sha256 与模型身份，改过的计划拒绝载入。谱友圈可以照抄这个习惯：`song` 增可选字段

```js
src: { kind:'ai-transcribe'|'ai-plan'|'abc'|'midi'|'mxl', tool, model, srcHash, reviewed:true }
```

（只增不改，符合 `musetab-*` 数据红线。）公开页显示「AI 转谱 · 人工校对」角标。

这既是「专业曲谱平台」话术的质量承诺，也是版权策略的合规护栏，还给 B 端授权留下可审计材料。

### 3.2 需要拍板（有价值，但触及既定优先级或版权策略）

#### ④ ABC 导入器　工作量：中　**产品刀判定：不是 P0**

提案原本标 P0，被产品刀推翻，理由站得住：

> CLAUDE.md:36 的 P0 是一份**封闭清单**「MusicXML 出→入→MIDI 入→MIDI 出」，PROJECT.md 已四项全 ✅ 并写明「P0 互操作深化告一段落」。把新格式导入自封 P0 是借用已关闭序列的名头。历史上 Guitar Pro 导入就是「用户评估后拍板」；PROJECT.md:405 更已记录「多声部音频转谱……暂缓（需拍板），MusicXML/MIDI 导入已吃下大部分价值」。

**正确形态**：定位成「通用 ABC 子集导入」（兼容标准 ABC 2.1 + YuE2 两声部方言），YuE2 方言作为自动识别的严格子集，不拿 YuE2 当卖点。返回 `{song, skip, keyDefaulted}` 与 `importMusicXML` 同形，经 `migrate` 收口，新增 `tests/tv_abc.js` 并入 CORE。

**映射表**（信息无损/有损分析）：

| ABC 侧 | 谱友圈侧 | 损耗 |
|---|---|---|
| `M:` / `Q:` / `K:`（30 个大小调） | `beats`/`unit`、`tempo`、`key` | 小调需落关系大调或扩字段（**待拍板**） |
| 音高 + `L:` 时值 | `deg`/`oct`/`dur`/`dotted` | 无损（方言已排除三连音等难点） |
| `"Cmaj7"` 和弦（15 种） | `col.chord` | 无损 |
| `% verse` / `% chorus` | `mea.label` | 无损 |
| 连音线 `C8-C8` | tie 链 | 无损 |
| `Z4`（多小节休止） | 展开成空小节 | 无损 |
| `Ins` 声部 | 第二旋律声部或忽略 | **待拍板** |

**前置动作（零代码）**：先取一份真实的 SheetSage2 / YuE2 导出样本验证方言假设——**仓库里没有这种样本**，现在的映射表是从规范文档推的。

#### ⑤ AI 转谱清洗流水线　工作量：中　**许可刀判定：必须去品牌化**

设想：SheetSage2 转谱 → 导入 → 自动串联既有链路（空小节和弦补全 → 智能配谱织体 → 智能填词 → 工作台校对）→ 输出教学对照谱 / 即兴伴奏谱。**这是北极星那句话的字面产品化**："AI 转谱是毛坯，谱友圈是精装"。

许可刀的三点要求：
1. **功能去模型化命名**：叫「ABC 文本导入」，UI/官网/更新日志**不点名 SheetSage2/YuE2**，不写使用指导，不拿「AI 转谱」当会员卖点；
2. **算力与权重零接触**：不托管、不下载、不代跑，用户自带文件；
3. **产物默认私有**：导入的谱只进「我的曲谱」；进公开库或付费包时走既有原创/公版白名单。

叠加一条：**SheetSage2 的许可原文不在 YuE2 仓库内**，只有技能文档转述一句。立项前必须查 HF model card 原文。

#### ⑥ 课程判分器：听音记谱自动批改　工作量：中
课程现在只有四选一判题。用 ③ 的事件级比对，可以做「听音记谱」题：播放参考旋律 → 学生录入简谱 → 逐音反馈（音高错/时值错/写法不同但等价）。

再配「改编作业四档不变量契约」（精确音高 / 音高+节奏 / 仅轮廓 / 有界改编）——这是 YuE2 编辑工作流要求先写「变更契约」的做法，翻译成教学量规。考编/艺考的听音记谱是必考项，教师批改有统一尺度。

#### ⑦ 白盒和声改编练习　工作量：中
YuE2 自带一个**可复现的符号干预样例**：`examples/score.abc` 与 `score-jazz.abc` 音符完全相同，只把 `C→Cmaj7 / G→G7 / Am→Am7 / F→Fmaj7`，`compare` 应报 `match:true`。

配和弦工作台加「练习模式」：旋律锁定，学生逐拍改和弦，系统用 ③ 校验「旋律事件未变、和弦已改」，并与引擎推荐解对照。顺带补上「整句试听」这个已记录的诉求。

#### ⑧ 教学素材：同旋律换和声的课程单元　工作量：小
把 ⑦ 的样例做成 2–3 份公开谱挂进课程。`examples/*.abc` 是 Apache 2.0 文档资产，可引用改编（保留署名）。官方演示音频来自 CC BY-NC 权重，**只外链、不下载、不嵌入**。

### 3.3 不建议

#### ✕ 站内 YuE2 在线生成 / 翻唱服务
需要：GPU worker + 异步任务表 + 队列 + 对象存储 + 第二套 Python 环境。现状是单进程 Node 监听 127.0.0.1。

**但阻断性的不是工程量，是两条**：
1. 权重 CC BY-NC 4.0，面向订阅会员提供推理属商业用途，须另签书面授权；生成音频的商用地位 `MODEL_LICENSE` **无任何条款**；
2. 方向与北极星相反——谱友圈要占的是箭头右端。

#### ✕ 「AI 演唱工程包」导出（谱 → YuE2 → 音频）
这条被**许可刀和产品刀双杀**：

- 产品刀：「本方案是**反向箭头**：谱 → 交付包 → YuE2 → 音频，把谱友圈变成音乐生成器的上游输入格式化器」。而且这是条**有损降级通道**——YuE2 方言不认三连音、双附点、圆滑线、装饰音、反复、TAB 技法，伴奏织体和 TAB 根本送不出去。
- 许可刀：命名带 YuE2 会制造背书与商标风险（`MODEL_LICENSE:213-218` 明确禁止暗示背书）。

**可保留的部分**：`exportABC()` 作为纯函数存在，**只用于 `tv_abc` 的 import→export→import 往返断言**，不进导出六出口、不进打印弹窗、不给用户可见入口。

产品刀还给了一条更好的替代路径：

> 若真要做「让用户听到自己的谱唱出来」这一价值，应回到北极星与现有资产：复用编辑器已有采样音色播放引擎 + 人声「啊」音色做无歌词范唱，或走已有 `OfflineAudioContext` 分支导出练习伴奏音频——这是纯前端、零门槛、强化「织体生成」护城河的路径，而非把用户推向外部 GPU。

## 4. 三把刀砍出来的通用结论

**许可红线**
- CC BY-NC 的约束对象是**权重文件**，不是格式、不是算法思路。只要产品不下载/不加载/不分发/不托管权重，约束就覆盖不到产品本体。
- 但有两条容易踩：① 拿 YuE2 品牌当卖点会触及背书与商标条款；② 移植 `abc_tools.py` 代码（而非按规范重写）须保留 Apache 2.0 署名并在 PROJECT.md 第三方声明区登记。
- SheetSage2 / MERT2 的许可**仓库内无原文**，立项前必须查 HF model card。

**技术边界**
- 凡是「只借鉴设计与格式」的方案，GPU/并发/双环境这些刀全部砍空——落地物是纯前端函数，`api/` 零改动，符合单文件无构建红线。
- 凡是要跑权重的方案，24GB 显存 + 一次一请求 + 两套 Python 环境就是硬墙。

**产品方向**
- 判断一条方案该不该做，先问**箭头方向**：是把 AI 产物变成干净谱面（右端，该做），还是把谱面变成 AI 输入（左端，不该做）。
- 「P0」是一份已关闭的封闭清单，新格式导入历来是拍板事项，不能自封优先级。
