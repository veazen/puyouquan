# 双引擎战略意见书：智能看谱 × 智能制谱（2026-08-16）

> 产品负责人 2026-08-16 拍板新定位：**曲谱平台双引擎 = 智能看谱（看谱 + 智能学习/跟弹/连接乐器）+ 智能制谱**。
> 本文为四位专家 agent（定位战略 / 看谱体验 / 制谱能力 / 商业变现）联合策划的交叉汇总，基线 v59.0。
> 网页版意见书（决策阅读版）：claude artifact「谱友圈双引擎战略」。

## 总纲

双引擎不是两条业务线，是**同一个出版级刻版引擎的两扇门**——智能制谱让谱变干净，智能看谱让干净的谱值钱。与原北极星（AI 生成音频/AI 转谱 → 人类可弹可唱可教的干净谱面）是补全而非替换：制谱=生产端，看谱=消费端。AI 让图片曲谱库存贬值，但让「结构化谱面 + 学习闭环」升值；谱友圈每张谱都是 song JSON，这是两个引擎共用的地基。四垂类（即兴伴奏/考编/艺考/师范）不变，仍是双引擎共同滩头。

**未来 12 个月每项排期只回答一个问题：这件事是否让「结构化谱面」对「图片库存」的领先再拉大一格。**

## 一、定位与竞争格局（定位战略报告要点）

- **空隙裁决**：「三记谱法同源互切 + 出版级刻版 + 看谱学习闭环」组合拳全球无人做。最接近的拼图分散在 Soundslice（学习闭环无简谱）/ 弹琴吧（闭环无制谱）/ 吉他世界（生态无简谱无教育）。中国音乐教育以简谱为主干，全球产品无一认真做简谱。
- **「旋律→出版级伴奏谱」与「乐理级智能审校」两个格子在全部竞品表里为空**（GuitarPro/MuseScore 的 AI 投在「听」不在「写」）。
- **打法**：不和 20–70 万库存竞赛，和形态竞赛；供给做窄做深（公版+垂类+AI 辅助批量制谱）。AI 转谱玩家（Klangio/反谱AI）是上游水源不是对手。
- **信息架构**：三域不动结构只动叙事——zhipu 头衔「智能制谱」、kanpu 观看页「智能看谱」、www 首页双引擎卡 + h1 副行「智能看谱 · 智能制谱」；slogan「智能曲谱平台」保持；puku 不升格独立门户（品牌落页面级）。导航保持 4 项（移动端 #menu 四等分硬约束）。
- **飞轮**：制谱降成谱成本 → 创作者发布 → 每谱 SSR 落地页+分享卡 → 看谱获客 → 收藏/练习留账号 → 部分转创作者 → 更多供给。冷启动侧重供给端。

## 二、智能看谱蓝图（看谱体验报告要点）

四层能力梯：**① 看谱**（现有移调/变调夹/互切 + 智能卷谱速度感知插值 + 学员笔记 overlay + AI 讲谱规则层）→ **② 学习**（练习模式 HUD：段落胶囊循环[mea.label>sectionBar>8小节自动]、阶梯提速 60% 起每 2 遍+10%、预备拍；打卡+成果卡走分享卡管线；练琴周报）→ **③ 跟弹**（先节奏 onset 后单音音准评分+错音回谱着色；视唱跟唱是考编/艺考硬考项可优先投放；wait-mode 弹对才走）→ **④ 连接**（调音器=获客钩子+权限教育场景，谱面感知调弦/变调夹；Web MIDI 电钢桌面闭环）。

**关键事实与红线**：
- 手机观看页的循环/变速目前被 `@media(max-width:640px)` 隐藏（index.html L1293-1297 附近）——解禁即净增量。
- iOS 微信麦克风：iOS 14.3+ WKWebView 才支持 getUserMedia；**真机矩阵是 P0 强制出口**；降级链 day1 内建（JS-SDK 录后评→无麦自评）。
- **复音识别不自研**（扫弦用 onset 节奏判定）；单音检测端到端延迟约 80–150ms。
- Web MIDI：iOS/微信内全灭 → 定位桌面 Chrome/Edge（考编电钢人群）；零延迟零误检，wait-mode 先以 MIDI 形态面世。
- 不做：瀑布/卡拉OK 视图（另起渲染=自削护城河）、「机器跟人」自动跟随（v1）。
- 数据红线：练习/笔记一律新键（musetab-practice-v1 / musetab-viewnotes-v1），song 与既有键零改动；AudioWorklet 用 Blob URL 内联守单文件。

## 三、智能制谱蓝图（制谱能力报告要点）

**招牌功能定案：「一键弹唱伴奏」（智能配谱 2.0）**——链路 80% 已建成（suggestChords Viterbi L2224 / PIANO_TEX 15 套 L2090 / arrangeAccompaniment L2354 / applyTabPattern L8304）。

- **P0-A 智能配谱 2.0 四步**（每步独立发版）：① 小调支持（detectMode + CHORD_CANDS_MIN，大调结果逐字节回归零漂移是最重要断言）→ ② 风格织体映射+段落差异化（PIANO_TEX 增 style/dyn 标签、pickTexture、mea.texId 小节级覆盖，段落来源 mea.label）→ ③ 前奏/尾奏生成（末乐句程式化，弱起谱豁免回归）→ ④ 吉他弹唱一键伴奏（applyTabPattern 批量驱动+capo 建议）。song 数据只增 `song.mode?` `mea.texId?` 两个可选字段（红线合规）。
- **P0-B 制谱体检**：六类纯前端规则审校——超欠拍（并入报告）/音域越界/和弦不可按（chordShape 反查）/歌词对位/临时记号规范（accCarry 反向）/平行五度八度（仅多声部，「建议」档可关）。**16 首预设零误报是硬门槛**；新键 musetab-audit。
- P1：一键排版宏（S 级快赢）· 哼唱转谱增强（节拍器引导/3/4·6/8/小调/接配伴奏）· 教学要点卡（规则引擎，考编内容包增值层）。
- P2：弹奏转谱服务端模型（basic-pitch 类→MIDI→既有量化管线，**需拍板 GPU 成本**）· LLM 讲解增强。整曲多声部转谱维持不自研（当上游接水：唯一能把 MusicXML/MIDI/GP 都吃进来转简谱+出版级排版的浏览器工具）。
- 已知脆点：suggestChords 的 song 全局换入换出（L2228）——扩展前先包 try/finally 加固。
- 对外话术：「AI 配的每一份谱都过了出版级审校」。
