# 谱库与新建：分类升级方案 v2（2026-11）——一级按「谱种」

> 2026-10-31 · 只出方案，未改产品代码 · 待负责人拍板（§十五）
> **v2 复核已改入正文**（2026-10-31，五类中国用户＋工程各走「找谱」「建谱」两条路）：手机一级改 2×4 宫格、古筝 / 二胡重奏不再落进合唱谱、「和弦谱」搜索不再落空、导入的器乐曲不再污染视唱、新建简谱可直接带伴奏、「简五对照」改叫「对照谱」等 26 条，逐条记录见 §十七；新增拍板 24–30。
> 负责人原话（2026-10-31，对 v1 的意见）：「曲谱分类，我感觉确实了一个特别重要的，符合中国人使用的《简谱》功能，和弦谱更普遍的叫法叫《功能谱》，玩西洋乐器或者民乐器的用户一般很少用户会搜索器乐谱，一般会搜索五线谱或者简谱，根据这个信息你看看如何优化。」
> 此前原话：「曲谱与谱库的分类我认为需要优化，无论是曲谱分类还是曲谱新建我认为要以用户需求作为优先级，结合网站的核心功能升级分类。」
> 依据：v1 的内部盘点（四套分类口径、编辑器 docType、服务端 docTypeOf、统一谱名逐例对拍）＋ v2 补做的国内谱站调研（搜谱网、简谱之家、虫虫钢琴 / 吉他、中国曲谱网、曲谱图网、弹琴吧、8pu 和各 App 名称，§二）＋ v2 规则的 headless 实测（曲库 10 首、示例 16 份、新建面板 49 种组合，§六）。外网页面本环境打不开，调研只用到搜索摘要；百度指数、百度下拉被代理拦截，搜索热度没有实测，用各站标题和 App 名称里的关键词作旁证。

## 〇、v2 相对 v1 改了什么、为什么

**一句话**：v1 一级按「用途」分（八用途），记谱法只做「能切换着看」的角标。v2 改为一级按**谱种**分，用中国用户自己的叫法：**简谱 · 五线谱 · 钢琴谱 · 吉他谱 · 尤克里里 · 合唱谱 · 功能谱**。用途降为二级和专题。

| 项 | v1 | v2 | 为什么改 |
|---|---|---|---|
| 一级主轴 | 用途（我要干什么） | **谱种**（用户搜什么） | 负责人指出用户搜的是「简谱 / 五线谱」，不搜「器乐谱」。调研也是这样：国内谱站的一级几乎都是谱种（搜谱网、简谱之家、虫虫钢琴），站名和 App 名里堆的关键词也都是「简谱、吉他谱、钢琴谱、五线谱」（§二） |
| 一级名单 | 弹唱 · 钢琴伴奏 · 歌谱合唱 · 教学对照 · 视唱练耳 · 指弹独奏 · 器乐 · 和弦谱 | **简谱 · 五线谱 · 钢琴谱 · 吉他谱 · 尤克里里 · 合唱谱 · 功能谱** | 7 个词都是用户自己的说法，按钮都不超过 4 字 |
| 简谱 / 五线谱 | 不当分类，只当「看法」（角标「简⇄五」，搜「简谱」不筛选） | **两个一级**，按原稿记谱归属 | 负责人：简谱是「符合中国人使用的特别重要的功能」。调研：简谱常排第一个关键词；民乐、声乐、考编、师范、学前默认用简谱 |
| 三记谱法互切 | 角标说明可切换，一级不随记谱法变（不变式「互切不变」） | **列表末尾提示「还有 N 首五线谱原稿，可转成简谱看」**；卡片角标「可看五线 / 可看简谱」；点开就用观看页的简谱 / 五线视图（v69.6 已有） | 一级既然按记谱法分，「能互切」就要变成**找谱时多出来的结果**，而不只是一个角标 |
| 一份谱放几处 | 交叉收录只限「人声＋钢琴」两种 | **按「含有」归属**：含简谱旋律就进简谱，含钢琴伴奏就进钢琴谱……另定一个**主谱种**，给面包屑、SSR 主分类页用 | 谱种是「这份谱里有什么」，天然可以多选。例如「简谱旋律＋钢琴伴奏」，要简谱的老师和要钢琴谱的伴奏者都该找得到 |
| 「器乐」 | 一级 | **撤掉**。民乐 / 西洋乐器的谱按原稿记谱落在「简谱 › 器乐」「五线谱 › 器乐」，再按乐器分；搜「二胡谱」变成「乐器：二胡」条件 | 负责人：器乐用户不搜「器乐谱」。调研：没有一个站或 App 把「器乐谱」当用户看得见的名称（§二） |
| 「和弦谱」 | 一级叫「和弦谱」，二级「和弦格 · 级数功能谱」 | 一级叫**功能谱**，二级「级数谱 · 和弦格」；搜「和弦谱 / 级数谱 / 和弦简谱」都落到功能谱。吉他的和弦谱仍在吉他谱 | 负责人：和弦谱更普遍的叫法是功能谱。调研：8pu 写「和弦谱也常称为功能谱」；吉他圈说的「和弦谱」其实是吉他谱（§二） |
| 用途 | 一级 | **二级与专题**：钢琴谱 › 独奏 · 弹唱 · 伴奏；吉他谱 › 弹唱 · 指弹；考编即兴伴奏 / 艺考视唱 / 师范儿歌弹唱 / 课堂对照谱做专题页 | 用途仍是主攻垂类的入口，但不再占一级 |
| 新建第一步 | 9 个用途卡（三组：弹唱伴奏 / 课堂声乐 / 独奏乐队） | 「常用」一行（考编 / 师范 / 艺考 / 课堂 4 张用途卡，仍 2 步）＋ 同一组 7 个谱种 → 第二步选形态 | 「新建入口同名」：谱库和新建用同一组词 |
| 不变式 | 「互切不变」：切换记谱法，一级不变 | 「**互切镜像**」：主谱种是简谱 / 五线谱的，切换后落到对面同名二级；主谱种是其他谱种的，切换后不变 | 一级按记谱法分以后，「不变」不再成立，改成「镜像」 |
| 拍板项 | 16 项 | 30 项（§十五；v2 复核新增 24–30），其中 v1 的第 1、2、14 项被否，第 3、7 项改写 | — |

**沿用 v1、不改的**：数据不改名（只新增派生值和一个可选字段 `song.intent`）；`PQ_KIND` 与 `api/kindname.js` 逐字节同一份；docTypeOf 收进 PQ_KIND（含 R12 的防脏写法）；服务端筛全库、`/api/pub/cats` 计数；列表缓存换键（R19）；服务端搜索补作曲（R20）；儿歌是跨类风格标记（R8）；考编专题按并集（R2）；手机只常显一级一行、首屏见第一张卡（R5）；手机和小程序里通往编辑器的按钮改「发到电脑做」；旧外壳谱友圈零差异；小程序不发版；冷启动由官方账号发布（R9）；P0–P4 五段、每段可单独上线和回滚。

## 一、结论

**推荐：一级 7 个谱种，按「含有」归属、定一个主谱种；用途做二级和专题；三记谱法互切变成「还有 N 首可以换成简谱 / 五线谱看」。**

1. **一级 7 个（全部 ≤4 字，顺序固定）**：

   全部 · **简谱 · 五线谱 · 钢琴谱 · 吉他谱 · 尤克里里 · 合唱谱 · 功能谱** · ♥ 收藏

   - 简谱放第一个。调研里「简谱」最常排在第一位；负责人也点名它最重要。
   - 尤克里里紧挨吉他谱，两者是同一家族。
   - **不设「器乐」，也不设「民乐」**。民乐默认用简谱，放在「简谱 › 器乐」，再按乐器分（二胡、古筝、笛子……）。民乐占全库 ≥10% 时再议是否单列（拍板 3）。
   - 7 个一级常显，0 首也显示，给空状态（「能换成简谱 / 五线谱看的有 N 首」或「自己做一份」）。原因：一级就是导航锚点，也是 SEO 分类页。
   - **手机（≤580px）不排成横滑一行**：9 个 chip 约 740px 宽，375px 屏只露出「全部 · 简谱 · 五线谱 · 钢琴谱」和半个「吉他谱」。未选一级时排成 2×4 宫格（简谱 五线谱 钢琴谱 吉他谱 / 尤克里里 合唱谱 功能谱 ♥收藏，再点已选的回到「全部」）；选了一级后收成一行（§4.1，v2 复核 T1）。
2. **一份谱可以出现在多个谱种下，另有一个主谱种。**
   - 例子：
     - 「简谱旋律＋钢琴伴奏」：主谱种「钢琴谱 › 弹唱」，也在「简谱 › 歌曲」；
     - 艺术歌曲（五线谱人声＋钢琴）：主谱种「钢琴谱 › 弹唱」，也在「五线谱 › 歌曲」；
     - 对照谱：主谱种「五线谱 › 对照谱」，也在「简谱 › 对照谱」；
     - 合唱＋钢琴：主谱种「合唱谱」，也在「五线谱（或简谱）› 合唱」和「钢琴谱 › 伴奏」。
   - 判法表 24 行（v2 复核把第 14、15 行拆了分支），只读现有字段，自上而下首条命中（§5.2）。多行简谱带乐器身份的（古筝左右手、二胡二重奏）归「简谱 › 器乐」，不进合唱谱（T2）。
   - 主谱种只给面包屑、SSR 主分类页、JSON-LD 用；筛选和计数都按「主谱种 ∪ 也出现在」算。
   - **吉他 / 尤克里里弹唱谱里的简谱旋律行，不让它进「简谱」**（§5.3）。理由：行业惯例把「六线谱＋简谱混排」算吉他谱；弹唱谱是本站数量最多的一类，放进来会淹没简谱一级。作为补偿，搜「X 简谱」时，弹唱谱排在简谱原稿之后。
3. **三记谱法互切**（§4.3）：
   - 简谱 / 五线谱两个一级，默认只列原稿。
   - 列表末尾一行提示「还有 N 首是五线谱 · 用简谱看 ›」，点开后它们接在原稿后面。
   - 卡片上有角标「可看简谱」；点开时链接带 `&nota=jp`，观看页直接用简谱视图（v69.6 的 `vwNota`，只要加一个 URL 参数）。
   - **推荐默认：浏览时关，搜索时开，原稿不满 6 首时自动展开。**
4. **用途降为二级与专题**（§4.2、§4.4）：
   - 钢琴谱 › 独奏 · 弹唱 · 伴奏；
   - 吉他谱 / 尤克里里 › 弹唱 · 指弹；
   - 简谱 › 歌曲 · 儿歌 · 合唱 · 器乐 · 视唱 · 对照谱；
   - 五线谱 › 歌曲 · 合唱 · 器乐 · 重奏 · 视唱 · 对照谱；
   - 合唱谱 › 简谱合唱 · 五线合唱，另有「带伴奏」开关；
   - 功能谱 › 级数谱 · 和弦格。

   考编即兴伴奏、艺考视唱、师范儿歌弹唱、课堂对照谱 4 个专题页，从首页文字链进去都是 2 步（§十）。
5. **新建入口同名**（§八）：
   - 第一步是「常用」一行（钢琴即兴伴奏〔考编〕· 儿歌弹唱〔师范〕· 视唱练耳〔艺考〕· 教学对照〔课堂〕）加 7 个谱种；第二步选形态。
   - 每个谱种有默认形态：钢琴谱默认独奏，吉他谱默认弹唱。所以主攻垂类、吉他弹唱、钢琴独奏都还是 2 步。
   - 形态全部映射到现有 11 个用途加变体，建谱逻辑、深链 `?new=`、`musetab-nw-last` 都不改。
   - 分两步上线：先只改谱库（P1），新建后改（P2a 补组合和 intent，P2b 改第一步）。
6. **数据不改名。**
   - 新增只读推断 `PQ_KIND.PZ / pzOf / docTypeOf`；
   - 唯一新写入的是建谱时的可选字段 `song.intent`（P2a）；
   - 旧的 `type` / docType 原样保留。

## 二、调研要点（v2 新增）

1. **国内谱站的一级是「谱种」，不按用途分**：
   - 搜谱网一级：简谱 / 吉他谱 / 钢琴谱 / 五线谱 / 电子琴谱 / 手风琴谱 / 二胡曲谱 / 笛箫曲谱 / 萨克斯谱 / 古筝曲谱 / 总谱 / 其他；
   - 简谱之家导航：钢琴谱 / 吉他谱 / 简谱 / 尤克里里谱；
   - 虫虫钢琴分「钢琴谱（五线）」和「钢琴简谱」两个列表，二级是弹唱谱 / 独奏谱 / 四手联弹谱 / 总谱；
   - 中国曲谱网、曲谱图网按声乐 / 器乐 / 戏曲分栏，但站名和每个频道标题都写谱种（「葫芦丝简谱」「口琴简谱」「二胡曲谱」）。
2. **搜索词**：
   - 站名和 App 名里几乎都有「简谱、吉他谱、钢琴谱」，其次是「五线谱、古筝谱、尤克里里谱、二胡谱」；「简谱」常排第一个；
   - **「器乐谱」没有一个站或 App 拿来当用户看得见的名称**，「器乐」只是栏目分组。负责人的判断成立。
3. **民乐用简谱，西洋乐器用五线谱**：
   - 曲谱图网的收录说明写明：声乐谱不注明的默认是简谱；西洋乐器（吉他除外）只收五线谱和线简混排；吉他以六线谱和简谱混排为主；民族乐器以简谱为主；
   - 例外一：萨克斯、电子琴的业余和中老年圈大量用简谱（「萨克斯简谱大全」、中老年萨克斯简谱教程）；
   - 例外二：艺考视唱以五线谱为准（浙江传媒学院附件写明统一用五线谱）；
   - 考编、师范、学前多用「简谱版」教材。
4. **功能谱 ≈ 和弦谱**：
   - 用级数（数字）记和弦，可再加简谱主旋律、歌词；换调后数字不变。
   - 8pu 帮助文档：「和弦谱也常称为功能谱」；功能简谱 ＝ 主旋律＋歌词＋和弦功能。
   - 叫法分人群：吉他弹唱圈说「和弦谱 / 吉他谱」（弹琴吧「和弦谱大全」、虫虫吉他「六线谱、和弦谱」）；乐队、键盘、教会、即兴伴奏说「功能谱 / 级数谱 / 和弦简谱」。
5. **常见叫法**：
   - 合唱谱 / 合唱简谱 / 混声四部 / 「合唱谱_带钢琴伴奏」 / 总谱与分谱；
   - 「正谱伴奏」（写好的钢琴伴奏谱，与「即兴伴奏」相对）；
   - 「双手简谱 / 钢琴简谱」；
   - 「线简谱混排 / 五线谱、简谱对照 / 简谱转五线谱」；
   - 「儿歌弹唱 / 简谱钢琴即兴伴奏」。

## 三、现状的问题（v1 结论仍成立，摘要）

1. **四套口径各说各话**：
   - 新建 11 个用途（`NWP.SC`）；
   - 谱行组合 14 种、统一谱名约 25 种（`PQ_KIND`）；
   - 谱库筛选 10 个 docType（编辑器 `CC_CATS`、官网 `CATS`）；
   - 官网 4 个垂类页。
2. **同一个用途建出的谱落进不同筛选**：钢琴即兴伴奏用简谱建落「歌谱」，用五线谱建落「器乐五线」；二胡简谱落「歌谱」；尤克里里独奏不进「尤克里里」。
3. **曲库名实不符**：8 首艺术歌曲的筛选是「器乐五线」，《阿特拉斯》是「钢琴独奏」，卡片却叫「钢琴伴奏歌谱（五线谱）」。
4. **筛选维度混杂**：11 个按钮混了用途、乐器、记谱法、形态四种维度，也没有按乐器筛的办法。v2 补一条：**没有「简谱」入口**。中国用户最常搜的词，在谱库里没有对应按钮（「器乐五线」倒是有）。
5. **工程缺口**：
   - 接口不带关键词时只返回最新 200 首（`api/db.js:247`），第 201 首以后按分类筛不到；
   - 服务端 `isChoirOf/docTypeOf` 和编辑器判法已经分家；
   - 建谱时选的用途不进 song，刷新就丢；
   - 后台看不到 `create_stack` 按用途的分布；
   - 分类没有落地页。

**为什么钢琴谱的二级不照计算稿写成「伴奏（即兴伴奏 / 伴奏歌谱 / 纯伴奏）· 弹唱（自弹自唱 / 儿歌弹唱）」**（拍板 8）：

- 「伴奏歌谱」和「自弹自唱」在谱面上是**同一种谱**：旋律、歌词、钢琴两行。只读现有字段分不开，只能靠 P2a 才有的 `intent`。这样「弹唱」上线时几乎是空的，老谱也全落进「伴奏」。
- 虫虫钢琴把这种谱叫「弹唱谱」，考编、师范也说「弹唱 / 儿歌弹唱」，所以有词的旋律＋钢琴统一叫「弹唱」。「伴奏」只装纯伴奏，以及给合唱、器乐的伴奏。
- 「即兴伴奏」是一门考试和一项技能，不是谱的形态。它的练习材料多是「简谱＋和弦」，不是写满的伴奏谱（v1 R2）。所以做成专题（并集口径，§4.4），入口放在钢琴谱和功能谱二级行的末尾。

### 4.3 三记谱法互切怎么体现

| 位置 | 做法 |
|---|---|
| 简谱 / 五线谱列表 | 默认只列**原稿**（主谱种或「也出现在」含该记谱法）。列表末尾一行：「还有 12 首是五线谱 · 用简谱看 ›」。点开后，这些卡接在原稿后面，前面有一条分隔线「以下是五线谱，打开时用简谱看」；本次会话记住展开状态（sessionStorage，非 `musetab-*` 键）。可转池按二级镜像：五线谱 › 歌曲 ↔ 简谱 › 歌曲，合唱 ↔ 合唱，器乐 ↔ 器乐（含同一乐器），视唱 ↔ 视唱，五线谱 › 重奏 → 简谱 › 器乐，简谱 › 儿歌 → 五线谱 › 歌曲。**去重**：可转池＝对面一级镜像二级的成员 − 本一级已有的成员（按 id）；对照谱两边都是原稿，永不进可转池（T15） |
| 合唱谱（v2 复核加） | 「简谱合唱 / 五线合唱」两个二级也按上面的写法给末尾提示「还有 N 首是五线合唱 · 用简谱看 ›」。中老年合唱团、中小学合唱几乎只读简谱，五线谱 SATB 转简谱正好用得上（T9） |
| 原稿不足时 | 当前筛选下原稿 <6 首（不满一屏），可转的那部分**自动展开**，分隔线照旧 |
| 只输入「简谱」「五线谱」（没有曲名） | 等于点了这个一级：只列原稿，不满 6 首自动展开（T8）。否则会把全库五线谱原稿都拉进「简谱」，与点按钮看到的不一样 |
| 搜索「X 简谱 / X 五线谱」 | 默认含可转：原稿在前，可转的在后（v1 R7 的口径保留）。只有六线谱或弹唱谱里有这首的，再往后放一节「吉他弹唱谱里也有简谱旋律」（§5.3） |
| 卡片角标 | 有旋律或人声行、主谱种不是吉他谱 / 尤克里里 / 功能谱 › 和弦格的卡片都带：简谱原稿标「可看五线」，五线谱原稿（含钢琴大谱表）标「可看简谱」；对照谱不标。在钢琴谱里，「可看简谱」就是双手简谱（调研：虫虫「钢琴简谱」、EOP「双手简谱」都是常见需求） |
| 点开 | 从简谱列表（或搜「简谱」）点进五线谱原稿，链接带 `&nota=jp`；反过来带 `&nota=st`。观看页初始化时把 `vwNota` 设成该值（v69.6 已有 `vwSetNota`、`vwNotaApply`，只改观看副本，不动数据）。打开后右上角的「简谱 / 五线 / 对照」三选一照常可切 |
| 落地页 `/pub/:id` | 按钮「看简谱 / 看五线谱 / 对照」，链接同样带 `nota`。SSR 不为 `nota` 另出页面，canonical 仍是 `/pub/:id` |

**推荐的默认：浏览时关（只列原稿）、搜索时开、原稿不满 6 首时自动展开。** 理由：

1. 一级既然叫「简谱」，列表里首先应该是真正写成简谱的谱。用户点「简谱」看到一串五线谱缩图，会以为分类错了。
2. 自动转换的质量不一：钢琴两行转成双手简谱、移调乐器、多声部、临时记号密集的段落，简谱都不如原稿好读。所以放在分隔线以下，让用户知道它是转出来的。
3. 数量如实：一级、二级的计数只算原稿，可转的另计（「还有 N 首」）。
4. 冷启动时简谱原稿少（首日实测：简谱原稿 6 首、可转 12 首，§6.5），这时自动展开，避免空页。
5. 搜索是在找某一首歌，找到就行，哪种原稿都可以，所以默认含可转。

### 5.3 吉他 / 尤克里里弹唱谱里的简谱旋律行，要不要进「简谱」

**推荐：不进（不做「也出现在」），只在搜索里排在后面。**

| 理由 | 说明 |
|---|---|
| 行业惯例 | 曲谱图网写明「吉他以六线谱简谱混排为主」，仍然算吉他谱；虫虫吉他、弹琴吧、有谱么都把带简谱旋律的弹唱谱放在吉他谱下 |
| 主体不同 | 弹唱谱的主体是六线谱和和弦图。简谱行是给弹唱者唱的旋律，常常只写了一部分 |
| 数量 | 吉他弹唱是本站数量最多的一类（拍板 10：首访默认吉他弹唱）。放进简谱后，简谱一级会被弹唱谱占满，民乐、合唱、课堂用户反而找不到纯简谱 |
| 镜像不变式 | 弹唱谱的主谱种本来就不随记谱法变，进不进简谱都不影响不变式；但进了以后，切换旋律行记谱法会让它在简谱和五线谱之间跳，徒增噪音 |

**补偿**：

1. 搜「X 简谱」时，原稿和可转的结果之后，再放一节「吉他弹唱谱里也有简谱旋律」；
2. 落地页「这首歌的其他谱」会列出它；
3. 吉他谱卡片不标「可转」。

**对照：功能谱（CJ / CS）有词时，让它也进简谱 / 五线谱 › 歌曲**（第 6 行）。CJ 的主体就是简谱旋律，和弦标在上方，即调研里的「和弦简谱 / 功能简谱」，拿来唱完全可用。同理，联排五线谱的 ST 也不进五线谱（第 4 行）。

### 5.4 不变式（写进 tv_taxonomy）

1. **互切镜像**（取代 v1 的「互切不变」）：对**有可切换行的谱**（没有这种行的，如纯钢琴 G、14b 的古筝大谱表，切换前后完全相同，不检验），把不在钢琴花括号组里的旋律 / 人声行整体在简谱和五线谱之间切换（等同作者逐行 `setVoxNotation` 后再发布）：
   - 主谱种是简谱 / 五线谱的，切换后落到对面的镜像二级（按 §4.3 镜像表：同名二级，另加 儿歌 → 歌曲、简谱 › 器乐（多声部）↔ 五线谱 › 重奏）；
   - 主谱种是钢琴谱、合唱谱、吉他谱、尤克里里、功能谱的，切换后主谱种不变：合唱谱的二级跟记谱法走（简谱合唱 ↔ 五线合唱），其余二级不变。
   - **已知例外只有三对**（都是跟现有谱名走造成的，与 v1 的三对相同）：第 12 / 13 行（无词无乐器无 intent 的旋律＋钢琴，二级 弹唱 ↔ 伴奏）、第 15c / 17 行（多声部无词无乐器，合唱谱 ↔ 五线谱 › 重奏；拍板 22 随拍板 26 前移到 P0 后，P0 上线即消失）、第 23 / 24 行（没有 intent 的单行无词老谱，歌曲 ↔ 视唱）。清单只许减少、不许增加。
   - 实测：曲库 10 首、示例 16 份、新建 49 种组合、合成样例 39 份全部通过，只有上述三对报例外（§六）。
2. **名实一致**：卡片谱名与主谱种不能互相打架。
   - 谱名含「合唱谱」→ 主谱种是合唱谱；
   - 含「独奏谱」→ 钢琴谱 › 独奏（无乐器或键盘族）、五线谱 › 器乐（其他乐器的大谱表，如「古筝独奏谱」，14b）、吉他谱 / 尤克里里 › 指弹；
   - 含「弹唱谱」→ 吉他谱 / 尤克里里 › 弹唱，或钢琴谱 › 弹唱（CG 改名前）；
   - 含「重奏谱」→ 五线谱 › 重奏；
   - 含「X谱（简谱）」「简谱重奏谱」→ 简谱 › 器乐（单行与 15a / 15c 的多行都是）；
   - 含「功能谱 / 和弦谱」→ 功能谱。

   金表逐例核对。正因为这一条，第 12、15、23 行才跟着现有谱名走。
3. **含有一致**：谱面有简谱旋律行（不在六线谱联排里）的，`主谱种 ∪ 也出现在` 必含「简谱」；有钢琴花括号组且不是独奏的，必含「钢琴谱」。弹唱谱（第 1–4 行）除外，见 §5.3。
4. **一级内唯一**（v2 复核 T14 加）：同一首谱在同一个一级里至多属于一个二级。所以一级按钮的数字＝该一级各二级数字之和（不含可转），`/api/pub/cats` 与列表共用同一个筛选函数，tv_taxonomy 对全部金表样例断言。
5. 坏谱（小节、声部、歌词不是数组）不抛错：`pzOf` 全程包 `safe()`，失败时退回 `{main:简谱 › 歌曲}`，与 docTypeOf 退回 vocal 的口径一致。

- **反推与归属形态**（v2 复核 T17）：一个「用途＋变体＋旋律用」可能对应几个形态（vocal parts=4 mel=J ＝ 简谱 › 合唱 ＝ 合唱谱 › 简谱合唱；pacc mel=J ＝ 常用「钢琴即兴伴奏」＝ 钢琴谱 › 弹唱 ＝ 简谱 › 带伴奏）。`PZ_FORMS` 给每个组合指定一个**归属形态**（合唱 → 合唱谱；对照 → 常用·教学对照；pacc → 常用·钢琴即兴伴奏；kids → 常用·儿歌弹唱；sight（五线谱）→ 常用·视唱练耳），反推、深链 `?new=` 预选、命令面板都落到归属形态上。
- **为什么简谱 / 五线谱下要有「带伴奏」**（T10）：老师新建时的第一反应是「我要一份简谱」，而「简谱＋钢琴伴奏」是课堂和考编最常用的一种。原稿只放在「常用 · 钢琴即兴伴奏」和「钢琴谱 › 弹唱」里，老师得先知道它算钢琴谱。名字与谱库简谱 / 五线谱的「带伴奏」开关同名；建出来主谱种仍是 钢琴谱 › 弹唱，「将归入」写清「也在 简谱 › 歌曲」。

- **P2a 另补**：
  - 「器乐独奏」的西洋管弦乐器也可以选「旋律用 简谱」：萨克斯、小号、长笛的业余和中老年用户多用简谱。改动是 `melLive` 对 staff 族也放开，默认仍是五线谱；
  - 器乐＋钢琴伴奏，只开五线谱旋律 SG（v1 拍板 11 保留）。
- 发布对话框显示「将归入：钢琴谱 › 弹唱（也在：简谱 › 歌曲）」。

## 十三、风险与兼容

| 风险 | 说明 | 对策 |
|---|---|---|
| 同一首谱出现在多个一级 | 用户可能在「简谱」和「钢琴谱」里看到同一张卡；冷启动时「五线谱」13 首里 10 首、「钢琴谱」12 首里 9 首是同一批艺术歌曲，换着点一级像在刷同一屏 | 本来就是设计目标（按「含有」）。卡片小字写主谱种（如「钢琴伴奏歌谱 · 也在简谱」只在非主谱种列表里显示）；「全部」里每首只出现一次；**一级列表主谱种在前、「也出现在」的在后、可转的最后**（T13）；同一一级里至多一个二级（§5.4 第 4 条） |
| 可转结果的质量 | 自动转出的简谱可能不好读（钢琴两手、移调乐器、密集临时记号） | 浏览默认只列原稿，可转的在分隔线下、卡片标「可看简谱」；SSR 分类页不列可转的 |

| 列表缓存 | 官网首页 sessionStorage `pyq-pub-cache`（site/index.html:166）。P1 后旧缓存条目没有 `pz`，一级按钮会被当成 0 首 | 换键 `pyq-pub-cache2`，或条目缺 `pz` 时当没命中（v1 R19；不是 `musetab-*` 键） |

| 两端判法再次分家 | pzOf 写在逐字节同步段里 | tv_taxonomy 金表＋ check-syntax / kindname.test / tv_kindsync 三处核对 |
| 列表性能 | 服务端筛全库要解析每份谱 | shapeCache 已缓存每份谱算好的卡片数据，pz / sub / also / fx 一并放进去；超过约 5000 首前用 P4 快照列 |
