## 0. 总体判断

**一句话：底子已经是出版级，问题集中在「成品交付的最后一公里」「同源互切与互操作的正确性欠账」和「垂类与生意没有闭环」三处。**

**先说做得好的。** 以下几点都经过真机实测，同体量国产工具里少见：
- 刻版底座：SMuFL/Bravura 字形、简谱 GB 惯例、五线谱符干与附点规则都过了几何实测。
- 一键配伴奏：约 2 秒出「五线＋简谱＋歌词／双手伴奏」教学对照谱。
- 智能填词：整段粘贴即逐字对位。
- 商业地基：计费、查单、兑换码核销、审计日志都已就绪。
- CI 门禁：112 个套件，配合语法、版本、重名三道闸门。

这些是护城河，必须保留。

**再说主要矛盾。** 共五类：

1. **交付最后一公里断裂**：
   - 「打印/存 PDF」只出第 1 页（P0-3）。
   - PNG、打印件、分享卡会带出编辑光标（P1-01）。
   - 手机上一键配伴奏的「生成」按钮被抽屉盖住（P1-03）。
   - 教师、考编用户最核心的产出物因此不可用。
2. **安全与内容治理有洞**：
   - 存储型 XSS 可以接管登录账号（P0-1）。
   - 审核通过后改谱不会回到审核（P0-2）。
   - 现有的清洗函数会误删渐强、渐弱楔形（P1-38）。
3. **同源互切和互操作有正确性破口**：
   - 中途转调、x/8 拍号、1=G～B 八度折叠，都会让播放、简谱、五线谱、导出彼此不一致（P1-10～12）。
   - MusicXML 导出或导入时会丢掉圆滑线、反复结构、钢琴左手、TAB 和弦与技法（P1-19～22）。
   - MIDI 入口会静默丢音（P1-39），而这正是 AI 转谱产物的主出口。
4. **垂类与商业没有闭环**：
   - 垂类落地页没有直达场景的深链（P2-41）。
   - ¥39 考编包零交付，却可以付款（P1-29）。
   - 课程不在主攻垂类（P1-30），测评缺乏效度（P2-65）。
   - 会员几乎没有增量价值（P2-53），度量为零（P2-42）。
5. **回归网有结构性盲区**（M-1）：112 套件全绿，却漏掉了 3 个 P0 和多个 P1。原因是没有覆盖 print 媒体，没有覆盖弹窗按钮能否点中，也没有覆盖真实的发声路径。

**方案**：双泳道推进，拍板前置，每段设出口闸门。

- **泳道 1「制谱正确性」**，按 A0 热修周 → A 止血与信任 → B 完善曲谱制作与互操作 → C 垂类深化 → D 课程闭环 的顺序串行推进，符合 2026-08-31 定下的「先完善曲谱制作」。
- **泳道 2「增长、商业止血与度量」**，从第 1 周起，每两周至少发一个 S 级版本。A4 合规和 A7 度量在第 2～5 周上线，E1「30 秒看到成果」在第 8～9 周上线。
- **工期**（按草稿量级折算，见 §6.8）：工程合计约 208 人日，另有内容（校谱、编课）约 37 人日。单人约 50 周；双人并行约 28～32 周（估计）。

### 1.2 方法与证据标准

- **真机试用为主**：
  - 工具：Playwright + Chromium，全程真实点击和键盘输入；编辑器用 `file://` 直接打开。
  - 官网：用 route 桩把页面伪装成 `*.puyouquan.com`，`/api` 反代到本地零依赖 API（各角色使用独立端口，`DEV_OTP=1`）。
  - 视口：至少测桌面 1440×900 和手机 390×844 两种，排版类问题另测 1280、1920、2560。
- **几何佐证**：位置、对齐类问题一律给出 `getBoundingClientRect` 或 SVG 坐标等数值，不只凭截图观感。
- **三道关**：
  1. 角色提交发现，附证据（文件:行号、复现步骤、测量值）。
  2. 独立核验员复测，结论为确证、合理未复现、驳回三者之一，并修正数字和严重度。
  3. 三位终审审稿（处理记录见附B）。
- **严重度**：
  - P0：数据丢失、安全漏洞、白屏，或核心流程走不通。
  - P1：核心场景明显受阻，或专业用户不可接受。
  - P2：体验、效率、质量上明显的提升项。
  - P3：锦上添花。
- **工作量**：S ≤半天；M 1–3 天；L 1–2 周；XL 更大。
- **过程披露**：growth 角色收尾时执行了 `pkill -f "node server.js"`，可能顺带终止了其他角色的本地 API 实例。档案里没有其他角色报告受影响。

## 4. 复盘：问题为什么会出现

1. **回归网有结构性盲区（M-1）**。项目自认的门禁很强，但以下几处没有覆盖：
   - print 媒体：`emulateMedia` 和 `.pdf(` 在 tests 里出现 0 次。
   - 弹窗主按钮能否被点中：tv_mobile 的 T7 只断言弹窗可见。
   - 课程里真实的独立增时线写法：tv_site 只测了连写的 `'1--'`。
   - 单音推弦：tv_bend 没有覆盖。
   - 中文考编曲：tv_eval 共 9 首，没有中文考编曲，也都不带歌词。
   - slur 与 ending 的往返：tv_mxl 没有用例。

   结果是 3 个 P0 和多个 P1 都在全绿状态下上线了。
2. **成品出口各自实现「清理」**：
   - 打印预览和缩图会清光标；分享卡只清掉一半；PNG 和打印完全不清。
   - 没有统一的 `withCleanSnapshot`，所以每加一个出口就漏一次。
3. **语义升级没有贯穿全链路**：
   - v60.29 让播放跟随 keyTo 换调，但五线谱、MusicXML 导出、MusicXML 导入仍按谱首调处理，原本的「一期取舍」由此变成了同源破口。
   - 1=G 起的八度折叠规则散落在 8 处，换调引擎没有做跨折叠点补偿。
4. **安全方案在落地时偏离了设计**：
   - §0.1 规划的是「输出点 esc() + 落库强校验」。
   - 实际只做了入口清洗，而且只挂在两条加载路径上。
   - 清洗本身还会误删合法数据（楔形 `'<'`、`'>'`）。
5. **文案和功能分别发版**：
   - 哼唱成谱下线、九种场景改为三意图卡、「＋和弦」热区撤销、织体从 11 套增加到 21 套之后，官网、帮助和弹窗文案都没有同步。
   - 发版清单里缺少「文案对账」这一步。
6. **商业执行序停在「先上支付」这一步**：
   - 考编内容包是执行序第 4 步，至今未开工，但支付已经可以开启。
   - 这违背了 §0 Sprint 3 自定的「先有可卖的东西再谈支付」。
7. **反应式返修挤占增长和商业版本**：
   - v45.4 之后约 252 个版本里，多数是「产品指示」或「用户报告」类的细节返修。
   - 会员只增加了配额，没有其他增量；度量为零。
   - 这不是失控，而是缺少在制项上限，以及「每两周至少一个商业版本」的约束。
8. **入口撤除后没有承接**：
   - v61.6 撤掉了首页场景带，当时已向产品汇报「垂类页自此无站内内链」。
   - 但之后没有补上替代承接，比如垂类页 CTA 直达场景的深链。

## 6. 升级方案

### 6.0 排序原则、泳道与红线合规

**排序原则**

1. **双泳道并行**：
   - **泳道 1「制谱正确性」**：A0 → A（泳道 1 部分）→ B → C → D，串行推进，满足「先完善曲谱制作」。
   - **泳道 2「增长、商业止血与度量」**：第 1 周起，每两周至少发 1 个 S 级增长或商业版本（E0）。A4 合规、A7 度量在第 2–5 周上线；E1 在第 8–9 周上线（A7 上线后先采 2 周基线）；E2–E7 的 L 级项与 C、D 同期推进。
   - **执行治理**（原 E8，现上升为原则，对应 P2-56）：
     - 在制项上限：同时进行的 Sprint 项不超过 2 个，另加 1 个热修；
     - 「产品指示」「用户报告」类细节返修按周批量合并；
     - 商业执行序的第 4 步（考编内容包）在 C7 落地。
2. **A0 热修周先行**：能在一周内消除的 P0/P1 止血项先做，其中包括清洗函数的修正（P1-38）。这项必须先于 A1 的其他步骤上线。
3. **B 的定位**：「P0 互操作的保真欠账（不重开 P0、不引入新格式）＋ 2026-08-31『先完善曲谱制作』」。
   - **口径**：沿用 PROJECT.md §0（2026-07-24）「暂停新增记谱功能」的裁决。B 段只修正确性，不加与正确性、互操作无关的新记号。
   - **例外**：为纠正错误谱面所必需的最小只增字段，逐项说明如下：
     - `tempoUnit`：修复 x/8 拍号的速度语义（P1-11）；
     - `refOct`：修复八度折叠（P1-12，需拍板）；
     - `voxGroups`：修复错误的花括号（P1-17）；
     - `col.slur`：修复圆滑线语义（P1-20）；
     - harmony kind 映射：G7 被导出成 major，属于互操作错误；
     - 2/2 拍号的导入支持：这是修错，不是新符号。
   - **移出 B**：C/¢ 拍号符号、`mea.multiRest`、歌词延长线、`song.timeSym` 移到 §8 延后；如果合唱分谱确有需求，再并入 C6 另行立项。
4. **C 垂类深化** 对应 CLAUDE.md 的「P1 织体深化 + 智能配谱」。**D 课程闭环** 以 B、C 的成果作为教具。**E 增长与商业** 对应「P2 H5 分享卡」与「P3 垂类文案」。
5. **拍板前置**：§7 按「最晚需要拍板的时间」分组，B、C 段不能卡在待决事项上。
6. **出口闸门**：每段都设出口闸门，用 §9 的「护城河健康度」指标衡量。
7. **先写用例**：每个修复都先补一条会失败的用例（对应 M-1），覆盖 print 媒体、弹窗可点中、真实发声路径、真实语料四类。
8. **护城河检验**：评审任何新功能时，先问一句它强化了四条护城河中的哪一条，即三记谱法同源互切、出版级刻版、织体生成、场景入口。
9. **哼唱转谱建议延后**，并先下架对外宣传文案。这一项会调整 CLAUDE.md 的 P2 执行序，需负责人确认（D-31）。
10. **防止作废提案借道复活**：
    - 不建「工具」频道，也不把导航增加到第 5 项（「五模块」方案已作废）；
    - D3、C3 的文案避免使用「跟练模式」「活曲谱」「智能看谱」等作废提案术语。
