## 1. 总原则

1. **只增不改**：song 字段只新增 `song.intent`（可选，缺省＝按谱面推断）；`musetab-*` 键 0 新增（`musetab-nw-last` 格式不变：新组合复用已有变体键 `tacc` / `inst`）；`instKey` 只增 6 个、旧键名义不变；`PQ_KIND` 的 PZ / 二级 id、`create_stack` meta 格式都不变。
2. **旧外壳与 `?next=0` 零差异**（§十五表后「另外几项」：旧外壳谱友圈和旧新建面板零差异）：本版所有**新界面**（新组合的变体、staff 族的「旋律用」、简谱视唱、6 种新乐器出现在下拉里、示例分组 / 新显示名 / 5 份新示例）只在新外壳新形态出现，统一由新全局 `nwP2A()` 判定（§6.1）。旧外壳、`?next=0`、≤820 窄档、手机仍走 v69.9 的界面与建谱结果。**数据层**（`song.intent` 写入、PQ_KIND 谱名规则、曲库种子）两种外壳都生效——它们不是界面。
3. **老谱零变化**：没有 `intent` 的谱，谱面 SVG、MusicXML、MIDI、`.mtab`、谱名、`pzOf` 与 v69.9 相同；只有下列已拍板 / 有意的派生值变化（§5、§4.4 列全）：拍板 11 合唱带钢琴的谱名、拍板 22 后半「X＋钢琴伴奏谱」、音轨名别名表新增 6 种乐器后按音轨名认乐器（只读）。
4. **两份逐字节**：`@pq-kindname begin … end` 段编辑器内联与 `api/kindname.js` 同一提交里改（语法闸 / `kindname.test` / `tv_kindsync` 三处核对）；官网 `muse-tab/site/pyq.js` 的 `INST / INST_FAM / MEL` 抄本同步（`tv_libpz` 对拍）。

6. **快捷键不变**：不加任何按键处理；新变体用现有 radiogroup（焦点在组内时 ←→ 已生效）。
7. **单文件后声明覆盖前声明**：本规格新名字基线 grep 为 0 处——`nwP2A` `INSTS_ALL` `instsShown` `IGRP2` `GM_IK_PROG` `gmProgFor` `LB_INTENT` `LB_INTENT_OK` `lbIntentFix` `IMP_INTENT` `effStack` `choirDefaults` `melAuto` `melPrev` `melBy` `vars2` `PRESETS_X` `EXAMPLES` `exList` `exName` `exGroups` `name2` `seedId` `presetTigersKids` `presetLiangxiao` `presetChunyou` `presetSightC` `presetSightJp` `pyq-intent`。**不要用** `nm2`、`libId`（基线已有同名局部量）。实现时再 grep 一次。

## 3. `song.intent`

### 3.1 取值与语义
- 取值＝`PQ_KIND.INTENTS` 11 个用途 id：`gtr pacc kids vocal teach sight solo inst chord blank custom`（基线已有常量与 `intentOf`，:5684）。读一律经 `PQ_KIND.intentOf(s)`（第 0 步起导出）：不是字符串或不在表里＝没写。
- 只在谱面推断有歧义时裁定（判法表第 11、19（blank / custom 只认真有词）、20–22 行与儿歌标记），不进 `docType`、不进谱名（拍板 13）。服务端 `pubShapeData` 已读它（`api/server.js:288`，P1），专题「艺考视唱」只收 `intent==='sight'`、「儿歌」读 `intent==='kids'`。
- 新组合的 intent 都是所在用途 id：合唱＋钢琴 → `vocal`；尤克里里指弹 → `solo`；器乐＋钢琴、西洋管弦简谱 → `inst`；简谱视唱 → `sight`。

### 3.2 写入点：只有一处——`realCreate(P, tpNote, ev)`（锚点 `function realCreate(P, tpNote, ev){`，:41200，B 组）

在 `const ns=NWB.build(P.stack, o);` 之后加一行：`if(PQ_KIND.INTENTS.indexOf(P.scene)>=0) ns.intent=P.scene;`（两种外壳都写）。**`NWB.build` 不写 intent**——它也是预览样谱、换谱类重建 / 另建一份和 30 个套件直接调用的结构构造器，保持纯结构。全部建谱路径都汇到这一处：

| 路径 | 走法 | 写入 |
|---|---|---|
| 新建面板「创建」/ 回车 / 双击用途 | `NWP.create()` → `realCreate` | `P.scene` |
| 深链 `?new=` | 面板预选（`showNewWizard({link, scene})`），用户回车才建 → 同上 | 同上 |
| 快速新建 ▾（用途项）/ 按上次（▾、Alt+Shift+N、命令面板 `r1:last`、启动台「按上次」） | `NWP.quickCreate(id)` → `realCreate` | 同上（按上次＝上次的用途） |
| 命令面板「新建…」`r1:new`、页签「＋」、启动台用途卡 `sc:*` | 开面板 → 同第一行 | 同上 |
| 自选记谱法 | `P.scene==='custom'` | `custom` |
| 示例做同款 `exApply(i,'same')` | 克隆示例（含示例自带的 intent，见 §7.2） | 不另写 |
| 只看示例 / 打开文件 / `.mtab` / 云端 / 谱友圈打开 | 原样载入 | 不写、不改 |

### 3.3 「换谱类」改写（A 组）

锚点：`function lbApplyDirect(s, from, to)`（:42225）、`function lbRebuild(s, to)`（:42295）、`function lbCopy(s, to)`（:42309）。三处末尾各调一次新函数 `lbIntentFix(ns, to)`（`direct` 在 `mutate` 里调，一步撤销连 intent 一起退回）；`lbMelSet`（旋律用切换）、`setVoxNotation`、加删音轨**不调**（记谱法切换是镜像不变式，intent 不动）。

规则（新常量放在 `LB_FAM` 旁）：
1. 谱上**没有** intent（`intentOf` 为空）→ 不写（老谱换谱类后行为与 v69.9 相同）。
2. `kids`、`custom` 不改（`kids` 是跨类风格标记，R8；`custom` 本来就能拼出任何组合）。
3. 旧 intent 能产出目标谱行（`LB_INTENT_OK[old]` 含 `to`）→ 不改。
4. 否则改成目标谱行的默认用途 `LB_INTENT[to]`。

```
LB_INTENT_OK = {gtr:['JT','T'], pacc:['JG','SG','CG'], vocal:['J','S','JG','SG'], teach:['SJ','SJG'], sight:['S','J'],
                solo:['ST','T'], inst:['G','J','S','SG'], chord:['C','CJ','CS'], blank:['J','S']}
LB_INTENT    = {J:'vocal', S:'vocal', SJ:'teach', SJG:'teach', JG:'pacc', SG:'pacc', CG:'pacc', JT:'gtr', T:'gtr', ST:'solo', G:'inst', CJ:'chord', CS:'chord', C:'chord'}
```
边界：`copy`（另建一份）改的是新窗口的谱，原谱不动；`rebuild` 的空谱同样按规则；`lbMerge` 本来就把非结构字段（含 intent）从原谱带过来，不需要把 intent 加进 `LB_STRUCT`。

### 3.4 「从已有音乐」（A 组，锚点 `function convert(a, t){`，:40701）

`convert` 末尾按做法写（v1 口径）：`IMP_INTENT={acc:'pacc', SJ:'teach', JT:'gtr', CJ:'chord'}`；`orig`（按原文件）、`J`（转成简谱）不写——保留文件自己读进来的 intent（自家导出的 MusicXML 有，见 §3.6）。Guitar Pro / MIDI 选轨对话框、拖放打开不写。

### 3.5 清洗白名单
见 §2 第 0 步：服务端 `SD_CODE` + `SD_TOP_SCALAR`；编辑器不改表（短码默认分支）。**不做**枚举剥除（口径「拒绝危险，不拒绝陌生」：不认识的值留在数据里、`intentOf` 当没写；服务端 `pubShapeData` 已只认 11 个值）。`kindname.test` 加：`SD_CODE`、`SD_TOP_SCALAR` 含 `intent`；对 11 个合法值 `normalizeSongFields` / `sanitizeUntrusted`（`sanitizeLike`）逐字节不变；`'<b>'` 被剥 / 被服务端拒收；`{intent:{}}` 被 `scoreDataDanger` 拒收。

2. **核对人**（与录入人不同的一位，不看录入结果）按同一版本写 manifest 的 `check` 字串：每小节一段、`|` 分隔；段内各谱表 `/` 分隔（自上而下）；每个音写「科学音高:时值」——`C4` 为中央 C，升降照谱面拼写（`D#5` 不写 `Eb5`），柱式和弦低到高用 `+` 连，时值 `1 2 4 8 16 32`，附点加 `.`，三连音加 `/3`，连音线起点加 `~`，休止写 `r:时值`，倚音不写。例：致爱丽丝弱起＝`E5:16 D#5:16 / r:8`。
3. **构建门 ⑫**：从往返导出的 MusicXML 逐 part 逐小节生成同格式清单与 `check` 逐字比；不一致即失败，报「第 N 小节 第 k 行：期望 … 实际 …」。两人结论不同时回到版本扫描逐音裁定，改错的一方。
4. **目视签字**：构建时加 `--png` 导出每首第一页 PNG 到临时目录（不提交、不进种子），与所据扫描页并排交制谱专家逐小节看力度、踏板、反复、终止线、弱起排法，签字写进 `reviewed`（构建门 ⑭）；发版截图（流水线第 6 步）附这三张给负责人。
5. 上线后发现错：改 manual JSON 重建种子即可，`seedLibrary()` 会把没人改过的官方谱刷新成仓库版本。
自编视唱谱例走 1 / 3 / 4（不需要版本与核对人）。

## 10. 风险与留待

- **简谱合唱行不画方括号**：现有简谱合唱就如此（刻版只在五线谱行画组括线），合唱＋钢琴沿用；加上会改动全部老简谱合唱谱面，留后续单独一版（需对拍老谱）。
- **简谱视唱谱名「简谱歌谱」**：名实观感不佳但不违反不变式；改名牵动老谱与判法表 23 / 24 行，P4 议。
- **派生值变化**：拍板 11 / 22 后半的改名会让少量老谱（带花括号钢琴组的导入合唱谱；X谱（简谱）直接换成钢琴伴奏歌谱的谱）在谱库 / SSR 换名；别名表新增让音轨名是大提琴 / 单簧管等的老导入谱归属从「视唱」改「器乐」。都是方案意图，`tv_taxonomy` 登记，日志写明。
- **合唱＋钢琴的「一键配伴奏」**：智能配谱只认「旋律＋钢琴两行」三行结构，合唱＋钢琴的钢琴两行要手写或另建钢琴伴奏歌谱再合并；面板与建成提示不承诺这条路（§6.6）。换谱类对这种谱只给「另建一份」（非标准组合）。
- **新外壳独享**：新组合、新乐器、示例分组在旧外壳 / `?next=0` / ≤820 窄档 / 手机都看不到（零差异规则）；旧外壳打开新外壳建的新组合谱照常显示与编辑（数据结构全是既有字段）。
- **手工录入的准确性**：会话内拿不到公版扫描，录入与核对都靠制谱专家对所据版本的掌握；双人互核＋机器比对＋并排目视签字三道，上线后可随发版刷新。
- **曲目替换**：《茉莉花》《让我们荡起双桨》《梦幻曲》按版权 / 引擎能力换掉（§7.2、§7.4），验收时负责人可否决换曲，不影响机制。
- **老种子并存**：线上 `official0000` 早年的两首 `seed…` 简谱示例（小星星 / 欢乐颂）与新上架的同名示例并存，需要时由管理员下架老的两首（不在代码里删）。
- **单簧管按实音**：与萨克斯 / 小号同口径；「按声部移调默认值」另议。
- **`st.mel` 自动默认**：§6.3 状态机只在新形态生效，有 N3 全用例与 `tv_newpanel` T3（`?next=0` 随机 500 串）兜底。
