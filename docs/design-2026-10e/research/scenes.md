## 0. 结论摘要

1. **向导第一层按引擎结构分，用户想的却是要做出什么谱。**
   - 现在的一级是「声乐谱 / 器乐谱 / 功能谱」（`index.html:21477-21479`），这是音轨类型的分法。
   - 七类核心用户嘴里说的是成品：伴奏谱、弹唱谱、合唱谱、视唱谱、儿歌伴奏、和弦谱。
   - 「功能谱」「器乐谱」不在任何一类用户的日常用词里。

2. **价值最高的「旋律 → 伴奏」流程，被向导引到了错误的起点。**
   - 四个垂类落地页写的都是「录入旋律 → 智能配谱」。
   - 用户凭直觉会选「器乐谱 · 钢琴 · 伴奏（弹唱）· 织体自动生成」，点 3 次就得到一份**空的、没有旋律的钢琴弹唱谱**（`shots/10-created-P1.png`）。
   - 这份谱上「一键配伴奏」是隐藏的：`renderDock` 只在歌谱、教学对照谱、器乐五线谱上显示它（`:8752-8753`）。
   - 正确做法是先建「声乐谱」，但向导里没有任何提示。

3. **「八场景入口」是 CLAUDE.md 定的护城河之一，现在被削弱成了三张结构卡。**
   - v60.41 按负责人手稿定了「谱类＝音轨组合×显示方式」，数据层这样做是对的。
   - 问题出在把引擎的分类直接摆给了用户。

4. **同一份谱在四个地方叫四个名字。** 实测 7 条路径里有 4 条，从向导选项到建成提示、谱类标签、谱库分类对不上（见 `probe2.json`）：
   - 声乐谱 · 我会五线谱 → 提示「已新建歌谱」→ 标签「器乐五线谱」→ 谱库归「器乐五线」。
   - 二胡 → 提示「二胡谱」→ 标签「简谱歌谱」→ 谱库归「歌谱」。
   - 指弹 · 我会简谱 → 提示「指弹吉他谱」→ 标签「吉他弹唱谱」。

5. **谱类会随显示切换而漂移。**
   - 原因是 `docType` 只看数据（`:21099-21110`）。
   - 实测到的漂移：
     - 歌谱切到五线谱且没填词，变成「器乐五线谱」。
     - 钢琴弹唱谱右手切到简谱，变成「简谱歌谱」。
     - 吉他独奏谱点「仅 TAB」，变成「吉他弹唱谱」。
     - 尤克里里独奏谱被标成「吉他独奏谱」。
     - 二声部合唱（高音谱表 + 低音谱表）没填词时被判成「钢琴独奏谱」，并因此被锁成不能加轨。
   - 所以谱类不是「在向导里一选定就不变」的东西，向导也不该这样承诺。

6. **创建后真正改不了的只有 5 项：**
   - 吉他还是尤克里里：`song.inst` 没有修改界面。
   - 钢琴大谱表和纯伴奏：`pianoAcc` 没有开关，也不能加轨。
   - 功能谱和和弦格：`func`、`chordOnly` 没有开关。
   - 定弦：没有界面。
   - 移调乐器：`transp` 只能靠导入带进来。

   其余项都能在创建后改：记谱法、调、拍号、速度、小节数、歌词段数、变调夹、声部数。

7. **向导里有 3 处承诺和实际能力不符：**
   - 提示写着「定弦创建后在『曲谱信息』与左栏随时改」（`:21491`），实际上任何地方都没有定弦界面。
   - 「织体自动生成」在空谱上不会发生，必须先手标和弦。
   - 「电吉他 Solo」和「指弹」建出来的谱逐字段相同，只差一个 `gtype` 字段，而这个字段从 v52.6 起已不再被读取。

8. **导入散在 4 处，每处支持的格式都不一样。**
   - 启动台「导入」：MusicXML 和 MIDI。
   - 新建向导：MusicXML 和 Guitar Pro。
   - 右栏「创作」：只有 MIDI（MusicXML 按钮 `rt-mxl` 实测是隐藏的）。
   - 顶栏「打开」：只认 `.json`、`.mtab`（`:2358`）。
   - 没有拖放导入。

9. **步数：除了默认的吉他弹唱 1 次点击，其余组合要 2–6 次点击；从启动台进来还要再加 1 次。**
   - 首次访问就显示「继续上次编辑：《小星星（弹唱示例）》」，评审 P2-24 仍然成立。
   - 手机上的「新建」卡是隐藏的（D-07 ②）。

10. **建议：**
    - 第一层按「成品 / 场景」分 8 张卡，兑现「八场景入口」。
    - 「从已有开始」（导入、示范、继续上次）和场景卡放在同一页。
    - 记谱法降为一个本机偏好，加编辑器里的开关。
    - 乐器降为卡内的二级选项。
    - 全部映射到现有 `createSong` 参数，最多新增 1 个可选 song 字段和 1 个本机偏好键。
    - 任何场景从启动台起不超过 2–3 次点击。

## 3. 七个核心人物

前四位属于主攻垂类。下面的默认值是按行业惯例和落地页用语推断的，上线后应该用 A7 的 `create_song` 埋点校准（见附录 C）。

### P1 考编备考 / 在职中小学音乐教师（考编、即兴伴奏）

- **要做的事（JTBD）**：拿到一首教材歌曲的简谱旋律，几分钟内想得到一份能弹、能唱、能交的伴奏谱，用来练习和打印说课讲义。
- **会说的词**：即兴伴奏、弹唱、伴奏谱、配和弦、正三和弦、织体、柱式 / 半分解、双手谱、五线谱简谱对照、说课、移调。
- **不会说的词**：声乐谱、器乐谱、功能谱、音轨。
- **第一步最想决定**：哪首歌，以及「我要配伴奏」。
- **常用默认**：1=C/F/G/D；2/4 或 4/4；8–16 小节；♩=72–96；歌词 1 段；用简谱录入。
- **现状卡点**：凭直觉点 3 次就落到空谱死路；选 2/4 时只有 2 套织体可用。
- **应该映射到**：新建一份歌谱，空状态引导「写旋律 → 一键配伴奏」，生成后在新窗口打开教学对照谱或纯伴奏谱。

### P2 师范生（学前 / 音乐教育）（师范）

- **要做的事**：给一首儿歌做一份能自弹自唱的钢琴谱，并移到孩子唱得动的调。
- **会说的词**：儿歌弹唱、儿歌伴奏、自弹自唱、课堂范谱、教学对照。
- **一个词义冲突**：他们理解的「钢琴弹唱谱」是带旋律和歌词的；产品里的钢琴弹唱谱是不带旋律的纯伴奏（参见 P2-19、P2-21）。
- **常用默认**：**2/4**；1=C/F/G；8–16 小节；♩=96–112；歌词 1–2 段；用简谱。
- **现状卡点**：
  - 2/4 只有「进行曲」「波尔卡」两套织体。
  - 「儿歌伴奏」织体只做了 4/4 版。
  - 预设里没有 2/4 儿歌。

### P3 艺考生（视唱练耳 / 声乐 / 器乐）（艺考）

- **要做的事**：做一条视唱谱例，要规范的五线谱和多个调的版本，打印成册练习。
- **会说的词**：视唱、练耳、谱例、首调 / 固定调、高音 / 低音谱号、几个升降号、小调。
- **第一步最想决定**：谱号、调号、拍号。
- **常用默认**：五线谱高音谱号；2/4、3/4、4/4、6/8；含小调；♩=60–80；不带歌词。
- **现状卡点**：
  - 用「声乐 · 我会五线谱」建出来，标签是「器乐五线谱」。
  - 向导没有小调选项。数据上已支持「关系大调 + `song.mode='minor'`」（`:5586`），只是向导没接上。
  - 3/8 拍能建，但伴奏织体是 0 套。

### P4 教培机构 / 琴行老师（即兴伴奏、B 端）

- **要做的事**：一学期要出 20–30 首版式统一、署名一致的教材谱，常常同一首要简谱、五线谱两版，还要多个调。
- **第一步最想决定**：用哪个模板（哪个系列）。
- **现状卡点**：没有「存为模板」，也没有「从模板新建」；练习卷在 C5，已挂起。
- **现有可用的部分**：署名 `maker` 会从个人资料自动带入；固定版宽已是新建默认。

### P5 吉他弹唱爱好者 / 博主（用户量最大）

- **要做的事**：扒一首歌，做成「六线谱 + 简谱 + 和弦图 + 歌词」的标准弹唱谱。
- **会说的词**：吉他谱、弹唱谱、六线谱 / TAB、扒谱、原调 / 选调、变调夹、C 调 / G 调指法、和弦图、节奏型、指弹谱、尤克里里谱。
- **第一步最想决定**：吉他还是尤克里里（这是唯一改不了的项）、弹唱还是指弹、歌名。
- **常用默认**：4/4；♩=70–100；变调夹 0–3。正好是现在一击建谱的默认值。
- **现状卡点**：
  - 「我会简谱」路径会留下一条空吉他轨。
  - 指弹常用的特殊定弦设不了。
  - 「电吉他 Solo」和「指弹」两个选项产物一样。

### P6 业余合唱团指挥 / 钢琴伴奏

- **要做的事**：排一首 SATB，要声部谱，也要钢琴伴奏。
- **会说的词**：合唱谱、混声四部、SATB、声部、简谱合唱谱、钢伴、总谱 / 声部谱。
- **第一步最想决定**：几个声部，用简谱还是五线谱。
- **现状卡点**：
  - 选五线谱只有第 1 声部生效。
  - 没有男高音谱号。
  - 声部默认叫「旋律1–4」，而不是女高 / 女低 / 男高 / 男低。
  - 合唱和钢琴伴奏放不进同一份谱：一键配伴奏只保留第 1 声部。

### P7 拿着 AI 转谱结果来修谱的人（北极星的右端）

- **要做的事**：手里有一份 MIDI 或 MusicXML，想变成量化干净、调号正确、可弹可唱的谱。
- **第一步最想决定**：文件从哪来，然后做成什么谱。他们不说「新建」，说「打开 / 导入」。
- **现状卡点**：
  - 导入分散在 4 处，格式各不相同。
  - 启动台导入菜单里没有 Guitar Pro。
  - 不能拖放。
  - MIDI 只能直接导成歌谱、钢琴独奏、吉他独奏、尤克里里独奏四种（`:24200`）；要弹唱谱或伴奏谱得导入后再做一步。

### 汇总：第一步想决定的事，现向导能不能直接表达

| 人物 | 第一步想决定 | 创建后能否再改 | 现向导一级能否表达 |
|---|---|---|---|
| P1 | 给这首歌配伴奏 | 能 | 不能，会被引到空伴奏谱 |
| P2 | 做儿歌弹唱 | 能 | 不能 |
| P3 | 视唱谱例，用五线谱 | 能 | 部分能，但标签错 |
| P4 | 用我的模板 | 能 | 不能 |
| P5 | 吉他 / 尤克，弹唱 / 指弹 | **吉他 / 尤克改不了** | 能 |
| P6 | 声部数，简谱 / 五线谱 | 能 | 部分能 |
| P7 | 我有一个文件 | 能 | 部分能 |

## 4. 信息架构建议

### 4.1 六条原则

1. **按成品分，用用户的词。** 卡上的名字就是建成后的谱类标签和谱库分类，一个词贯穿到底。
2. **第一屏只问改不了的事；基础四项保留。** 曲名、调、拍号、速度按场景预填，因为负责人在 v67.3 明确要求创建时能填速度。
3. **三种记谱法互切这条护城河，在编辑器里演示，不在向导里拆开。** 向导只记一个本机偏好。
4. **新建和导入放在同一页。** 启动台本身就是新建页，去掉「点新建再弹一个窗」这一层。
5. **按流程选起点。** 「伴奏谱」场景的起点是一份旋律谱，因为引擎的 `arrangeAccompaniment` 只能从歌谱、教学对照谱、器乐五线谱出发。
6. **数据层零改名。** 只新增可选字段或新的本机键。

### 4.2 第一层按哪个维度分

| 维度 | 结论 | 理由 |
|---|---|---|
| 记谱法 | 不做一级 | 完全可逆，放在一级会暗示「选错要重建」，反而削弱护城河 |
| 乐器 | 不做一级 | 22 项里只有吉他、尤克两项改不了；人声和合唱也不是乐器 |
| 音轨结构（现状） | 退回数据层 | 不是用户的词，还会把伴奏流程引错 |
| 来源（空白 / 导入 / 模板） | 做成同屏的并列侧栏，不做关卡 | 只有 P4、P7 第一步就想决定来源 |
| **成品 / 场景** | **做第一层** | 和 7 类人的第一句话一致，也兑现了护城河 |

### 4.3 八张场景卡

排序按战略优先级。默认选中哪张：有 `?start=` 深链就选对应场景，否则选上次用过的；首访不预选，或者按埋点数据选最多的那张。

| # | 卡名 | 副标题 | 卡内二级（最多 2 项） | 映射到现有参数 | 建成后首屏 |
|---|---|---|---|---|---|
| 1 | **钢琴伴奏谱** | 旋律 → 配和弦 → 双手织体（考编 · 师范 · 即兴伴奏） | 起点：从旋律生成（推荐）/ 我自己写和弦；产出：旋律＋伴奏对照 / 纯伴奏 | 从旋律：`createSong('vocal',{nVox:1,lyr:1})`；自己写：`createSong('pianoacc',{lyr:1})` | 从旋律：空状态卡「① 写 / 导入旋律 → ② 一键配伴奏」；自己写：「① 右手标和弦 → ② 选织体」 |
| 2 | **歌谱 · 视唱谱** | 一条旋律＋歌词（独唱 · 儿歌 · 视唱） | 简谱 / 五线谱（取偏好）；勾选「附简谱行」 | `vocal`；五线谱写 `voxNotations[0]='staff'`；附简谱行写 `voxDual[0]=true`，即教学对照谱 | 光标在旋律轨 |
| 3 | **合唱谱** | 混声四部 · 女声三部 · 童声二部 | 声部 2 / 3 / **4**；简谱 / 五线谱 | `vocal` 加 `nVox`，并写 `voxGroups` 方括号 | 光标在第 1 声部 |
| 4 | **吉他弹唱谱** | 六线谱＋简谱＋和弦图＋歌词 | 吉他 / 尤克里里（注明建后不可改）；直接写六线谱 / 从旋律生成 | 弹唱类型加 `inst` | 同现状 |
| 5 | **指弹 · 独奏谱** | 六线＋五线联排 | 吉他 / 尤克里里 | `solo` | 同现状 |
| 6 | **钢琴谱** | 大谱表双手 | 音色：钢琴 / 电钢琴 / 电子琴 / 手风琴 | `piano` 加 `instKey` 和混音台音色 | 同现状 |
| 7 | **器乐谱** | 小提琴 · 长笛 · 二胡 · 笛子…… | 乐器下拉：现有 22 项去掉吉他、尤克、键盘族，剩 15 项＋其他 | 管弦：`instr` 加预置谱号；民乐：`vocal`（简谱）加 `instKey` | 同现状 |
| 8 | **和弦谱 · 级数谱** | 乐队排练一页纸 | 小节格 / 简谱＋级数 | `func` 加 `ftype` | 同现状 |

**各卡的补充说明：**

- **卡 2 · 歌谱**：需要修标签规则，否则用五线谱又没填词的歌谱会被标成「器乐五线谱」。
- **卡 3 · 合唱谱**：
  - 选五线谱时，要给**每个声部**写谱号：女高、女低用高音谱表，男高也用高音谱表（目前没有男高音谱号，界面上要注明），男低用低音谱表。
  - 声部名可以直接写成女高 / 女低 / 男高 / 男低，`voxVoices` 本来就是字符串数组，不需要改字段。
- **卡 4 · 吉他弹唱谱**：走「从旋律生成」时不要预先建一条空吉他轨，或者生成把位轨后自动删掉那条空的「吉他1」。
- **卡 5 · 指弹 · 独奏谱**：「电吉他 Solo」和「指弹」合并为这一张卡。
- **卡 7 · 器乐谱**：要修标签，否则二胡这类民乐会被标成「简谱歌谱」。
- **预填拍号**：
  - 卡 1 默认 4/4，因为 4/4 有 15 套织体。
  - 选「儿歌」时默认 2/4，并在旁边提示「2/4 目前只有 2 套织体」。
- **教学对照谱不单设卡**，遵守 D1：它以卡 1 的产出选项、卡 2 的「附简谱行」开关出现。
- **卡 1 的名字**：叫「钢琴伴奏谱」更贴近 P1/P2 的用词。如果要让谱类标签也改成这个名字，需要同时改 `TYPE_FULL` 和 `server.js` 里的 `typeLabelOf`，谱库里存量谱的显示会跟着变，需要负责人拍板。

### 4.4 哪些选项可以推迟到创建后

| 现在向导里的选项 | 建后能否改 | 建议 |
|---|---|---|
| 吉他 / 尤克里里 | **不能** | 保留，并注明「建后不可改」 |
| 钢琴伴奏 / 钢琴独奏 | **不能**（`:14000`、`:13877`） | 保留，但换问法：「从旋律生成」还是「自己写和弦」 |
| 级数谱 / 和弦格 | **不能** | 保留在卡 8 内 |
| 电吉他 Solo / 指弹 | 两者无区别 | 删掉这个选项 |
| 具体乐器 | 谱号和音色都能改 | 只留在卡 7 内 |
| 「我会」 | 随时可改 | 改成本机偏好，卡内用分段开关显示当前值 |
| 合唱声部数 | 能改（上限 8） | 保留快捷选择，因为合唱方括号只在创建时写入 |
| 曲名 / 调 / 拍号 / 速度 | 能改 | 保留，按场景预填 |
| 小节数 / 歌词段数 / 变调夹 / 署名 / 弱起 | 能改 | 不放进向导 |
| 定弦 | **不能**，没有界面 | 删掉提示文案（`:21491`）里的「定弦」；或者在编辑器里补一个定弦界面，现成的预设在 `TUNINGS :3092` |
| 小调 | 能改 | 卡 2 加「大调 / 小调」开关，映射为关系大调加 `mode:'minor'` |

### 4.5 模板库按场景组织

每个场景下分三层：
1. 空白：按场景默认值预填。
2. 示范模板：官方模板，显示真实谱面缩图，可以播放。缩图直接复用现有的 `buildThumbCanvas` / `PRESET_THUMB`（`:21319-21336`）。
3. 我的模板：
   - 第一阶段：只做「从我的曲谱另存一份为新谱」，不需要新增存储。
   - 第二阶段：如果要做真正的模板库，需要新增一个键，例如 `musetab-templates`。

16 个预设怎么分到各场景，以及还缺什么内容（缺口只能用公版曲目，见 D-16）：

### 4.6 最少需要几步（从启动台算起）

| 任务 | 现状 | 建议 |
|---|---|---|
| 吉他弹唱，空白 | 2 次 | 2 次，按回车也能直接创建 |
| 钢琴伴奏，从旋律开始 | 没有直达路径：要先点 3 次建歌谱，录旋律，再点 2 次配伴奏 | 点卡、创建共 2 次；录旋律；空状态卡上点 2 次生成 |
| 钢琴伴奏，自己写和弦 | 4 次 | 3 次 |

### 4.7 入口统一

  - `.gp*` → `showGPTrackModal`。
  - `.json` / `.mtab` → `loadSong`。
  - 另外补上拖放。
- **首访**：不显示「继续上次编辑：示例谱」，改成「看一首示范」。
- **手机**：维持 D-07 ②，不提供新建。

## 5. 谱类能力边界（给设计师：做不到的不要画）

### 5.1 互切矩阵

| 谱类 | 向导怎么来 | 其他来路 | 建后能变成 | 不能做 / 被锁定 |
|---|---|---|---|---|
| 吉他弹唱谱 | 默认 | 歌谱加吉他轨；导入 | 删光吉他轨 → 歌谱；可加五线谱联排、简谱联排行；可从旋律生成把位轨 | 不能改成尤克；没有定弦界面；没有一键配伴奏 |
| 尤克里里谱 | 尤克 | 导入 | 同上 | 同上；尤克独奏会被标成「吉他独奏谱」 |
| 吉他独奏谱 | 电吉他 Solo / 指弹 | MIDI、Guitar Pro | 加旋律轨 → 弹唱谱；点「仅 TAB」也会变成弹唱谱 | 不能删最后一轨；没有旋律，无法生成把位轨 |
| 歌谱 | 声乐；民乐乐器 | MIDI 歌谱 | 切五线谱 → 器乐五线谱 / 五线谱歌谱；附简谱行 → 教学对照谱；加吉他轨 → 弹唱谱；一键配伴奏在新窗口生成教学对照谱或纯伴奏谱 | 声部最多 8、歌词最多 5 段、总轨最多 15；合唱和钢伴不能同谱 |
| 教学对照谱 | 不在向导里（D1） | 一键配伴奏的默认产出 | 去掉简谱行 → 器乐五线谱；切回简谱 → 歌谱 | 无 |
| 器乐五线谱 | 管弦、贝斯、其他；声乐 · 我会五线谱 | MusicXML | 同歌谱 | 移调乐器只有实音谱；没有专属音色；没有贝斯四线 TAB |
| 钢琴独奏谱 | 键盘 · 独奏 | MIDI 钢琴 | 右手切简谱会漂成「简谱歌谱」 | 不能加删轨；不能转成伴奏谱 |
| 钢琴弹唱谱 | 键盘 · 伴奏（空谱） | 一键配伴奏「纯伴奏」；预设卡农 | 右手切简谱会漂成「简谱歌谱」 | 没有旋律；不能加人声轨或吉他轨；必须先标和弦；没有一键配伴奏；纯伴奏会丢歌词 |
| 功能谱 | 功能 · 级数 | 预设 | 级数和音名互切 | 去不掉功能谱身份；不能加吉他轨；没有一键配伴奏 |
| 和弦谱 | 功能 · 和弦格 | 预设 | 级数和音名互切 | 不能加删轨；回不到简谱 |

### 5.2 全局边界

- **调**：向导只有 12 个大调。
- **拍号**：分子 2/3/4/5/6/7/9/12，分母 2/4/8。
- **伴奏织体**：
  - 4/4：15 套。
  - 2/4、3/4、6/8：各 2 套。
  - 3/8、6/4、2/2、5/4、7/8、9/8、12/8：**0 套**。
  - 「儿歌伴奏」织体只有 4/4 版。
- **轨数上限**：旋律轨 8、吉他轨 8、总轨 15、歌词 5 段。
- **导入**：
  - 支持 MusicXML（含六线谱声部）、MIDI（4 种目标谱类）、Guitar Pro 3–8。
  - 不支持拖放，也不支持「粘贴简谱文本直接成谱」。

### 5.3 设计稿和文案里不要承诺的事

1. 定弦可以在创建后改。
2. 选了「伴奏」就会自动生成织体。
3. 任何拍号都能配伴奏，或者 2/4 儿歌织体很丰富。
4. 以下合唱相关能力：
   - 合唱加钢琴伴奏一键生成到同一份谱。
   - 选五线谱时合唱各声部自动设好 SATB 谱号。
   - 男高音谱号。
5. 小号、萨克斯、圆号按记谱音（移调）显示。
6. 吉他谱和尤克里里谱互转。
7. 功能谱或和弦谱转成普通简谱。
8. 钢琴伴奏谱和钢琴独奏谱互转。
9. 在钢琴谱、钢琴伴奏谱、和弦谱上加人声轨或吉他轨。
10. 「电吉他 Solo」和「指弹」功能不同。
11. 谱类一旦选定就不会变。
12. 手机上新建或写谱。
13. 哼唱成谱，或者音频直接转谱。AI 转谱只接收 MusicXML、MIDI 文件。
14. 拖入文件导入。
15. 粘贴简谱文本直接成谱。
16. 存为模板。

## 附录 B：图标语义现状（给图标那条线参考）

| 位置 | 现在用的图标 | 问题 |
|---|---|---|
| 向导一级卡（`:21477-21479`） | 声乐用话筒、器乐用吉他、功能用和弦格 | 「器乐谱」卡选了钢琴或二胡后仍是吉他图标 |
| 启动台（`:2711-2716`） | 新建用铅笔、打开用文档、导入用**循环箭头**、我的用谱子 | 「导入」用了表示循环 / 反复的图标 |
| 标签条谱类图标 `docIcon`（`:21111`） | 歌谱用音符、**功能谱用钢琴**、教学对照谱用书、器乐五线谱用小提琴 | 功能谱配了钢琴；只看谱类、不看乐器，所以二胡谱显示音符，长号谱显示小提琴 |
| 左栏轨钮 `INST_ICON`（`:21429`） | 按乐器 | 和标签条的图标对不上 |

建议：
- 一个场景（谱类）对应一个图标，在向导、标签条、谱库三处统一。
- 乐器图标只出现在乐器选择和轨钮上。
- 场景卡的主视觉优先用真实谱面缩图，图标作辅助。

## 附录 C：上线后用数据校准默认值

在服务器上只读执行：

```
sqlite3 /var/lib/puyouquan/pyq.db "SELECT meta, COUNT(*) FROM events WHERE name='create_song' AND created_at > strftime('%s','now','-28 days') GROUP BY meta ORDER BY 2 DESC;"
```

- 这条查询的 `meta` 目前就是向导里的类型：`tanchang`、`vocal`、`func`、`piano`、`pianoacc`、`instr`、`solo`。可以据此决定首访默认选哪张卡、卡片怎么排序。
- 再把 `arrange_done` 和 `create_song` 按 `anon_id` 关联，就能看出「从旋律到伴奏」的完成率。这是卡 1 的核心指标，和评审 §9.2「落地页 → 首次看到成果」用的是同一口径。
