## 0. 十条结论

1. **建出来的谱类和用户选的不一致，可以复现。** 49 个结构组合里错 5 个，9 条状态泄漏路径里出问题 7 条。
   - 「声乐谱·独唱·我会五线谱」建出**器乐五线谱**，标签页显示小提琴，提示却说「已新建歌谱」。
   - 「电吉他 Solo / 指弹」加上「我会 简谱或五线谱」，建出**弹唱谱**，提示却说「吉他独奏谱」。
2. **向导有状态泄漏。** 「我会」的值（`NW.know`，L21515）在换意图卡或换乐器时不重置，隐藏后照样生效。
   - 吉他里选过「我会 简谱」再改钢琴独奏，得到**简谱歌谱**（右手变简谱，标签页显示 ♪）。
   - 再改二胡得到**器乐五线谱**，改小提琴得到**简谱歌谱**。
   - 建成提示也会说错（「旋律轨已按五线谱显示」）。
3. **根源在数据层。** `docType()`（L21099）只看数据形状推断谱类，`song` 不保存用户的建谱意图。导入同样丢谱类：
   - MusicXML 往返后，功能谱和和弦谱变成歌谱，独奏谱变成弹唱谱。
   - Guitar Pro 导入的纯吉他谱算「吉他弹唱谱」。
   - MIDI 选「尤克里里」，得到的标签是「吉他独奏谱」。
4. **入口分散。** 「开始一份谱」共 22 条路径，打开方式有 4 种：新窗口、替换当前窗口、只读观看、跳站。三处导入给的格式各不相同：启动台是 MusicXML + MIDI，向导是 MusicXML + GP，右栏只有 MIDI。
5. **官网和编辑器对不上。**
   - 官网写「八种场景一键建谱」（含教学对照谱），向导只有 3 张意图卡，**教学对照谱在向导里建不出来**。
   - 即兴伴奏、考编、艺考、师范四个垂类页的按钮全部只跳编辑器根地址，不带场景参数。评审团 P2-41 和 E1 都还没落地。
6. **主攻垂类的路径最长。** 默认选中吉他弹唱，点 1 次就能建；钢琴弹唱要 3 次，钢琴独奏 5 次，合唱 4 次，教学对照谱建不出来。
7. **谱类叫法有 6 套口径**：向导、建成提示、右栏、观看页、谱库筛选、MIDI 导入，加上官网各叫各的。
   - 「形态」「我会」「谱式」是自造标签。
   - 「伴奏（弹唱）」在吉他下会自动加人声轨，在钢琴下建的却是没有旋律的纯伴奏。
8. **图标是同一套 SVG，但用得很乱。**
   - 同一个线宽 1.8 在 7 档尺寸下渲染，实际线宽从 0.90 到 2.40px；12–13px 的位置（启动台、标签页、右栏）不到 1px。
   - 视觉重量（墨量）从 9.1% 到 31.5%，差 3.5 倍。
   - 一图多义：吉他图标有 7 种含义，和弦格 6 种，钢琴 5 种。
   - 语义错误：标签页里功能谱显示钢琴，「导入」用循环箭头，「新建」用铅笔，「伴奏」用柱状图。
   - 另有 14 处字符图标混在其中；官网用的是另一套 Lucide 风格图标。
9. **启动台没有主次。** 4 张卡同等权重，132×105 的卡上图标只有 13px，背后还能看到淡出的工具栏和右栏。新用户的「继续上次编辑」指向演示谱《小星星》；「我的」点进去先显示「预设」页签。
10. **手机端说法自相矛盾。**
    - 启动台写「写谱请在电脑」，☰ 抽屉却能进完整向导建谱。
    - 手机向导里「形态」「我会」两个标签和各自的下拉不在同一行。
    - 选「我会 简谱」后内容高 806px，超过 743px 的弹窗高度，要滚动。

## 2. 决策树

### 2.1 结构（L21466–21740）

- **声乐谱**（话筒图标）：形式（独唱 / 合唱 2、3、4 声部）× 我会（简谱 / 五线谱）。
- **器乐谱**（吉他图标，默认选中）：乐器下拉共 22 项。
  - 吉他：形态（伴奏 / 电吉他 Solo / 指弹）× 我会（六线谱 / 简谱→生成六线谱 / 五线谱→生成六线谱）。
  - 尤克里里：形态下拉**只有 1 项**；「我会」的文案仍写「六线谱」，而尤克里里是四线谱。
  - 键盘 4 件：形态（伴奏 / 独奏）。
  - 管弦 6 件 + 贝斯：没有下拉，只有一行提示。
  - 民乐 8 件：没有下拉，提示「简谱记谱」。
  - 其他器乐：谱号（高 / 中 / 低音谱表，三项用同一个图标）。
- **功能谱**（和弦格图标）：谱式（简谱＋级数和弦 / 和弦格）。
- 下方是基础信息（曲名、调、拍号、速度）、导入（MusicXML、Guitar Pro）、「创建，进入编辑」。

### 2.2 组合数

- 结构组合 **49 个**：声乐 8 + 功能 2 + 器乐 38（吉他 9、尤克里里 3、键盘 8、管弦和贝斯 7、民乐 8、其他 3）。
- 再乘调 12 × 拍号 24 × 速度单位。另有 **9 条状态泄漏路径**。

## 6. 数据层约束

### 6.1 谱类推断规则

在 L21099–21109，服务端 `api/server.js` L240 `docTypeOf` 用同一套规则：

```
有 TAB 声部       → (tabStaff 且没有人声轨) ? 吉他独奏 : (尤克里里 ? 尤克里里 : 吉他弹唱)
chordOnly        → 和弦谱
func             → 功能谱
第1声部五线谱 + 第2声部低音谱表 → pianoAcc ? 钢琴弹唱 : (合唱 ? 歌谱 : 钢琴独奏)
第1声部五线谱     → voxDual[0] ? 教学对照 : (合唱 ? 歌谱 : 器乐五线)
其余             → 歌谱
```

谱类完全由数据形状决定，**只看第 1 声部**的记谱法，`song` 不保存用户意图。

### 6.2 现有字段表达不了的组合

| 组合 | 现在实际落到 |
|---|---|
| 没有歌词的五线谱独唱歌谱 | 器乐五线 |
| 吉他独奏 + 参考旋律轨 | 吉他弹唱 |
| 尤克里里独奏 | 吉他独奏，标签写「吉他独奏谱」 |
| 民乐、键盘器乐的乐器身份 | 体现不到谱类上；`instKey` 只驱动左轨图标和默认音色 |
| 钢琴弹唱同时带主旋律 | 钢琴弹唱定义为纯伴奏且锁死加轨；只有智能配谱的教学对照产出能做到 |
| 合唱整组五线谱 / 男高音谱号 | 要逐声部设置；男高音谱号（P2-16 提的 'tenor'）还没做 |
| Solo 与指弹的区别 | 只剩 `gtype` 一个字段，界面不再区分 |

### 6.3 不碰红线就能用的映射

- 新方案的每个场景或模板都能落到 `createSong` 的既有类型：tanchang / solo / vocal / instr / teach / pianoacc / piano / func（含 ftype）。
- 可复用的建谱参数：`nVox`、`nTab`、`lyr`、`clef`、`gtype`、`tuning`、`capo`、`nMea`、`inst`、`tempoUnit`。
- 建好后还能调整的既有字段：`voxNotations`、`voxDual`、`voxGroups`、`instKey`、`mixer`、`layout.fixed`。
- `showNewForm` 证明教学对照谱、小节数、变调夹、定弦、声部数早就能程序化创建，向导只是没开放。
- 16 首预设的 `make()` 可以直接当模板源，覆盖全部 10 类谱类。

### 6.4 如果要「记住用户意图」

可以只增不改地加可选字段，例如 `song.scene`（场景）、`song.tpl`（模板）、`song.inputNota`（用哪种谱输入）。
- 这些字段只用于界面和标签，**不参与谱类推断**，老谱、发布、谱库都感知不到。
- 若要让标签读它们，要改编辑器的 `TYPE_FULL` / `docTypeLabel`，同时改 `api/server.js` 的 `typeLabelOf`（L368），两处必须同步（代码注释 L3107 有要求）。
- 标签页图标改成读 `instKey` 只需改 `docIcon`（L21111），与数据无关。

### 6.5 必须保留的行为

- 新建谱默认固定版宽（D-09，L21665）。
- 合唱写入 `voxGroups` 分组（L21666）。
- 速度单位只在 x/8 拍号且选 ♩. 时才写入（L21648）。
- 新建 / 导入开新窗口，打开已有谱走替换前确认。
- 启动台下编辑区不可操作（A3）。
- 手机端「只读引导」（D-07）需要和 ☰ 抽屉统一。
