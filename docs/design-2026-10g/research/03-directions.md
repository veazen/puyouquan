# 方向 A「谱面即界面」：界面简约化方案（请负责人拍板）

**结论：** 把“靠文字说明”换成“直接在谱面上点、在旁边改”，能把编辑器上常驻的文字从每屏三四百字压到三五十字，说明句压到 0。这个方向以 v68.3 吸顶悬浮条为前提。

- **只留两条工具条：**
  - 吸顶悬浮条是唯一常驻的工具条。
  - 第二种是“对象条”：点谱面上的音、歌词、和弦、记号、小节线、页头或轨名，紧挨着它出现一条图标为主的小工具条。
- **原第 2 行：** 撤掉，内容分进悬浮条和对象条，谱面多出 40px。
- **左右侧栏：** 默认收成 44px 的竖条，展开后只放高级设置。
- **说明文字：** 只在两种时候出现：空谱（12 字以内），和出错（错在哪、怎么修）。

## 一、设计原则（6 条，每条都能自动检查）

1. **说明句只在空谱和出错时出现。**
   - 怎么查：书写、排版、输出三种模式 × 钢琴伴奏歌谱、吉他弹唱、简谱歌谱、钢琴独奏四种谱，共 12 屏，用审计脚本量。
   - 标准：正常状态说明字为 0；空谱时不超过 12 字；出错时只写“错在哪”加修复按钮。
2. **常驻文字每屏不超过 60 字。** 谱面、曲名、纯数字不算。现状 277–398 字，效果图实测 33–53 字。
3. **一个功能只有一个常驻位置。** 命令面板和快捷键不算入口。现状有 14 个功能各有 3 处以上入口，目标是 0 个功能有 2 处以上。
4. **对象在哪，工具就在哪。** 适用于音、歌词、和弦、记号、小节线、页头、轨名 7 类对象。
   - 点中后 120ms 内出现对象条。
   - 离对象不超过一个行间距（60px 以内）。
   - 不压任何墨迹，用几何断言检查：与墨迹的相交面积为 0。
   - 在同一行里移动光标时，对象条位置不动。
5. **字数上限：**
   - 按钮标签不超过 4 字。
   - 菜单项不带副标题。
   - 悬停提示只写“名称 + 快捷键”，不超过 12 字。
   - 提示条不超过 10 字，带“撤销”。
   - 超限的由新加的文案检查脚本 `deploy/check-copy.js` 拦下。
6. **每个情境只有 1 个强调按钮。** 工作区里同时最多一个强调样式；行 1 的“发布”仍是唯一的主色实底按钮。

### 对象条怎么摆，不挡谱面

1. **按排版结果找空隙。** 用 `layoutSystems` / `sysMetrics` 算出每行的范围（含歌词、和弦、记号、连线），找出“本行上方”和“本行下方”的空白带。选中的是本行最上面一行就放上方，最下面一行就放下方，中间的放离得近的那边。
2. **空白带要有 34px 才放。** 不够的话，只在书写模式的屏幕显示里让出 34px。这个间距不写进曲谱数据，打印和导出的结果用断言保证一模一样。
3. **水平位置固定。** 对象条左端对齐本行第一小节；在同一行里移动光标时条不动，只有底下的小三角跟着移。
4. **滚出屏幕时吸边。** 光标所在行滚出屏幕后，对象条贴到悬浮条下沿或状态栏上沿，小三角变成 ↑ 或 ↓，点一下滚回去。
5. **键盘操作。** Esc 收起；F6 在悬浮条、对象条、谱面之间循环切换；方向键在条内移动。
6. **实测位置。** 钢琴伴奏歌谱那屏的空白带是 35px，送别是 36px，都放得下 28px 高的条。

**四级渐进披露（适用于所有控件）**：

| 级别 | 内容 | 什么时候出现 |
|---|---|---|
| 第 0 级 | 图标 | 始终 |
| 第 1 级 | 不超过 4 字的标签 | 默认始终显示，可在偏好里切换「全部 / 只当前项 / 纯图标」 |
| 第 2 级 | 一句话提示 | 悬停、聚焦或长按时出现，同时写进底栏说明位 |

**角标约定（只用 5 种）**：
- ↗：在新窗口打开。
- 🔒：当前不可用。悬停或点一下才说明原因，原因不超过 16 字。
- 作用范围：♪ 当前音、▭ 选区、≡ 本声部全曲。随选区实时变化。
- 文件徽章：PDF、PNG、XML、MIDI、.mtab，徽章本身就是名字。
- 状态点：● 当前、○ 未存、✓ 已存、⚠ 后跟数字表示有几处错。

**例外**：更新日志、特色功能这类用户主动打开阅读的长文档，不受字数上限约束。发版流程中「应用内更新日志加 `<li>`」的步骤照旧。

## 4. 风险、对各类用户的影响、护城河

**风险与对策**
- **新手更难发现功能**（Figma UI3、Gmail 2011、Windows 8 都踩过）：
  - 标签默认「全部」显示，动作按钮不去字，常用功能都不藏到只有悬停才出现。
  - 有说明位、示范，命令面板仍可按旧名和拼音搜到。
  - 埋点：记录"悬停超过 1 秒却没点""打开菜单 3 秒内又关掉""标签档位分布"，两周后和 v68.2 对比；哪一处不达标，就单独恢复那一处的标签。
- **触屏和手写笔没有悬停**：长按 0.5 秒等同悬停；手机抽屉一直显示"图标 + 4 字"。
- **角标要学一次**：只用 5 种，第一次出现时弹一次一句话提示。
- **测试要迁移**：
  - 102 个测试文件里有 873 处读 `textContent`，多数和本方案无关。
  - 45 个套件里有 405 处提到提示条。给提示条加上种类标记（`data-k`），测试改为断言种类而不是原文。
  - 导览在 `tv_flowdef` 里有 42 处引用，需要整段重写。
- **性能**：v68.4 的性能优化还没做之前，悬停预览只重画当前行；超过 100 小节的长谱降级为只高亮不预览；智能页缩略图按谱类缓存。
- **数据红线**：
  - 只改显示文字和界面结构，曲谱数据字段一个不动。
  - 只新增两个本机键：`musetab-labels`（标签档位）、`musetab-hints`（示范已看），读到坏值就回默认。
  - `musetab-tour-shell` 和 `musetab-signdensity` 照常读写，不改名、不删除。
  - 打印、导出、互动谱快照里不能带幽灵键帽、预览或提示层，要加断言。

**对各类用户的影响**
- **熟手**：更快。可以切成纯图标；命令面板不再有位置那一列；键帽和实体键一一对应。
- **新手**：首屏变干净，靠示范、说明位和命令面板兜底。这是本方案风险最大的一类人群。
- **老师投影上课**：默认「全部」档，图标不小于 18px，系统不会自动降档。
- **考编、师范**：要背中文术语。所以记号面板默认改成"混合"：力度等去字，奏法保留中文；原来的"带字"档继续保留。考题常指定织体名，所以织体卡上保留名称，也能搜索。
- **手机**：主界面本来就达标；抽屉从"一行一个带副标题"改成图标网格，说明字归零。

**护城河：没有削弱，三项加强**
- **三种记谱法同源互切（加强）**：三个切换按钮放到新建预览上和悬浮条里，常驻可见。「同一份数据」这句话移进悬停提示，可选做一个"切换时音符原地变形 0.3 秒"的动画来表达同源。
- **出版级刻版（中性偏强）**：谱面一个像素都不动；排版去掉重复控件、选中行就地出工具，更聚焦。
- **织体生成（加强）**：智能页的缩略图直接展示生成后的样子，比「按已标和弦生成双手伴奏」这句话更有说服力。
- **八个场景入口（不变）**：用途名称和垂类徽标保留，只删说明句，各场景的差别交给实时预览来体现（引擎中位耗时约 3 毫秒）。

## 2. 核心机制：「下一步」主按钮

在现有 `lbSteps` / `lbCur` 之上扩展出一个函数 `NEXT.resolve(mode, kind, song, meta)`，返回四样东西：动词、图标、动作、预览方法，以及 ▾ 里的备选项。现在只有 JG/SG/SJG、JT、CG 这几类谱有步骤，要扩到全部 14 种谱型和三种模式。

| 情境 | 步骤点（每步 2 字） | 主按钮怎么变 | ▾ 里的备选 |
|---|---|---|---|
| 钢琴伴奏歌谱 | 旋律 · 伴奏 · 织体 | 配伴奏（有缺口时变「补配 N 小节」）→ 换织体 → 去排版 › | 配和弦、填词、吉他轨 |
| 吉他弹唱 | 旋律 · 吉他 · 节奏 | 生成吉他轨（或「补齐六线谱」）→ 选节奏型 → 去排版 › | 配和弦、填词 |
| 歌谱 / 视唱 | 旋律 · 歌词 | 填词（整段粘贴走智能填词）→ 去排版 › | 配和弦、配伴奏 |
| 和弦谱 / 功能谱 | 旋律 · 和弦（或和弦 · 织体） | 配和弦 → 生成伴奏 → 去排版 › | 配和弦工作台 |
| 指弹 / 钢琴独奏 | — | 去排版 ›（谱为空时置灰） | — |
| 排版模式 | — | 版面检查有问题时显示「修 N 处」，悬停可预览修后效果；没问题时显示「去输出 ›」 | 纸张、疏密 |
| 输出模式 | — | 存 PDF（记住上次用的格式） | 8 格格式画廊 |
| 启动台 | — | 新建 | 拖放、最近 |

几条规则：
- 主按钮固定在同一位置，只换文字；`lbMono` 保证步骤只前进不后退。
- 快捷键 Ctrl+Enter（查过 `index.html`，目前没有占用）。换动作时用 aria-live 播报「下一步：换织体」，首次变化时按钮发光一次。
- 悬浮条收起后变成一个胶囊：谱类图标 + 当前步骤点 + 主按钮。主按钮永远不藏，吸取 Windows 8 Charms 的教训。

## 5. 风险与对各类用户的影响

### 风险

| 风险 | 应对 |
|---|---|
| 主按钮猜的下一步不是用户想做的 | 主按钮只建议、不自动执行；▾ 里永远有其他选项；步骤点可以直接点任意一步 |
| 长谱上预览慢，或预览与结果不一致 | 预览用同一引擎排一份克隆谱；超过 80 小节只预览可见行；性能预算是 32 小节首次预览不超过 120ms、缓存命中不超过 30ms；超出预算就退化为「点了再看 + 撤销」。这依赖 v68.4 的性能版 |
| 智能页撤掉后，其他生成工具不好找 | 每个生成工具至少在一种谱类里当主按钮；▾ 画廊和命令面板都能找到，智能页的旧名作为搜索别名；用 `ui_cmd` 埋点观察使用情况 |
| 文案相关的测试断言大量要改 | 文案清理单独作为一版（v68.8）上线 |
| 预览或占位混进打印、导出、截图 | 加测试断言，打印输出中不得出现淡紫预览和键帽占位 |
| 色弱用户分不清预览 | 淡紫色加「预览」角标，双重标识 |
| 与正在做的 v68.3 冲突 | 等 v68.3 悬浮条合入后再开工；希望 v68.3 先在悬浮条右端留出主按钮的位置 |

### 对各类用户的影响

- **熟手**：Ctrl+Enter 直接执行下一步；命令面板可以直接输入值；要读的字少了。代价是右栏默认收起，要多点一次，可以钉住。
- **新手**：屏上只有一个亮按钮。跟着它走（写旋律 → 配伴奏 → 换织体 → 排版 → 存 PDF）就能出成品。
- **老师（考编、师范、艺考）**：
  - 织体卡保留标准名（柱式、半分解、分解、八分琶音），可以搜索，考题点名的织体能直接找到。
  - 输出模式的主按钮就是「存 PDF」。
  - 右栏收起后谱面宽 264px，投影上课更清楚。
  - 奏法格保留 2 字中文，方便艺考学生学术语。
- **手机**：看谱主界面不变；抽屉改成图标网格和缩略图；没有悬停，改为长按预览；手机上仍不开放编辑。

### 护城河：四项都没有削弱，三项明显加强

- **三记谱法同源互切**：从音轨子行的眼睛图标，升级为悬浮条上常驻的「简谱 | 五线 | 对照」分段钮，悬停就能预览另一种记谱。
- **出版级刻版**：所有缩略图和预览都由刻版引擎实时排出，引擎本身成了说明书；排版模式的「修 N 处」把版面检查变成一步操作。
