# 记号覆盖清单（按谱种）

> **用途**：基石方案 §1.1「记谱完整度」按这份清单验收（`docs/plan-2026-11-foundation.md` §3.7）。每个记号一行，配一个 fixture。三个条件同时满足才打勾（☐ → ☑），在同一提交里改这份清单，并在说明里写版本号：
> - fixture 已入库；
> - 该行的断言通过；
> - 状态已改为「支持」。
>
> **基线**：v70.3（`16de944`）。v70.4 正在做的项（双音震音 trem2、倚音加线）按 v70.3 现状写，目标版本写 v70.4。
>
> **来源**
> - 简谱、六线谱、功能谱：`docs/review-2026-11-jp-tab-audit.md`（JP / TB / FN 编号）；
> - 五线谱：`docs/review-2026-10-staff-audit.md`（T / E / F / N 编号）、`docs/completeness-audit-v42.md`（Tier 0–4、Q / S 编号），以及 PROJECT.md §9.0 的完成记录。
>
> **状态**
> - **支持**：能录入、能刻版、合乎出版惯例，导出导入不丢；
> - **部分**：有这个记号，但有已知缺口，写在说明里；
> - **缺失**：写不出，或者印不出。
>
> 状态为「支持」但说明里带 P3 细节的行，要等细节修掉、断言通过才打勾。
>
> **fixture 命名**：`muse-tab/tests/fixtures/notation/<前缀>_<记号>.json`（谱数据，v:3），导入类用 `.musicxml`。
> - 前缀：`jp` 简谱、`st` 五线谱、`tb` 六线谱、`uk` 尤克里里、`fn` 功能谱 / 纯和弦谱；
> - 一个 fixture 可以服务几行，同名即可；
> - 由新套件 `tv_ncov.js` 逐个加载：新外壳、PAGE_W 870，跑该行的断言（几何、计数或往返），输出本清单的勾选报告；
> - 目录和套件随第一批修复版（v70.7）建立。
>
> **已有现成数据的 fixture**（在复核会话临时目录 `audit704/`，开工时入库）：
> - `fn_audit_func`、`fn_audit_chord`：`func/presets_func.js`；
> - `tb_preset_fix`：`tab/preset_fix.js`；
> - `tb_alltech`：`tab/` 探针里的全技法数据；
> - `tb_ms_gtr`：`tab/ms/ms_gtr.musicxml`；
> - `jp_acc_carry`：`acc.musicxml`。
>
> **范围**
> - 钢琴谱、合唱谱的记号分在五线谱 / 简谱两节，大谱表、踏板、方括号、声部名单列；
> - 吉他谱、尤克里里在六线谱一节；
> - 和弦谱（chordOnly）并入功能谱；
> - 版面指标（竖向、页数、版宽稳定性、碰撞普查）不在本清单，见 §1.1 的刻版行。

目录：一 简谱 · 二 五线谱 · 三 六线谱 / 尤克里里 · 四 功能谱 / 纯和弦谱 · 五 不在本轮 · 六 统计
