# 评委：engraver

【评委立场】我按出版级制谱师的习惯（Dorico / Sibelius / MuseScore / Guitar Pro）来评，只看五件事：工作流是否符合「输入 → 记号 → 排版 → 校对 → 输出 / 分谱」，音轨和声部模型对不对，记号分组和字形规不规范，排版与输出有没有一级入口，专家用起来快不快。三个方向的 DESIGN.md、原型截图、注入真实编辑器的实拍、图标表我都逐张看过了，负责人的两张截图（images/12.png、13.png）也看了。仓库没有改动（git status 为空）。我自己的拼图放在 /tmp/claude-0/-home-user-puyouquan/c5c19e8e-d3d1-572e-9787-3dc37b4d5300/scratchpad/lt/judge-engraver/（left2x-pacc.png、left2x-gtr.png、left1x-all.png、tabs1280.png）。

【评分】满分 10，七个维度加权：工作流 20%、音轨模型 15%、记号与字形 15%、排版输出入口 15%、专家效率 15%、空间与页签 10%、可行性 10%。
- A：8.2
- B：7.7
- C：7.1

【推荐】以方向 A「制谱五步」为骨架，嫁接 B 的音轨树和记号分类，再嫁接 C 的随记谱法换键位的输入行和命令面板细节。

为什么选 A 做骨架：
- 只有 A 把「排版」和「输出」做成真正的工作区。排版模式有分页视图、版心、行标签，有此处换行、锁定此行，还有版面检查（第 1 页 3 行 · 第 2 页 1 行、重叠：无、末行 4 小节拉满、第 12 小节后翻页），这正是出版谱交付前的校对环节。输出模式以打印预览为主视图，可以勾分谱，可以在编辑器内发布。
- B 的排版选项卡没有分页视图，也没有断行工具（catalog.js L142–158）；C 的排版只是一条参数条，输出是个下拉菜单。这两种做法撑不起「专业曲谱平台 · 出版级」这个定位。
- A 的五步用中文动词做成软模式：默认停在书写，按数字键自动回到书写。老师、考编、艺考这些用户不会被模式困住，而且纵向空间收益最大（1280×800 下可见高 586 → 676）。

A 的短板要拿 B 来补：
- 音轨树的「组 → 轨 → 记谱法行（眼睛）→ 歌词段 → 和弦」结构，把「三记谱法同源互切」这条护城河直接画进了左栏。
- 「五线谱联排 · 全部吉他轨」放在组级，作用范围在结构上就是对的。
- 记号分类（调·拍·谱号 / 变音·八度 / 连线·连音 / 奏法 / 力度平铺 / 装饰音 / 钢琴 / 吉他技巧 / 小节线·反复 / 跳转）是三套里最接近 Sibelius/Dorico 的。

A 的专家效率要拿 C 来补：
- A 书写模式的行 2 改成 C 那样随当前轨的记谱法换键位：简谱用减时线字形，五线谱用 C–B 加本调级数，六线谱用品位。
- 命令面板加上「在界面哪里」和旧名别名。

C 的自动选中浮条不要默认开。实拍里它盖住了相邻声部和歌词（choir、pacc 两张截图），校对时这是致命问题。保留现有的右键浮条就够了。

## 记号按钮方案
我选方案 1（SMuFL/Bravura 字形），并加四条硬补丁，不采用方案 2，也不混用两套。分工是：凡是会写到谱面上的符号都用 Bravura 轮廓，凡是动作都用 pqIcon 线性图标。理由有三条。第一，出版级的可信度来自「按钮上的 ♯、𝄐、tr、Ped. 就是谱面上那一个」；方案 2 的 ♮、谱号、tr 一看就是画出来的（judge-engraver/left2x-pacc.png 右栏）。第二，两方案的尺寸一致性打平：最大边 p10–p90 是 ×1.38 对 ×1.39。第三，只往 SMUFL 表追加字形，smg 不改，谱面零回归。四条补丁：① 力度 pp–ff/sfz/fp、Ped./✱、8va、3 连音一律用 Bravura 的 dynamic*、keyboardPedal*、ottavaAlta、tuplet3 真字形，可直接用 B 的 37 字清单。D.C./D.S./Fine/rit./P.M. 用谱面同一字面的轮廓，禁止用 Liberation Serif 占位。② 六线谱品位数字类技巧（击弦、勾弦、滑音、推弦、点弦、泛音）在 1x 下只有约 5px 高（judge-engraver/left1x-all.png），这一族改成「品位数字用 13px 无衬线 + SMuFL 技法记号」混排，「击勾弦」去掉第三个数字。③ 简谱语境的参照数字用直立的 --font-num，不用斜体。附着记号画在 50% 墨的参照符头上，并保持出版比例：跳音最多放大 1.4 倍，不采用 C 的 S 档 1.63 倍。④ 16px 场景（手机、菜单）用 sign16 母版，不缩放 20 母版。格子尺寸：电脑默认 36×36 只看字形，加一条名称提示行；可切换到 52×52 带字（给老师用）；手机固定带字。

## 必须修改
- 分谱要按「演奏者 / 乐器」出，不能按谱行或轨出。现状 A 的输出页（dirA/shots/proto/1440x900-light-13-mode-output.png）、B 的 catalog.js L190、C 的「每个声部各出一份」都会把右手伴奏和左手伴奏拆成两份。正确做法：voxGroups 花括号组（钢琴大谱表）算 1 份；TAB 轨连同它的简谱行和五线谱联排算 1 份；人声旋律连同歌词与和弦算 1 份；合唱可以选「每声部各一份」或「SA / TB 合并」。
- 「此处换页」在现有数据里没有对应字段（现有只有 measures[].brk/pull，index.html L8244–8260、L16174–16183），要在可行性表里明确标为「新增可选 song 字段，例如 measures[].pbrk，只增不改，待拍板」。否则首期只做现有能力：此处换行（brk）、并入上一行（pull）、锁定此行（选区内的 brk/pull 组合）。
- 力度（pp–ff、sfz、fp）、Ped./✱、8va、3 连音换成 Bravura 的 dynamic*、keyboardPedal*、ottavaAlta、tuplet3 真字形（直接用 B 的 37 字清单和 glyphs.py 的 bbox 校验）。D.C./D.S./Fine/rit./P.M. 用谱面同一字面的轮廓。A 现在用 Liberation Serif 占位，按钮和谱面不同形，这违背了选方案 1 的唯一理由。
- 记号面板改用出版通行的分类：「谱号 · 调号 · 拍号」单独成组（A 把谱号放在「变音·八度」，把调号、拍号放在「小节·反复·跳转」）。「和音」（加音程）属于输入动作，移到书写模式行 2 或「更多」，不放在记号面板。「整体升 / 降八度」属于编辑动作，和「八度线 8va」、简谱的「高音点 / 低音点」做到三形三义。
