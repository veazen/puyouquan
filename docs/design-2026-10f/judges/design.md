# 评委：design

【评审报告：左栏音轨与工具、顶栏主菜单、多窗口页签（方向 A / B / C ＋ 记号按钮两方案）】

评审依据：亲眼看了负责人的两张截图（images/12.png、13.png）。逐屏看了三个方向的注入实拍、原型截图和图标表，重点看了这些图：dirA/shots/inject/1280x800-light-pacc-after.png、proto/01、09、11、13、17；dirB/shots/real-01、real-03、real-06、02、09、10、15、m01、m05；dirC/shots/inject/pacc_1280_light_after.png、pacc-drawer、tabs10-win，proto/16、m1、m3；icons/board.png 的 A、B、D 区；三个方向各自的 icons.png。局部放大图在 scratchpad/judge-vis/ 下。仓库零改动，只用 grep 只读核对了 index.html L15378–15444 的现有快捷键。

一、评分维度（每项满分 10，括号内为权重）
信息架构清晰度（15%）· 决策负担/可发现性（15%，主要面向考编、师范、艺考老师）· 一致性与图标精致度（15%，逐像素看）· 纵向空间与谱纸 870 保护（10%）· 多窗口页签（10%）· 可达性：对比度、键盘、命中区（10%）· 深色与移动端（5%）· 护城河与「专业曲谱平台」定位契合（10%）· 落地风险与数据红线（10%）。

二、结论
A 7.7 ＞ C 7.5 ＞ B 7.2。推荐以方向 A 为骨架，嫁接 B 的音轨树语义和语境记号格，以及 C 的带字记号格、谱边输入键位、命令面板和分期节奏。

三、三个方向共同做对的地方（都应保留）
- 对象和工具分开：左栏只放音轨，不再和歌词、小节、段落、帮助混在一列。
- 页签并进深色标题栏，取消 41px 的独立页签带；撤掉写死的橙点、绿点，只用空心圈标「仅存本机」。
- 「发布」是全栏唯一的实底主色按钮，两步完成，不离开编辑器。
- 「智能」在 ≥1201 宽时是死按钮，撤掉。
- 偏好设置补回入口。
- 谱纸 870 不被遮挡；谱型条不再吸顶。
- song 字段新增 0 个，现有 musetab-* 键一个不动。

四、为什么选 A
负责人问的是「主菜单按出版级定位怎么规划」。只有 A 用顶栏结构本身回答了这个问题：设置 › 书写 › 排版 › 播放 › 输出。排版模式是真实分页，带版心和锁行；输出模式有分谱勾选和页缩略图。A 同时拿到最好的纵向空间：1280×800 谱面可见高 676，新建谱也是 676。左栏常驻、谱纸 100%。
B 的功能区对 WPS 用户最熟悉，音轨树也最好，但展开态只多 4.7% 纵向空间，单行模式还有排序 bug，九个选项卡的决策负担也高。
C 最轻，但浮条压住歌词，工具分散在四处，出版流程表达弱，1280 宽下 10 个窗口只露 2 个页签。

五、记号按钮方案
选方案 1（SMuFL），加七个补丁，见 iconPick。

六、必须修改项与嫁接点
见 mustFix 和 graft。按优先级排序，前 4 条不改不建议灰度。

七、建议落地节奏（参照 C 的分期）
- P1：标题栏合并（文件 ▾、页签、发布、账号 ▾、偏好）＋底栏 40。风险最低，纵向收益在这一期就能拿到。
- P2：左栏音轨列表＋带字记号面板＋补 Bravura 字形。
- P3：书写行 2（嫁接作用于指示、文字标签、五线谱音名带级数）。
- P4：五步模式。用 ?shell=flow 灰度两周，按 ui_cmd 埋点决定五段还是收成三段。
每期都跑语法闸、tv_matrix.js 和对应几何套件。旧 DOM 保留隐藏，程序化点击继续有效。

八、待负责人拍板
1) 五步模式先灰度再定段数。
2) 隐藏轨（不刻版、不打印）用的可选字段，和分谱放在下一批一起做。
3) 音轨拖动排序：原子重排所有并列数组，一步撤销，必须有往返断言。
4) 记号面板电脑端默认带字（本评审推荐，与 A 的默认相反）。
5) 选中浮条只保留为可开启项，不默认自动弹出。

## 打分
- **方向 A「工作流模式 · 制谱五步」** 7.7 分：满分 10，九项加权：信息架构 8（权重 15%）· 决策负担/可发现性 6.5（15%）· 一致性与图标精致度 7.5（15%）· 纵向空间与谱纸保护 9（10%）· 多窗口页签 7.5（10%）· 可达性 8（10%）· 深色与移动端 8（5%）· 护城河与定位契合 8.5（10%）· 落地风险 7（10%）。加权合计 7.70
  - 优点：1) 只有它把「出版级」直接做成了顶栏结构：设置 › 书写 › 排版 › 播放 › 输出。排版模式是真实分页视图，带版心虚线、「行 n · 4 小节」锁定标签和版面检查（shots/proto/1280x800-light-11-mode-engrave.png）；输出模式把总谱/分谱勾选、页缩略图、发布卡放在一屏（…-13-mode-output.png），回答了负责人「主菜单按出版级定位怎么规划」。2) 纵向空间最好：1280×800 谱面可见高 586→676（+15%），新建谱 499→676（+35%）。左栏 248 常驻，同时 1280 宽下谱纸 870/870 不被压（现状打开左栏只剩 569，即 65%）。3) 左栏结构对路：上半是对象（音轨，大谱表用花括号组、合唱用方括号组，当前行下挂「简谱｜五线谱｜对照」子行和「歌词 1 2 ＋」），下半是工具（记号，带搜索、最近使用、分组，标题写「作用于『旋律』」）。现状里「旋律」和「小节」两个按钮同时高亮的问题在结构上消失了。4) 页签并入标题栏，额外占高 0；当前页签用 --toolbar 底色和行 2 连成一片，三明治观感消失；溢出列表可搜索，每行标谱类和入库状态，当前页签始终可见（…-17-tabs-8-overflow.png）。5) 记号字形缩放比例从 2.42–10.83 收到 4.1–6.0（相差 1.46 倍）；行 2 的高音点、低音点画成带点的 5，一个字形只表达一个意思。
  - 缺点：1) 默认密度是「只看字形」36×36、不带文字，而且奏法、连线画在 42% 浓度的语境符头上。1x 下实测：连音线读成笑脸「•‿•」，跳音读成「:」，保持音读成「÷」（judge-vis/A_left.png；icons/icons.png 第④节）。TAB 技巧格（H、P、HP、滑、推、揉…）没有文字，老师认不出。2) 行 2 撤掉了现有的文字标签，后插、前插成了「□+」「+□」，难以分辨，比现状还退步。3) 当前页签只有 148 宽：1280 宽下显示「两只老…」，1440 宽下显示「欢乐颂 · …」，曲名只露 3–4 个字。五步分段控件约占 280px，和页签抢行 1 的宽度，1024 宽下没有方案。4) 1280–1439 宽时右栏收成 40px 竖条，谱型条原有的三步起步只剩在右栏「智能」里，新建谱时基本看不到。5) 快捷键 Alt+1–5 和 Linux 版 Chrome、Firefox 切换标签页冲突（方案已自认）。备选组合不能用 Ctrl+Alt+数字，因为 index.html L15438 已把 Ctrl+Alt+0–4/T 用作吉他指法。6) 1280 宽下保存状态只显示一个「○」，单靠形状表达含义。7) 1440 宽下谱纸 866/870，仍被挤掉 4px。8) 五个模式是新概念，需要埋点验证「设置」「播放」两个模式的使用率。
- **方向 C「轻顶栏 + 谱边工具 + 命令面板」** 7.5 分：满分 10，九项加权：信息架构 7（15%）· 决策负担/可发现性 7（15%）· 一致性与图标精致度 8（15%）· 纵向空间与谱纸保护 9（10%）· 多窗口页签 6.5（10%）· 可达性 8（10%）· 深色与移动端 8.5（5%）· 护城河与定位契合 7.5（10%）· 落地风险 7（10%）。加权合计 7.53
  - 优点：1) 外壳最轻：顶栏只有一行 44px，底部是 32px 状态栏，外壳占屏高从 28.4% 降到 16.3%，1280×800 谱面可见高 573→670，1440 下到 770。2) 记号抽屉格子 52×52、4 列、带 11px 文字。小记号放大到 S 档 10.4 px/谱线距，大记号 L 档 6.4，不画语境符头，1x 下最好认（shots/inject/pacc-drawer_1280_light_after.png）。改名「移高八度」画成音符加箭头，「八度线」画成 8va 加括线，「谱号切换」单独一格，八度相关的三个按钮三形三义。3) 输入条随当前轨的记谱法换键位：五线谱轨显示 C₁ D₂ E₃…，右下角标出本调级数，对师范和考编老师很友好；轨标「右手伴奏 + 谱号徽标」清楚说明正在写哪条轨。4) 命令面板每条结果写明「在界面哪里」，并收录旧名别名（预设、打印…、智能、存为文件），Ctrl+K 仍是和弦输入，照顾老用户迁移。5) 分期 P1–P4 最务实：P1 只动顶栏、页签、发布、偏好、状态栏，就能先拿到 +80px 纵向空间。6) 手机端干净，遵守 D-07，触控目标全部 ≥44。
  - 缺点：1) 选中浮条会盖住歌词：metrics.json 实测 ctx 浮条 y=382–420，正好压在《送别》旋律歌词行「古道边 / 芳草碧连」上（shots/inject/pacc_1280_light_after.png），对歌谱用户是硬伤。2) 工具分散在四处：输入条、浮条、抽屉、命令面板。「某个功能在哪」要靠记，老师不会主动按 Ctrl+/。3) 出版流程表达弱：输出只是一个菜单，没有「设置」，排版模式只换了输入条和右栏。4) 1280 宽、10 个窗口时只露出 2 个页签（shots/inject/tabs10-win_1280_light_after.png），只开一个窗口时「＋」漂到 x≈676，离页签很远。5) 窄列里的谱号徽标只有 16px，高音谱号顶到框边，1x 下难辨（judge-vis/C_left.png）。想切换记谱法得先展开 240 面板，三记谱法互切的护城河露得最少。6) 注入实拍里右栏仍是现状的「创作 / 信息」，没有重做。
- **方向 B「选项卡功能区」** 7.2 分：满分 10，九项加权：信息架构 7.5（15%）· 决策负担/可发现性 7（15%）· 一致性与图标精致度 7.5（15%）· 纵向空间与谱纸保护 6（10%）· 多窗口页签 7（10%）· 可达性 7.5（10%）· 深色与移动端 6.5（5%）· 护城河与定位契合 8.5（10%）· 落地风险 6.5（10%）。加权合计 7.18
  - 优点：1) 左栏「音轨与层级」树把三记谱法同源表达得最好。每条轨下列出「简谱 / 五线谱 / 六线谱」子行，眼睛开关就是记谱法切换，已在真实编辑器里验证会重新刻版：voxNotations 从 jianpu 变 staff，谱面路径数 24→41。吉他组写明「五线谱联排 · 全部吉他轨」的作用范围；「由此生成六线谱轨…」做成动作行，不再伪装成开关（shots/02-gtr-mark-tab_1280-light.png）。2) 记号格按当前轨的记谱法画语境：简谱轨画在灰色 5 上，五线谱轨画在符头上，六线谱轨画在品位 3 上。简谱语境下连音线画成「5‿5」，正好避开 A 和 C 的笑脸问题（icons/icons.png）。3) 选项卡行常驻「作用于 ♪ 旋律1 · 简谱」，提示同时写出名称、快捷键、一句说明和作用对象。4) 功能区组名在按钮下方，小按钮保留文字（后插、前插、休止、删除、拆分、合并），用 WPS 的老师一眼就会。5) 新建谱时出现上下文选项卡「新谱起步」，三步引导不占纸面。

## 记号按钮方案
选方案 1（SMuFL / Bravura 字形），但要打补丁后再落地。原则：会写到谱面上的符号一律用 Bravura 轮廓，所有动作一律用 pqIcon 线性图标，两套不混用。选它的理由：(a) 与谱面同源，「出版级刻版」这条护城河直接体现在按钮上；(b) 尺寸一致性两方案打平，墨迹最大边 p10–p90 方案 1 为 1.38 倍、方案 2 为 1.39 倍（icons/SPEC.md §0.3）；(c) 方案 2 的字母类记号（f<、tr〜、Ped）看起来像「画的」，不像「刻的」，在 icons/board.png 的 D 区逐枚对照能看出来。必须同时做的补丁：1) 电脑端默认用带字的 52×52 格子（字形框 20 + 11px 文字，采用 C 抽屉的做法）；只看字形的 36×36 作为可选档，存在本机键 musetab-signdensity。2) 语境元素只在带字档里画，按 B 的规则随当前轨变（简谱画 5、五线谱画带符干的音符、六线谱画品位 3）。连音线和圆滑线不能再画成两颗点状语境符头，现在 1x 下像笑脸「•‿•」。跳音、保持音在密排档里不画语境，免得读成「:」「÷」。3) 缩放比只分两档：L 约 6.0–6.4 px/谱线距，管独立记号；S 约 10.4，管点、楔这类小记号。同族共用缩放比和基线；刻版线不细于 1px；Bravura 发丝线按 SPEC 补描 0.02–0.37px。4) 六线谱品位数字类（击弦、勾弦、滑弦、推弦等）按 SPEC §6.3 混排：品位数字用 13px 无衬线粗体，记号部分用 SMuFL，保证 1x 下数字高度 ≥6.5px。5) 文字类记号（D.C.、Fine、P.M.、let ring、力度字母）换成谱面同一字面的轮廓（Georgia 斜体 600–700，或补 Bravura dynamic* 字形）。现在的 Liberation Serif 只是占位。6) 手机和菜单用 16 母版，禁止用 CSS scale 缩放。7) 四套新增线性图标（A 58 枚、B 80 枚、C 45 枚、SPEC 47 枚）落地前按 SPEC §8 前缀（sg-/ed-/act-/mea-/ui-/tool-/trk-/tab-）合并去重，一个意思只留一个图标。

## 必须修改
- A-1 页签可读性：当前页签按曲名自适应（最多 12 个汉字或 240px），非当前页签最窄 120 且至少露 4 个汉字。实测当前页签 148 宽，1280 宽下只露「两只老…」（proto/1280x800-light-01、17），1440 宽下只露「欢乐颂 · …」（proto/1440x900-light-09）。× 只在当前页签和悬停时出现，命中区 28×28；未入库的空心圈和 × 共用同一个位置（悬停互换）。
- A-2 记号面板电脑端默认改为带字 52×52（字形框 20，文字 11px，4 列，采用 C 抽屉的做法，也是 SPEC §11-2 的推荐）。36×36 只看字形作为可选档。现在默认无字，加上 42% 的语境符头，1x 下连音线像「•‿•」笑脸、跳音像「:」、保持音像「÷」（judge-vis/A_left.png），TAB 技巧格没有文字，老师认不出。
- A-3 修字形歧义：连音线和圆滑线去掉两颗点状语境符头，改用 B 的随轨语境（简谱「5‿5」、五线谱画带符干的音符）；密排档里的跳音、保持音不画语境；「整体升八度 / 整体降八度」从「8↑ 8↓」改为 C 的音符加箭头（移高八度 / 移低八度），和行 2 的高音点、八度线 8va 三形三义；字母类力度和 D.C. 落地前换成谱面同一字面（A 自认的风险 3）。
- A-4 行 2 恢复文字：编辑组「后插 / 前插 / 休止 / 删除」在所有宽度都显示 12px 文字（16 图标 + 字），≥1440 宽再显示组标签。现在是纯图标「□+ / +□」，比现状的文字按钮退步（judge-vis/A_top.png）。
- A-5 快捷键冲突：Alt+1–5 在 Linux 版 Chrome、Firefox 被浏览器用来切标签页；Ctrl+Alt+0–4/T 已被吉他左手指法占用（index.html L15438），也不能用。改为 Alt+Shift+1–5，或用 F6 在模式间循环，在四个浏览器、三个平台实测后再定；Esc 回书写保留。
- A-6 非书写模式下按数字键会自动回书写并落音。这条规则必须让位于输入框：排版模式里的每行小节数、内容大小、♩= 等字段获得焦点时，数字键不能被截走。补 tv_modes 断言：切模式时选区和滚动不变、数字键回书写、输入框不被截键。
