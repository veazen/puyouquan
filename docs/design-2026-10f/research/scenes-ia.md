## 0 结论

1. **主要问题是空间，不在按钮多少。** 1280×800 下，顶部三行 161px（主栏 45、编辑栏 75、页签条 41），加谱型条后谱面从 y=252 开始；底栏 49px。外壳合计 **301px，占屏高 37.6%**，谱面只剩 **499px** 可见。原因之一是编辑栏在 ≤1600 宽时折成两行（75px），1024 宽折成三行（109px）。横向上，左轨 72、面板 272、右栏 292，合计 636px。870 宽的谱纸在 ≤1440 宽放不下，左栏面板只能改成浮层，**盖住谱面左侧 243px 和谱型条 241px**（实测 1280 与 1440）。
2. **左栏的音轨逻辑把两类东西混在一列。** 左轨里，音轨（数据对象：旋律、右手伴奏…）和工具页（歌词、小节、段落、帮助）用同一种 56×46 方块、同一种选中色，会同时出现两个高亮（`shots/probe-mixer-1280.png`：「旋律」「歌词」都是实底）。轨名标签只有 10px。一条音轨的设置散在三处：
   - 左栏「当前音轨」：改名、删除、显示、MIDI、键盘、变调夹；
   - 底栏「音轨 ▴」混音台：独奏、静音、音量、音色，展开后高 173px，压住谱面；
   - 右栏「指板 / 键盘」。

   钢琴独奏谱、钢琴弹唱谱、和弦谱里「＋音轨」照样显示，点了只弹一句「暂不支持加轨」（L14909）。
3. **记号工具没有分组。** 记号面板是一张 4 列网格，按谱类有 27–38 个同等权重的 50×46 按钮，标签 10px。
   - 字形的视觉大小从 4×15 到 30×19 不等，还有 3 个用文字代替字形（8va、Ⅳ、ᵛ）。
   - 三种不同操作名字几乎一样：「8ᵛᵃ」（顶栏，单音加高音点）、「升八度」（左栏，选区整体移八度）、「八度线 8va」（左栏，ottava 括线）。
   - 同一功能多处入口：一键配伴奏 3 处、指板 / 键盘 3 处、导入 MIDI 3 处、和弦 3 处。
4. **顶栏是平铺，没有按制谱流程编排。** 第一行 14 个按钮。
   - 强调色给错了：实底主色给了「个人中心」，加粗给了「预设」「谱库」两个逛谱入口，「保存」「打印」反而是普通按钮。
   - 「智能」排在最前，但在 ≥1201 宽点了**没有任何反应**。实测只给 body 加了 `rsheet` 类，右栏不变，遮罩高 0。
   - 「发布到谱库」不在编辑器里：要依次点保存 → 个人中心 → 创作者中心 → 发布到谱友圈 → 提交审核，共 5 步，还要离开编辑器（L30695、L29161）。
5. **多开窗口页签的位置和状态表达都有问题。**
   - 页签条放在两行工具栏**下面**。正常的层级是先选文档、再用工具，这里反了；配色也成了深、浅、深三明治。
   - 页签条固定占 41px，而通常只开 1–3 个窗口。
   - 11 个窗口时总宽 1722px，超出 1280 的部分看不见，滚动条被隐藏，也没有溢出菜单（`shots/1280x800-manytabs.png`）。
   - 状态点：橙色表示「未存入我的曲谱」，绿色表示「已存入」。但大家习惯把橙点读成「有改动没保存」；这两个颜色还写死在 L1637–1638，不在色板里。
   - 只剩一个窗口时没有 ×。
6. **有 4 个设置从来没有可点的入口。** GP / 简谱大师键位（D-13 拍板的可选档）、落音自动前进开关、播放演奏感、触屏浮条重新开启。它们只能在「提示」宿主 `#hint-body` 里打开，而这个宿主 v56.6 就删了（L3337 注释；L9735、L18450 都是空宿主守卫）。v63.7 的更新日志却写着「在右栏『创作』页的提示里开启」，用户根本找不到。回归测试是直接写 `localStorage` 的（tv_b1b.js:111）。
7. **频率统计**：78 项功能里，**高频 13 项**、**中频 33 项**、**低频 32 项**。
   - 高频项几乎全是录入循环：光标、音高、时值、附点、休止、八度、增时线、升降、插删、撤销、播放、切轨、逐字歌词。它们现在都有键盘路径，也都在顶栏第二行，位置大体对。
   - IA 的问题集中在中低频项。记号、结构、音轨、智能、输出、文件这几组用鼠标时，一次会话要点 96–318 次；按建议放置，估算可降 **21%–39%**（`data/burden.json`）。
8. **建议的信息架构**（线框见 `shots/ia-wireframe-1280.png`）：
   - **顶部两行，共 88px。**行 1：品牌、「文件 ▾」、窗口页签、工作区「写谱｜排版｜输出」、保存状态、「发布」、账号。行 2：当前工作区的工具条，单行不折行。
   - **左栏 240px。**上半是**音轨列表**（每行带记谱法、独奏 / 静音、⋯），下半是**分组的记号面板**。
   - **右栏「属性｜智能」。**内容跟着选中对象变；1280–1535 宽默认收成 40px 竖条，点开浮出，不挤谱面。
   - **底栏 40px。**播放和状态（光标位置、时值检查）合成一行。
   - **低频功能和偏好设置**进命令面板和账号菜单。
   - **常驻外壳 128px（16%）**，1280×800 下谱面可见 672px，**比现在多 35%**。
9. **能力边界**：78 项里，已有且保留 24 项，**只改入口 50 项**，需新增 3 项（音轨排序、音轨隐藏、分谱），修复 1 项（偏好入口）。
   - 工作区三分没有新功能：「排版」是把现有排版浮层升格；「输出」是把现有预览浮层、打印 / 导出弹窗和发布菜单合并升格。
   - song 字段新增 0 个。只有「音轨隐藏」需要一个可选字段，要拍板，建议和分谱一起做。
   - 现有快捷键全部保留，见 §5.5。

## 2 六个核心人物与一次完整制谱会话

点击口径：从编辑态起算，视口 1280×800（左栏面板默认被 D7 收起）。键盘快捷键记 0 次，打字不计，弹窗里的「确定」算 1 次。

## 3 功能使用频率与位置（78 项）

### 3.1 方法

- **每格的含义**：该人物一次会话里大约用几次。这是专家估算，原因有两个：
  - 编辑器没有逐控件的使用埋点，现有事件只有 `create_song`、`export_*`、`transpose` 等 19 个（`grep pyqEvent`）；
  - 本机有习惯统计 `musetab-habits`，但不上报。
- **分层规则**：
  - **高**：合计 ≥50，且至少 5 类人物用到；
  - **中**：合计 ≥6 且至少 3 类人物用到，或合计 ≥15（某一垂类的核心动作）；
  - **低**：其余。
- **★**：护城河或商业关键（三记谱法、刻版输出、织体 / 配谱、发布）。放置时比频率层级上调一档。例如「打印 / 存 PDF」频率低，但每份谱都要走这一步，所以放一级入口。
- **完整数据**：`data/freq.json`（含每格数值与规则）、`data/freq-table.md`。

## 4 信息架构建议

### 4.1 原则

1. **按频率决定位置。**
   - 高频：键盘 + 行 2 常驻工具条 + 右键浮条，最多点 1 次。
   - 中频：左栏分组面板或右栏属性，最多 2 次。
   - 低频：菜单、命令面板或折叠组，最多 3 次，但都能在命令面板里搜到。
   - ★ 项比频率层级上调一档。
2. **对象和工具分开。**
   - 音轨、歌词行、小节是对象，放在列表和属性里。
   - 记号、时值是工具，放在工具条和面板里。
   - 同一列不放两类东西，两个高亮同时出现的问题也就没了。
3. **按「写 → 排 → 出」组织。**出版级制谱的流程就是录入、刻版排版、输出发布。Dorico 分写谱 / 刻版 / 打印，MuseScore 4 分首页 / 乐谱 / 发布，都是这个思路。顶栏用三个工作区表达这条主线，「专业曲谱平台」的定位就落在了界面结构上。
4. **外壳尺寸受谱纸约束。**870 固定版宽（v67.7）不能被外壳挤压或遮挡：任何档位外壳都不能盖住谱面，工具条也永不折行。
5. **演进，不换肤。**沿用现有的 `--chrome` 深色顶栏、`--panel` 白面板、`--accent` 主色和 pqIcon 图标，只改排列、层级和尺寸。

### 4.3 顶栏：主菜单怎么分组

**三种组织方式的比较：**

| A 桌面菜单栏 | 文件 / 编辑 / 插入 / 记号 / 排版 / 播放 / 输出 / 智能 / 帮助，共 9 个文字下拉 | 每个功能都有固定位置 | 要多占一行；教师和学生不习惯在菜单栏里找；高频项还得另做工具条 | 不推荐作主结构；**这 9 组改作命令面板和右键菜单的分类** |

### 4.5 音轨在信息架构里的位置

```
文档（窗口页签）
 ├ 整谱属性：标题词曲 · 调 · 拍 · 速度 · 版式 layout · 和弦显示（级数/音名、和弦图位置）
 ├ 谱类（由音轨组合派生，PQ_KIND；只读，可「换谱类」）
 └ 音轨 ×N（tabVoices / voxVoices；乐器 instKey · mixer · tabCapos）
     ├ 视图：记谱法（voxNotations · voxDual · tabStaff · tabJpVoices）
     ├ 歌词行 ×段（voxCol.lyrics）
     └ 内容：小节 → 列 → 音符 + 记号（measures[].voxes[vi] / tabs[vi]）
```

- **主入口是左栏音轨列表。**这延续了 v60.43「音轨是最上级导航」的拍板：音轨仍是左栏第一层，只是从 56×46 的竖排方块改成横排的列表行。
- **辅助入口是谱面行标。**每行谱开头已经画着「旋律」这类行名（`shots/1280x800-pacc.png`，x≈119），把它做成可点的：
  - 点一下选中该轨，光标放到行首；
  - 悬停时显示轨名和记谱法；
  - 合唱和多轨用户在谱面上找声部更直接；
  - 这是新增交互，不改数据。
- **混音放进轨行。**S / M 放在行内，音量音色放在 ⋯ 里。底栏「混音 ▴」保留，作为纯播放用的整体视图，两边状态同步。
- **不建议在谱纸左边常驻一列轨道**（GP / DAW 的做法）。谱纸宽度是硬约束（870），而这里的用户平均只有 1–4 轨，不值得为此占宽度。

### 4.6 右栏：属性与创作辅助

- **两个页签：属性 ｜ 智能。**「信息」页的内容并入「属性（整谱）」；帮助、特色功能、更新日志移到账号 ▾。
- **属性页跟着选中对象变**：
  - 选中音符：音高、时值、附点、记号列表（可逐个点 × 删除）、和弦、歌词、指法。
  - 选中小节：拍号、转调、反复、段落标记、宽度。
  - 选中音轨（点轨行或行标）：名称、乐器音色、记谱法、谱号、变调夹、调弦。
  - 什么都没选（点谱面空白处或标题）：整谱属性。把现有「曲谱信息」弹窗的字段内联显示，再加上级数 / 音名切换、和弦图位置、调外音拼写方向。
- **智能页**：
  - 顶部是「下一步」卡，即谱型条起步条的三步：写旋律 → 配和弦与伴奏 → 选织体；
  - 下面依次是一键配伴奏、配和弦工作台、伴奏织体、智能填词、节奏型库、从旋律生成六线谱、导入 MIDI 到本轨。
- **两张状态卡移到底栏。**「当前编辑位置」「编辑模式 · 时值提示」挪到底栏状态行；「自由编辑 / 修复建议」开关放进时值徽标的弹出层。
- **停靠规则**：
  - ≥1536 宽：停靠，宽 288。
  - 1280–1535 宽：默认收成 40px 竖条。点开后浮出 292（带 `box-shadow`，不改谱面排版），按 Esc 或点外部收起。

### 4.7 底栏：播放 + 状态（40px）

### 4.8 右键与命令面板

### 4.9 多开窗口页签

- **位置**：并入行 1（深色栏），省掉现在独占的 41px。
  - 层级随之理顺：先选窗口（文档），再用工具。

- **规格**：
  - 页签高 32，宽 112–200，放不下时自动收缩。
  - 谱类微缩图标 16（现有 docIcon）；曲名 13px，过长显示省略号。

  - **只剩一个窗口时也显示页签**，因为保存状态要靠它表达。这个页签上也显示 ×，关掉后回到启动台（这一点要拍板）。

  - 未入库：空心圆 ○（`--muted`），悬停显示「只在本机，未存入我的曲谱」；
  - 已入库：不加标记，悬停显示「已存入我的曲谱（最近更新 …）」；
  - 去掉写死的橙色 #e8a13a 和绿色 #2eaf64，避免被读成「有改动没保存」。
- **溢出**：页签都缩到最小宽度后仍放不下时，出现「⋯ N」按钮，下拉列出全部窗口（图标、曲名、状态、关闭），可按曲名搜索。滚动条被隐藏、看不到溢出的问题一并解决。
- **其他交互**：
  - 中键关闭（新增）；
  - 拖动排序（可选，低优先级）；
  - 页签右键菜单：关闭 / 关闭其他 / 存入我的曲谱 / 复制为新窗口；
  - 窗口切换快捷键可选 `Alt+[ / Alt+]`（按 `e.code` 判断），需实测。
- **数据红线**：`musetab-docs-v1` 的结构不动，页签顺序就是现有的 `docs[]` 顺序。

### 4.10 谱型条的去留（需拍板）

- **现状**：谱型条高 58px，加上上下间距约占 84px。内容是：谱类 ▾、旋律用简谱 / 五线谱、起步条三步、收起按钮。
- **推荐方案**：把内容拆到三个固定位置，谱型条本身只留作新谱引导。
  - 谱类 ▾ → 移到音轨面板标题。
  - 旋律用简谱 / 五线谱 → 移到旋律轨行的记谱法 chip。
  - 起步条三步 → 移到右栏「智能」页顶部的「下一步」卡。
  - 谱型条本身只在新建后出现，高度压到 36px；写满 8 小节或完成第 ② 步后自动收起；Alt+B 照旧能调出（L15430）。
- **理由**：v67.5 刚上线的引导作用保住了，常驻占用的 84px 也收回来了。
- **备选**：维持现状。代价是 1280×800 下外壳为 128 + 84 = 212px（仍比现在的 301 少）。
